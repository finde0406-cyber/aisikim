# AI시킴 블로그/콘텐츠 집중팩

제목, 도입부, 구조, CTA, 최종 검수까지 콘텐츠를 끝까지 다듬는 흐름형 작업지시서

---

## 이 팩이 특히 잘 맞는 사람
- 글 초안은 나오지만 도입부와 흐름이 늘 약한 사람
- 콘텐츠를 게시 직전까지 더 강하게 다듬고 싶은 사람
- 정보형 글과 판매형 문구를 자연스럽게 함께 쓰고 싶은 사람

## 먼저 이렇게 사용하세요
1. 초안부터 막히면 `블로그 글의 첫 구조를 잡고 싶을 때`부터 시작합니다.
2. 읽는 사람이 중간에 이탈하면 `블로그 도입부를 더 강하게 쓰고 싶을 때`와 `소제목 구조를 더 읽기 좋게 정리하고 싶을 때`를 이어서 사용합니다.
3. 게시 직전에는 `완성된 글을 전체 검수하고 수정하고 싶을 때`로 마무리합니다.

## 이 팩은 왜 따로 존재하나요?
이 패키지는 특정 분야에서 바로 써먹을 수 있는 작업지시서만 빠르게 꺼내 쓰고 싶은 사용자를 위해 분리한 집중팩입니다.
즉, 안 쓸 분야까지 같이 사는 느낌보다 `내가 지금 필요한 문제를 바로 해결하는 느낌`이 먼저 오도록 구성합니다.

## 핵심 작업지시서
## 블로그 글의 첫 구조를 잡고 싶을 때

### 한 줄 설명
글 주제는 정했지만 제목, 구조, 검색 의도, CTA까지 한 번에 잡히지 않을 때 가장 먼저 꺼내 쓰는 초안 설계형 작업지시서입니다.

### 이런 상황에서 특히 잘 맞습니다
- 블로그를 자주 쓰지 않는 사람
- AI가 너무 뻔한 블로그 구조만 줄 때
- 초안을 빨리 만든 뒤 직접 다듬고 싶은 사람

### 이 작업지시서로 기대할 수 있는 결과
- 제목 후보 5개
- 가장 적합한 제목 1개와 이유
- 검색 의도에 맞는 소제목 구조
- 도입부 초안
- 각 소제목의 역할과 핵심 흐름
- 반드시 넣어야 할 사례/근거 포인트
- 마무리 CTA 방향

### 언제 쓰는지
- 블로그 글의 첫 질문 단계
- 주제는 정했는데 구조가 안 잡히는 시점

### 바로 복사할 본문
```text
지금 저는 [주제]에 대한 블로그 글을 작성하려고 합니다.
이번 글의 목적은 [정보 제공 / 제품 소개 / 경험 공유 / 문제 해결]입니다.
이 글을 읽을 대상은 [대상 독자]이며, 이 독자는 [현재 수준 / 관심사 / 자주 겪는 문제]를 가지고 있습니다.
이 글로 노리고 싶은 검색 의도 또는 독자의 질문은 [검색 유입 키워드 또는 독자가 찾는 표현]입니다.

이 글을 읽은 뒤 독자가 얻어가야 하는 핵심은 [한 줄 핵심 메시지]입니다.
이 글을 읽은 뒤 독자가 하길 원하는 다음 행동은 [댓글 / 저장 / 문의 / 신청 / 구매 / 다른 글 읽기]입니다.

먼저 이 글에서 반드시 다뤄야 할 핵심 포인트가 무엇인지 짚어주세요.
그 다음 아래 순서로 결과를 작성해 주세요.

1. 제목 후보 5개
2. 그중 가장 적합한 제목 1개와 선택 이유
3. 소제목 구조
4. 도입부 초안
5. 각 소제목별 핵심 문장과 그 소제목의 역할
6. 반드시 넣어야 할 실제 사례, 수치, 경험 포인트
7. 마무리 문장과 CTA 방향

답변은 너무 추상적이지 않게, 실제 블로그 초안으로 바로 옮겨 쓸 수 있을 정도로 구체적으로 작성해 주세요.
읽는 사람이 중간에 이탈하지 않도록 흐름이 자연스럽게 이어지게 해주세요.
가능하면 흔한 표현보다는 실제 상황과 연결되는 문장으로 써주세요.
검색 유입만 노린 어색한 키워드 나열은 피하고, 독자가 얻는 결과가 제목과 구조에서 분명히 보이게 해주세요.
각 소제목은 왜 필요한지 역할이 느껴지게 정리해 주세요.
```

### 바꿔야 할 부분
- `[주제]`: 예) AI로 블로그 글쓰기, 직장인 아침 루틴
- `[정보 제공 / 제품 소개 / 경험 공유 / 문제 해결]`: 글 목적
- `[대상 독자]`: 예) AI 초보자, 직장인, 1인 사업자
- `[현재 수준 / 관심사 / 자주 겪는 문제]`: 독자 설명
- `[검색 유입 키워드 또는 독자가 찾는 표현]`: 예) AI 블로그 글 쓰는 법, 직장인 아침 루틴 만들기
- `[한 줄 핵심 메시지]`: 독자가 얻어가야 할 핵심
- `[댓글 / 저장 / 문의 / 신청 / 구매 / 다른 글 읽기]`: 읽은 뒤 원하는 행동

### 후속 질문
- 위 구조를 유지한 채 도입부와 마무리 CTA만 더 강하게 다시 써줘.
- 소제목은 유지하고, 각 소제목 아래에 들어갈 실제 사례와 숫자 예시를 더 추가해줘.

### 수정 요청
- 너무 흔한 블로그 표현은 줄이고 실제 경험이 느껴지는 표현으로 바꿔줘.
- 모바일에서 읽기 쉽게 문단 길이를 더 짧게 나눠주고, 문단마다 한 가지 메시지만 남겨줘.

### 검수 요청
- 이 글 구조에서 빠진 핵심 요소가 있는지 점검해줘.
- 대상 독자가 읽었을 때 공감이 약하거나 중간에 이탈할 만한 부분이 있다면 짚어줘.

### 자주 하는 실수
- 주제만 넣고 독자 설명을 비워둔다
- 목적 없이 “그냥 글 써줘” 식으로 요청한다
- 검색 의도나 읽은 뒤 원하는 행동을 비워둔다
- 첫 결과만 보고 끝낸다

### 이 순서에서 쓰면 좋습니다
1. 이 작업지시서로 초안을 만든다
2. 제목 후보 확장형 또는 도입부 강화형으로 입구를 더 세게 만든다
3. 마지막에 검수형 작업지시서로 마무리한다

### 사용 팁
블로그는 초안이 아니라 `구조를 잡는 첫 질문`에서 품질이 많이 갈립니다.  
제목, 검색 의도, CTA까지 같이 잡아두면 무료 결과보다 훨씬 덜 헤매고, 이후 후속 질문에서 완성도를 빠르게 끌어올릴 수 있습니다.

## 글 제목 후보를 여러 방향으로 뽑고 싶을 때

### 한 줄 설명
하나의 주제를 서로 다른 클릭 이유와 검색 의도로 풀어 보고, 가장 잘 먹히는 제목 방향을 고르는 제목 확장형 작업지시서입니다.

### 이런 상황에서 특히 잘 맞습니다
- 제목이 너무 평범하게 느껴질 때
- 같은 주제로 정보형, 클릭형, 실전형 제목을 비교하고 싶을 때
- 글 구조는 있는데 제목만 약할 때

### 이 작업지시서로 기대할 수 있는 결과
- 성격이 다른 제목 후보 7개
- 각 제목의 클릭 이유와 방향 차이
- 가장 추천하는 제목 1개와 이유
- 검색형/클릭형 균형 판단
- 이후 소제목 확장 포인트

### 언제 쓰는지
- 초안 작성 전 제목 브레인스토밍 단계
- 글 구조는 있는데 제목을 못 고르겠는 시점

### 바로 복사할 본문
```text
지금 저는 [주제]에 대한 글을 쓰려고 합니다.
이 글의 목적은 [정보 제공 / 제품 소개 / 경험 공유 / 문제 해결]입니다.
읽을 대상은 [대상 독자]이며, 이 독자가 가장 끌릴 만한 포인트는 [관심 포인트]입니다.
이 글에서 노리고 싶은 검색 표현은 [검색 키워드 또는 독자 질문]입니다.

아래 기준으로 제목 후보를 7개 제안해 주세요.

1. 정보형 제목
2. 문제 해결형 제목
3. 경험 공유형 제목
4. 호기심 유도형 제목
5. 비교/대조형 제목
6. 실전 팁형 제목
7. 가장 추천하는 제목 1개와 그 이유

제목은 너무 자극적이지 않되, 읽는 사람이 클릭할 이유가 보이게 써주세요.
가능하면 각 제목의 성격 차이도 짧게 설명해 주세요.
검색 유입과 클릭 유도의 균형도 함께 고려해 주세요.
각 제목마다 “누가 왜 클릭할지”를 한 줄씩 붙여주세요.
너무 뻔하거나 흔한 표현이 들어간 제목은 왜 약한지도 짚어주세요.
```

### 바꿔야 할 부분
- `[주제]`: 예) AI시킴 사용법, 직장인 업무 자동화
- `[정보 제공 / 제품 소개 / 경험 공유 / 문제 해결]`: 글 목적
- `[대상 독자]`: 예) AI 초보자, 직장인, 1인 사업자
- `[관심 포인트]`: 예) 시간 절약, 쉬운 시작, 실전 활용
- `[검색 키워드 또는 독자 질문]`: 예) 블로그 글 구조 잡는 법, AI로 글 제목 뽑는 방법

### 후속 질문
- 위 제목 중 검색형 3개와 클릭형 3개를 다시 나눠서 더 뽑아줘.
- 가장 추천한 제목을 기준으로 소제목 구조와 도입부 첫 문장도 같이 제안해줘.

### 수정 요청
- 너무 흔한 표현은 줄이고 더 신선한 표현으로 바꿔줘.
- 클릭 유도는 유지하되 과장된 느낌은 줄여줘.

### 검수 요청
- 이 제목들이 대상 독자에게 실제로 매력적으로 보일지 검수해줘.
- 검색 유입과 클릭 유도 측면에서 아쉬운 제목이 있다면 바꿔줘.

### 자주 하는 실수
- 독자 없이 제목만 뽑아달라고 한다
- 제목의 방향 차이를 안 나눠서 비슷한 것만 받는다
- 검색 의도 없이 자극적인 제목만 원한다
- 제목만 받고 끝내고 구조까지 안 이어간다

### 이 순서에서 쓰면 좋습니다
1. 블로그 초안 생성형으로 구조를 만든다
2. 이 작업지시서로 제목을 강화한다
3. 독자 맞춤 수정형으로 본문 톤을 다듬는다

### 사용 팁
제목은 글의 입구이자 약속입니다.  
좋은 제목은 “누구를 위한 글인지”, “무엇을 얻는지”, “왜 지금 읽어야 하는지” 중 최소 두 가지가 보여야 합니다.

## 블로그 도입부를 더 강하게 쓰고 싶을 때

### 한 줄 설명
이미 정한 주제와 구조는 유지하되, 첫 문단과 다음 연결 문장까지 다듬어 독자의 시선을 더 강하게 붙잡는 도입부 강화형 작업지시서입니다.

### 이럴 때 가장 먼저 꺼내 쓰세요
- 제목과 본문 방향은 괜찮은데 첫 3~5문장이 약할 때
- 글 전체를 갈아엎고 싶지는 않지만 시작 구간의 흡입력만 높이고 싶을 때

### 이 항목이 다른 항목과 다른 점
이 항목은 글 전체 구조나 소제목을 다시 짜는 용도가 아니라, `독자가 읽기 시작하는 첫 진입 구간`만 집중적으로 강화하는 데 목적이 있습니다.

### 이런 상황에서 특히 잘 맞습니다
- 제목과 소제목은 괜찮은데 첫 문단이 밋밋할 때
- 도입부에서 독자의 문제를 충분히 건드리지 못할 때
- 클릭은 됐는데 읽기 시작 부분이 약할 때

### 이 작업지시서로 기대할 수 있는 결과
- 더 강한 첫 문장
- 독자 공감이 살아 있는 도입부
- 첫 문장 다음에 이어지는 자연스러운 연결 문장
- 문제 제기와 기대 결과가 선명한 시작 구간

### 언제 쓰는지
- 글 구조가 나온 뒤 도입부를 다듬는 단계
- 초안 작성 후 “첫 문단이 약하다”는 느낌이 들 때

### 바로 복사할 본문
```text
아래는 제가 작성하려는 글의 제목과 구조입니다.
전체 흐름은 유지하되, 도입부만 더 강하게 다시 써주세요.

이번 글의 주제는 [주제]이고,
대상 독자는 [대상 독자]입니다.
이 독자가 가장 자주 느끼는 문제는 [핵심 문제]입니다.
이 글을 읽고 나면 독자가 얻어가야 하는 핵심은 [얻어가야 할 결과]입니다.
도입부에서 신뢰를 주기 위해 넣을 수 있는 실제 경험/예시는 [짧은 경험 또는 근거 포인트]입니다.

도입부는 아래 기준으로 다시 써주세요.
1. 첫 문장에서 독자의 문제를 더 분명하게 건드릴 것
2. 너무 추상적인 설명은 줄일 것
3. 독자가 "이 글은 나한테 필요하다"는 느낌을 빨리 받게 할 것
4. 글을 끝까지 읽고 싶게 만드는 흐름을 만들 것
5. 첫 문장 다음 문단이 자연스럽게 이어지게 할 것

답변은 아래 순서로 주세요.
1. 더 강한 첫 문장 3개
2. 그중 가장 추천하는 1개와 이유
3. 첫 문장 다음에 붙는 연결 문장 2개
4. 다듬은 도입부 최종본
```

## 소제목 구조를 더 읽기 좋게 정리하고 싶을 때

### 한 줄 설명

### 바꿔야 할 부분

### 후속 질문

### 수정 요청

### 검수 요청
- 지금 상태에서 정말 빠진 핵심 요소가 없는지 한 번 더 검수해줘.
- 보완 우선순위가 적절한지도 점검해줘.

### 사용 팁
결과물이 약할 때는 전체를 새로 쓰기보다, 빠진 요소 1~2개를 보완하는 쪽이 훨씬 빠를 때가 많습니다.

## 전체 작업 흐름을 한 번에 설계하고 싶을 때

### 한 줄 설명

- 단발성 질문이 아니라 결과물을 끝까지 완성하고 싶을 때

- AI 활용을 더 체계적으로 해보고 싶을 때

- 첫 질문

```text

- 목적: [무엇을 만들고 싶은지]

- 현재 막힌 부분: [어디서 막히는지]

1. 첫 질문
2. 첫 결과를 받은 뒤 이어갈 후속 질문
3. 결과가 약할 때 수정 요청하는 질문
4. 완성도를 높이기 위한 추가 질문
5. 마지막 품질 검수 질문

각 단계마다 왜 필요한지도 짧게 설명해 주세요.
가능하면 각 단계마다 바로 복사해서 쓸 문장 예시도 함께 붙여 주세요.
설명만 길게 하지 말고, 실제로 그대로 따라할 수 있는 흐름으로 정리해 주세요.
```

### 바꿔야 할 부분
- `[목표 작업]`: 예) 블로그 글 완성, 보고서 작성, 기능 정의, 제안서 고도화
- `[무엇을 만들고 싶은지]`: 실제 목적
- `[누가 보거나 쓰는지]`: 대상
- `[어디서 막히는지]`: 현재 문제
- `[어떤 상태를 원하는지]`: 원하는 완성 결과

### 후속 질문
- 위 흐름을 더 짧은 실전형 버전으로 다시 줄여줘.

### 수정 요청

- 빠진 단계가 있다면 보완해줘.

### 자주 하는 실수
- 목적은 있는데 대상과 최종 결과가 불분명하다
- 수정 요청 단계를 빼먹는다
- 첫 질문만 정리하고 후속 흐름을 안 만든다

### 이 순서에서 쓰면 좋습니다
1. 이 작업지시서로 전체 흐름을 잡는다
2. 각 단계에 맞는 카테고리 작업지시서로 들어간다
3. 마지막에 검수형으로 마무리한다

### 사용 팁
이 작업지시서는 단일 작업지시서가 아니라 “AI를 쓰는 전체 방식”을 바꾸는 데 더 큰 가치가 있습니다.  
결과물이 중요한 작업일수록, 처음부터 이 흐름을 잡아두는 편이 훨씬 강합니다.
