# AI시킴 업무/보고서 집중팩

보고서 초안, 상사 보고, 기획서 정리, 문제 보고, 최종 검수까지 실무 문서 흐름에 맞춘 작업지시서

---

## 이 팩이 특히 잘 맞는 사람
- 보고 문서 초안을 더 빨리 정리하고 싶은 직장인
- 상사나 이해관계자가 바로 이해하는 문장을 만들고 싶은 사람
- 실행안, 요약본, 문제 보고처럼 실무 문서를 반복 작성하는 사람

## 먼저 이렇게 사용하세요
1. 보고서 뼈대가 막히면 `업무 보고서의 기본 구조를 잡고 싶을 때`부터 시작합니다.
2. 상사 공유용으로 줄여야 하면 `상사 보고용 요약본을 짧게 만들고 싶을 때`를 이어서 사용합니다.
3. 제출 직전에는 `완성된 보고서나 기획서를 최종 검수하고 싶을 때`로 마무리합니다.

## 이 팩은 왜 따로 존재하나요?
이 패키지는 특정 분야에서 바로 써먹을 수 있는 작업지시서만 빠르게 꺼내 쓰고 싶은 사용자를 위해 분리한 집중팩입니다.
즉, 안 쓸 분야까지 같이 사는 느낌보다 `내가 지금 필요한 문제를 바로 해결하는 느낌`이 먼저 오도록 구성합니다.

## 핵심 작업지시서
## 업무 보고서의 기본 구조를 잡고 싶을 때

### 한 줄 설명
상사나 팀이 바로 이해할 수 있는 보고서 구조를 빠르게 잡아주는 실무 초안 생성형 작업지시서입니다.

### 이런 상황에서 특히 잘 맞습니다
- 내용을 알고는 있지만 문서 구조가 안 잡힐 때
- 보고서를 짧은 시간 안에 초안 수준으로 만들어야 할 때
- AI 답변이 장황하고 실무감이 없을 때

### 이 작업지시서로 기대할 수 있는 결과
- 한 줄 요약
- 배경
- 현재 상황
- 핵심 이슈
- 제안 또는 다음 행동

### 언제 쓰는지
- 첫 초안 작성 단계
- 보고용 문서 구조를 처음 잡는 시점

### 바로 복사할 본문
```text
지금 저는 [업무 주제]에 대한 보고서 초안을 정리해야 합니다.
이 문서는 [상사 / 팀원 / 고객 / 이해관계자]가 읽을 예정입니다.
보고 목적은 [현황 공유 / 문제 보고 / 제안 / 실행 계획 정리]입니다.
이 문서를 읽는 사람이 가장 먼저 이해해야 하는 것은 [핵심 이슈 / 제안 / 요청 사항]입니다.

먼저 이 문서에 꼭 들어가야 할 핵심 항목이 있다면 질문해 주세요.
그 다음 아래 형식으로 보고서 초안을 작성해 주세요.

1. 한 줄 요약
2. 배경
3. 현재 상황
4. 핵심 이슈
5. 제안 또는 다음 행동

답변은 실무 문서처럼 단정하고 명확하게 정리해 주세요.
불필요하게 장황하지 않게 쓰되, 실제 공유 가능한 수준으로 내용 밀도를 유지해 주세요.
읽는 사람이 빠르게 판단할 수 있도록 중요한 내용을 앞쪽에 배치해 주세요.
```

### 바꿔야 할 부분
- `[업무 주제]`: 예) 신규 서비스 출시 준비, 콘텐츠 운영 계획
- `[상사 / 팀원 / 고객 / 이해관계자]`: 실제 독자
- `[현황 공유 / 문제 보고 / 제안 / 실행 계획 정리]`: 문서 목적
- `[핵심 이슈 / 제안 / 요청 사항]`: 우선 이해 포인트

### 후속 질문
- 이 문서를 임원 보고용으로 더 짧게 다시 정리해줘.
- 핵심 이슈 3개가 먼저 보이도록 요약형 버전도 추가해줘.

### 수정 요청
- 문장을 더 단정하게 바꾸고 군더더기를 줄여줘.
- 읽는 사람이 바로 의사결정할 수 있게 제안 부분을 더 선명하게 써줘.

### 검수 요청
- 이 보고서에서 빠진 핵심 항목이 있는지 점검해줘.
- 상사가 읽었을 때 바로 이해하기 어려운 부분이 있는지 검수해줘.

### 자주 하는 실수
- 배경 설명이 너무 길어진다
- 핵심 이슈보다 설명이 먼저 나온다
- 독자가 누구인지 정하지 않고 문서를 만든다

### 이 순서에서 쓰면 좋습니다
1. 이 작업지시서로 기본 구조를 만든다
2. 요약본 압축형 작업지시서로 줄인다
3. 최종 검수형 작업지시서로 제출 전 점검한다

### 사용 팁
보고서는 `길게 잘 쓰는 것`보다 `읽는 사람이 빨리 이해하는 것`이 더 중요합니다.  
한 줄 요약과 핵심 이슈가 약하면 본문을 아무리 잘 써도 체감 품질이 떨어집니다.

## 보고서 목차를 더 설득력 있게 만들고 싶을 때

### 한 줄 설명
보고서나 기획서 초안이 있는데 목차 흐름이 약할 때, 읽는 사람이 더 빨리 이해하고 설득되도록 목차를 재구성하는 작업지시서입니다.

### 이럴 때 가장 먼저 꺼내 쓰세요
- 본문을 쓰기 전에 문서의 뼈대부터 설득력 있게 정리해야 할 때
- 보고서 내용을 손보기보다 `무슨 순서로 읽히게 할지`가 먼저 중요할 때

### 이 항목이 다른 항목과 다른 점
이 항목은 기획서 본문을 채우는 작업이 아니라, `읽는 사람의 이해 순서와 의사결정 흐름`에 맞게 목차를 재배열하는 데 집중합니다.

### 이런 상황에서 특히 잘 맞습니다
- 내용은 있는데 목차 순서가 어색할 때
- 목차만 봐도 무엇을 말하려는지 드러나지 않을 때
- 상사나 의사결정자가 빠르게 이해하게 만들고 싶을 때

### 이 작업지시서로 기대할 수 있는 결과
- 더 설득력 있는 목차 구조
- 중요 내용 우선 배치
- 읽는 흐름이 살아 있는 문서 구조

### 언제 쓰는지
- 보고서 초안 작성 초반
- 본문 쓰기 전 목차 정리 단계

### 바로 복사할 본문
```text
지금 저는 [문서 주제]에 대한 [보고서 / 기획서 / 제안서]를 작성하고 있습니다.
현재 초안은 있는데, 목차 순서와 흐름이 아직 설득력 있게 잡히지 않았습니다.
이 문서를 읽을 사람은 [상사 / 고객 / 팀 리더 / 의사결정자]입니다.
이 사람이 가장 먼저 이해해야 하는 것은 [핵심 이슈 / 제안 / 방향 / 요청 사항]입니다.

먼저 이 문서에서 가장 먼저 보여야 할 논리 흐름이 무엇인지 짚어주세요.
그 다음 아래 기준으로 목차를 다시 제안해 주세요.

1. 읽는 사람이 빠르게 이해할 수 있는 순서
2. 중요도가 높은 내용이 먼저 보이는 구조
3. 중복되거나 약한 항목은 정리
4. 문서 목적과 잘 맞는 흐름

답변은 아래 순서로 주세요.
1. 현재 목차가 약한 이유
2. 추천 목차 구조
3. 각 목차 항목에 들어갈 핵심 한 줄
```

### 바꿔야 할 부분
- `[문서 주제]`
- `[보고서 / 기획서 / 제안서]`
- `[상사 / 고객 / 팀 리더 / 의사결정자]`
- `[핵심 이슈 / 제안 / 방향 / 요청 사항]`

### 후속 질문
- 위 목차를 임원 보고용으로 더 짧게 압축해줘.
- 실무자용 상세 버전 목차도 따로 만들어줘.

### 수정 요청
- 목차 이름을 더 실무적으로 바꿔줘.
- 읽는 사람이 바로 핵심을 파악하기 쉬운 표현으로 수정해줘.

### 검수 요청
- 이 목차만 봐도 문서 목적이 충분히 드러나는지 검수해줘.
- 흐름상 어색하거나 순서를 바꾸는 게 더 좋은 항목이 있는지 점검해줘.

### 사용 팁
좋은 목차는 예쁘게 나열된 항목이 아니라, 읽는 사람이 “어떤 논리로 읽어야 하는지”를 미리 보여주는 구조입니다.

## 회의록을 실무 문서로 정리하고 싶을 때

### 한 줄 설명
메모 수준의 회의 내용을 실제 실행 가능한 실무 문서로 바꾸는 회의록 정리형 작업지시서입니다.

### 이런 상황에서 특히 잘 맞습니다
- 회의 메모는 있는데 공유용 문서가 안 나올 때
- 누가 무엇을 해야 하는지 정리가 안 될 때
- 회의 후 액션 아이템이 흐려질 때

### 이 작업지시서로 기대할 수 있는 결과
- 회의 목적 요약
- 결정 사항
- 미결 사항
- 담당자별 액션 아이템

### 언제 쓰는지
- 회의 직후
- 팀 공유 문서 정리 단계

### 바로 복사할 본문
```text
아래는 회의 중 메모해둔 내용입니다.
이 내용을 팀이 실제로 바로 이해하고 움직일 수 있는 실무형 회의록으로 정리해 주세요.

회의 목적은 [회의 목적]이고,
참여자는 [참여자 성격 또는 역할]입니다.
이 회의에서 가장 중요한 것은 [결정 사항 / 미결 사항 / 다음 액션]입니다.

아래 형식으로 정리해 주세요.
1. 회의 목적 한 줄 요약
2. 핵심 논의 내용
3. 결정된 사항
4. 아직 미결정인 사항
5. 다음 액션 아이템
6. 담당자 또는 확인 필요 주체

답변은 길게 풀어쓰기보다, 실제 공유 문서처럼 바로 전달 가능한 형태로 정리해 주세요.
모호한 표현보다 누가 봐도 이해되는 구조를 우선해 주세요.
```

### 바꿔야 할 부분
- `[회의 목적]`
- `[참여자 성격 또는 역할]`
- `[결정 사항 / 미결 사항 / 다음 액션]`

### 후속 질문
- 이 회의록을 상사 공유용으로 더 짧게 다시 정리해줘.
- 액션 아이템만 별도 체크리스트 형태로 다시 뽑아줘.

### 수정 요청
- 논의 내용은 줄이고, 결정과 액션이 더 선명하게 보이게 바꿔줘.
- 담당자와 일정이 더 잘 보이게 구조를 다시 정리해줘.

### 검수 요청
- 이 회의록만 봐도 누가 무엇을 해야 하는지 충분히 보이는지 검수해줘.
- 빠진 핵심 결정 사항이 있다면 짚어줘.

### 사용 팁
회의록은 회의 내용을 “기록”하는 문서보다, 회의 이후 “행동”이 가능하게 만드는 문서로 보는 것이 좋습니다.

## 상사 보고용 요약본을 짧게 만들고 싶을 때

### 한 줄 설명
긴 문서나 정리 메모를 상사가 30초 안에 이해할 수 있는 보고형 요약본으로 압축하는 작업지시서입니다.

### 이런 상황에서 특히 잘 맞습니다
- 이미 긴 문서가 있는데 핵심만 보고해야 할 때
- 임원/상사 보고 전에 핵심 정리가 필요할 때
- 문서는 있지만 판단 포인트가 흐릴 때

### 이 작업지시서로 기대할 수 있는 결과
- 한 줄 요약
- 핵심 이슈 3개
- 판단 포인트
- 요청 사항 또는 다음 행동

### 언제 쓰는지
- 초안이 이미 있을 때
- 공유 전 `압축본`이 필요할 때

### 바로 복사할 본문
```text
아래 내용은 현재 [보고서 / 기획서 / 메모 / 회의 정리]의 전체 초안입니다.
이 내용을 [상사 / 임원 / 팀 리더]가 빠르게 이해할 수 있도록 짧은 요약본으로 다시 정리해 주세요.

정리 기준은 아래와 같습니다.
1. 한 줄 요약
2. 지금 가장 중요한 핵심 이슈 3개
3. 바로 판단해야 할 포인트
4. 다음 행동 또는 요청 사항

문장은 짧고 단정하게 써주세요.
읽는 사람이 30초 안에 전체 맥락을 파악할 수 있게 정리해 주세요.
설명보다 판단이 쉬운 구조를 우선해 주세요.
```

### 바꿔야 할 부분
- `[보고서 / 기획서 / 메모 / 회의 정리]`: 원문 성격
- `[상사 / 임원 / 팀 리더]`: 실제 독자
- 아래에 실제 원문 붙여 넣기

### 후속 질문
- 위 요약본을 더 짧게 5문장 안으로 줄여줘.
- 지금 버전을 유지하되 보고용 어조를 더 단정하게 바꿔줘.

### 수정 요청
- 설명형 문장을 줄이고 판단 포인트가 먼저 보이게 바꿔줘.
- 읽는 사람이 바로 결정할 수 있게 요청 사항을 더 선명하게 써줘.

### 검수 요청
- 이 요약본만 읽어도 맥락이 충분히 보이는지 검수해줘.
- 빠진 핵심 정보가 있다면 최소 범위에서 보완해줘.

### 자주 하는 실수
- 원문을 너무 많이 압축해서 맥락이 사라진다
- 핵심 이슈와 요청 사항을 분리하지 않는다
- 독자의 역할에 따라 요약 방식이 달라져야 한다는 점을 놓친다

### 이 순서에서 쓰면 좋습니다
1. 보고서 초안 생성형으로 기본 구조를 만든다
2. 이 작업지시서로 요약본을 만든다
3. 제출 전 검수형으로 최종 확인한다

### 사용 팁
보고용 요약본은 “잘 쓴 요약”보다 “의사결정하기 쉬운 요약”이 더 중요합니다.

## 기획서 초안을 항목별로 채우고 싶을 때

### 한 줄 설명
빈 기획서 템플릿이나 러프한 개요를 실제 항목별 문장으로 채워 넣는 구조화형 작업지시서입니다.

### 이럴 때 가장 먼저 꺼내 쓰세요
- 목차는 이미 정했는데 각 항목 본문이 비어 있을 때
- 기획서 흐름은 잡혔지만 `실제 문장 초안`이 하나도 안 써질 때

### 이 항목이 다른 항목과 다른 점
이 항목은 목차를 재구성하는 용도보다, `빈 항목을 실무 문장으로 채우는 초안 생산`에 더 초점이 맞춰져 있습니다.

### 이런 상황에서 특히 잘 맞습니다
- 목차는 있는데 본문이 안 써질 때
- 기획서를 처음부터 다 쓰기 막막할 때
- 항목별로 빠르게 초안을 채우고 싶을 때

### 이 작업지시서로 기대할 수 있는 결과
- 항목별 본문 초안
- 빠진 핵심 요소 보완
- 실제 공유 가능한 기획서 초안 구조

### 언제 쓰는지
- 기획서 작성 초반
- 항목별 초안 채우기 단계

### 바로 복사할 본문
```text
지금 저는 [기획서 주제]에 대한 기획서 초안을 작성하고 있습니다.

1. 각 항목마다 왜 필요한지 짧게 드러날 것
2. 너무 추상적이지 않게 실제 문서처럼 쓸 것
3. 읽는 사람이 빠르게 이해할 수 있게 구조화할 것

답변은 아래 순서로 주세요.
1. 항목별 핵심 포인트
```

## 제안서를 읽는 사람이 바로 이해하게 고치고 싶을 때

### 한 줄 설명
길고 복잡한 제안서나 기획안을, 읽는 사람이 핵심을 더 빨리 이해하고 판단할 수 있게 다듬는 설득력 강화형 작업지시서입니다.

### 이런 상황에서 특히 잘 맞습니다
- 제안서가 길고 복잡하게 느껴질 때
- 내용은 맞지만 한 번에 핵심이 안 들어올 때
- 읽는 사람이 “그래서 뭘 제안하는지”를 빨리 이해하길 원할 때

### 이 작업지시서로 기대할 수 있는 결과
- 핵심 메시지 선명화
- 구조 개선 포인트
- 이해가 쉬운 최종본
- 의사결정 포인트가 앞쪽에 보이는 문서

### 언제 쓰는지
- 초안이 이미 있고, 제출 전 설득력을 끌어올리고 싶을 때

### 바로 복사할 본문
```text
아래 문서는 [제안서 / 소개서 / 기획안] 초안입니다.
내용 자체는 있지만, 읽는 사람이 핵심을 한 번에 이해하기에는 다소 복잡하거나 흐름이 약합니다.

이 문서를 읽는 사람은 [대표 / 고객 / 의사결정자 / 팀 리더]입니다.
이 사람이 가장 빠르게 이해해야 하는 것은 [핵심 제안 / 기대 효과 / 차별점 / 실행 가능성]입니다.

그 다음 아래 기준으로 문서를 다시 다듬어 주세요.

1. 핵심 메시지가 앞쪽에서 더 잘 보이게 할 것
2. 중복되거나 흐린 표현은 줄일 것
3. 읽는 사람이 빠르게 판단할 수 있게 구조를 정리할 것
4. 장점과 기대 효과가 선명하게 보이게 할 것
5. "그래서 왜 이걸 해야 하는지"가 더 분명하게 보이게 할 것

답변은 아래 순서로 작성해 주세요.
1. 현재 문서의 이해 방해 요소
2. 구조 개선 방향
3. 다듬은 최종본

최종본은 실제로 상대방에게 제출하거나 공유할 수 있는 수준으로 정리해 주세요.
```

### 바꿔야 할 부분

- `[대표 / 고객 / 의사결정자 / 팀 리더]`: 읽는 사람
- `[핵심 제안 / 기대 효과 / 차별점 / 실행 가능성]`: 우선 포인트
- 아래에 실제 문서 초안 붙여 넣기

### 후속 질문
- 위 최종본을 유지한 채 1페이지 요약본 형태로도 다시 만들어줘.
- 읽는 사람이 가장 먼저 보게 될 도입부만 더 선명하게 다시 써줘.

### 수정 요청
- 문장을 더 단정하고 명확하게 바꿔줘.
- 장점은 유지하되 과장처럼 보이는 표현은 줄여줘.

### 검수 요청
- 이 문서를 처음 읽는 사람이 핵심을 빠르게 이해할 수 있는지 검수해줘.
- 여전히 흐리거나 중복되는 부분이 있다면 표시해줘.

### 자주 하는 실수
- 핵심 제안보다 배경 설명이 먼저 나온다
- 장점은 있는데 판단 포인트가 약하다
- 독자가 누구인지에 따라 구조를 다르게 잡아야 한다는 점을 놓친다

### 이 순서에서 쓰면 좋습니다
1. 제안서 초안을 먼저 만든다
2. 이 작업지시서로 핵심 메시지와 구조를 정리한다

### 사용 팁

## 완성된 보고서나 기획서를 최종 검수하고 싶을 때

### 한 줄 설명

### 이럴 때 가장 먼저 꺼내 쓰세요

- 목차나 초안 채우기는 끝났고, `제출 가능한 수준`인지 마지막으로 확인하고 싶을 때

### 이 항목이 다른 항목과 다른 점
이 항목은 목차 정리나 기획서 초안 작성과 다르게, `논리 흐름·판단 포인트·제출 직전 리스크`를 걸러내는 제출 직전 검수용입니다.

### 이런 상황에서 특히 잘 맞습니다
- 문서는 다 썼는데 설득력이 충분한지 불안할 때
- 빠진 근거나 흐름상 약한 부분이 없는지 확인하고 싶을 때
- 상사나 고객에게 보내기 전 마지막 점검이 필요할 때

### 이 작업지시서로 기대할 수 있는 결과

- 빠진 핵심 요소

- 더 다듬어진 최종본

### 언제 쓰는지

### 바로 복사할 본문

- 결과물 마무리 전
- 최종 점검 루틴 만들기 단계

### 바로 복사할 본문
```text
지금 저는 [결과물 종류]를 거의 마무리한 상태이며, 마지막 검수 질문을 더 잘 던지고 싶습니다.

검수의 목적은 [빠진 요소 확인 / 읽기 쉬움 확인 / 설득력 확인 / 제출 가능 여부 판단 / 오류 점검]입니다.
읽는 사람은 [상사 / 고객 / 사용자 / 팀원 / 일반 독자]입니다.

아래 기준으로 검수 질문을 설계해 주세요.
1. 꼭 확인해야 할 핵심 질문
2. 결과물 종류에 맞는 검수 질문
3. 너무 막연하지 않고 실제로 도움이 되는 질문
4. 최종 제출 여부를 판단하는 질문

답변은 아래 순서로 주세요.
1. 검수 질문 5개
2. 그중 가장 중요한 핵심 질문 1개
3. 바로 복사해서 쓸 최종 검수 질문 문장
```

### 바꿔야 할 부분
- `[결과물 종류]`
- `[빠진 요소 확인 / 읽기 쉬움 확인 / 설득력 확인 / 제출 가능 여부 판단 / 오류 점검]`
- `[상사 / 고객 / 사용자 / 팀원 / 일반 독자]`

### 후속 질문
- 위 검수 질문을 더 짧고 실전형으로 다시 줄여줘.
- 초보자도 바로 쓸 수 있게 설명을 더 쉽게 붙여줘.

### 수정 요청
- 막연한 질문은 줄이고 실제로 판단 가능한 질문 중심으로 바꿔줘.
- 결과물 종류에 더 맞는 질문으로 다시 다듬어줘.

### 검수 요청
- 이 검수 질문 세트가 실제 품질 점검에 도움이 되는지 검수해줘.
- 빠진 핵심 검수 관점이 있다면 보완해줘.

### 사용 팁
좋은 검수 질문은 “어때?”가 아니라 “무엇이 빠졌는지, 무엇이 약한지, 지금 내보내도 되는지”를 분명히 묻는 질문입니다.

## 전체 작업 흐름을 한 번에 설계하고 싶을 때

### 한 줄 설명
첫 질문부터 후속 질문, 수정 요청, 검수 질문까지 하나의 결과를 끝까지 완성하기 위한 전체 작업 흐름 설계형 작업지시서입니다.

### 이런 상황에서 특히 잘 맞습니다
- 단발성 질문이 아니라 결과물을 끝까지 완성하고 싶을 때
- 처음부터 전체 흐름을 설계해서 덜 헤매고 싶을 때
- AI 활용을 더 체계적으로 해보고 싶을 때

### 이 작업지시서로 기대할 수 있는 결과
- 첫 질문
- 후속 질문
- 수정 요청 질문
- 추가 고도화 질문
- 마지막 품질 검수 질문

### 언제 쓰는지
- 작업 시작 전
- “이번에는 처음부터 끝까지 제대로 해보고 싶다”는 시점

### 바로 복사할 본문
```text
지금 저는 [목표 작업]을 AI와 함께 완성하고 싶습니다.
한 번 질문하고 끝내는 것이 아니라, 처음부터 결과물을 더 잘 만들 수 있도록 전체 작업 흐름을 설계해 주세요.

현재 제가 알고 있는 상황은 다음과 같습니다.
- 목적: [무엇을 만들고 싶은지]
- 대상: [누가 보거나 쓰는지]
- 현재 막힌 부분: [어디서 막히는지]
- 원하는 최종 결과: [어떤 상태를 원하는지]

먼저 이 작업을 시작하기 전에 꼭 확인해야 할 질문이 있다면 먼저 제시해 주세요.
그 다음 아래 순서로 전체 흐름을 설계해 주세요.

1. 첫 질문
2. 첫 결과를 받은 뒤 이어갈 후속 질문
3. 결과가 약할 때 수정 요청하는 질문
4. 완성도를 높이기 위한 추가 질문
5. 마지막 품질 검수 질문

각 단계마다 왜 필요한지도 짧게 설명해 주세요.
가능하면 각 단계마다 바로 복사해서 쓸 문장 예시도 함께 붙여 주세요.
설명만 길게 하지 말고, 실제로 그대로 따라할 수 있는 흐름으로 정리해 주세요.
```

### 바꿔야 할 부분
- `[목표 작업]`: 예) 블로그 글 완성, 보고서 작성, 기능 정의, 제안서 고도화
- `[무엇을 만들고 싶은지]`: 실제 목적
- `[누가 보거나 쓰는지]`: 대상
- `[어디서 막히는지]`: 현재 문제
- `[어떤 상태를 원하는지]`: 원하는 완성 결과

### 후속 질문
- 위 흐름을 더 짧은 실전형 버전으로 다시 줄여줘.
- 각 단계에서 실패하기 쉬운 포인트까지 같이 설명해줘.

### 수정 요청
- 설명보다 실제 복사할 문장 예시에 더 집중해서 다시 정리해줘.
- 단계 간 차이가 더 분명하게 보이도록 흐름을 다시 다듬어줘.

### 검수 요청
- 이 흐름만 따라가도 결과물을 끝까지 만들 수 있는지 검수해줘.
- 빠진 단계가 있다면 보완해줘.

### 자주 하는 실수
- 목적은 있는데 대상과 최종 결과가 불분명하다
- 수정 요청 단계를 빼먹는다
- 첫 질문만 정리하고 후속 흐름을 안 만든다

### 이 순서에서 쓰면 좋습니다
1. 이 작업지시서로 전체 흐름을 잡는다
2. 각 단계에 맞는 카테고리 작업지시서로 들어간다
3. 마지막에 검수형으로 마무리한다

### 사용 팁
이 작업지시서는 단일 작업지시서가 아니라 “AI를 쓰는 전체 방식”을 바꾸는 데 더 큰 가치가 있습니다.  
결과물이 중요한 작업일수록, 처음부터 이 흐름을 잡아두는 편이 훨씬 강합니다.
