# AI시킴 개발 기획서 v1.0

## 1. 문서 목적
이 문서는 `AI시킴`의 1차 MVP를 개발 가능한 수준으로 정의하는 기준 문서입니다. 이후 랜딩페이지 설계, 질문 흐름 설계, 이메일 수집 구조, 판매 페이지 설계, Claude Code 작업 지시, Codex 리뷰 기준의 상위 기준으로 사용합니다.

## 2. 서비스 정의
- 서비스명: AI시킴
- 한 줄 정의: AI에게 뭘 시켜야 할지 모르겠다면, 선택만으로 ChatGPT·Claude·Gemini·Codex에 바로 넣을 수 있는 작업지시서를 만들어주는 모바일 최적화 웹서비스
- 서비스 형태: 앱이 아닌 모바일 최적화 웹서비스
- 핵심 방식: 사용자가 긴 설명을 입력하는 대신, 목적·상황·막힌 부분·원하는 결과물·사용할 AI 도구·원하는 톤을 선택하면 기본 작업지시서를 생성

## 3. 문제 정의
많은 사용자가 ChatGPT, Claude, Gemini 같은 생성형 AI를 사용해보고 싶어 하지만 다음 문제에서 막힙니다.

- 무엇을 먼저 물어봐야 할지 모른다.
- 내 상황을 AI에게 어떻게 설명해야 할지 모른다.
- 답변이 뻔하거나 일반론적으로 나와서 실망한다.
- 한 번의 질문으로 끝내려 하다 보니 결과물이 완성형으로 이어지지 않는다.
- "작업지시서"라는 개념은 필요해 보이지만 실제 작업 흐름 단위로 지시하는 방법은 어렵다.

AI시킴은 이 문제를 "자유 입력"이 아니라 "선택 반응형 질문 흐름"으로 푸는 것을 핵심 차별점으로 삼습니다.

## 4. 제품 목표
### 4.1 1차 제품 목표
- AI 초보자도 3분 이내에 기본 작업지시서 1개를 얻을 수 있게 한다.
- 무료 결과에서 이메일 전환으로 이어지게 한다.
- 유료 스타터팩 소개를 자연스럽게 연결한다.

### 4.2 사업 목표
- 출시 후 2개월 안에 유료 상품 1개 이상 판매
- 초기 시장 검증 지표 확보
- 어떤 카테고리와 어떤 메시지가 가장 전환이 높은지 파악

## 5. 타깃 고객
### 5.1 1차 타깃
- AI는 쓰고 싶지만 어떻게 써야 할지 막막한 초보 사용자
- 블로그 글쓰기, 업무 문서, 개발 지시 같은 실용 작업이 필요한 사용자
- 모바일에서 가볍게 탐색하고 바로 결과를 보고 싶은 사용자

### 5.2 구체 고객군
- 개인 창작자 및 1인 사업자
- 직장인
- 사이드프로젝트 준비자
- 예비 창업자
- 비개발자지만 AI로 웹/앱 제작을 시도하는 사람

## 6. 핵심 가치 제안
- 직접 입력하지 않아도 선택만으로 시작 가능
- 한 번에 대충 묻고 끝내는 방식이 아니라 결과물을 완성하는 단계별 작업지시서 제공
- 모바일에서 빠르게 사용 가능
- AI 도구별로 바로 붙여 넣어 쓸 수 있는 형태 제공
- 무료 결과와 유료 확장 흐름이 명확함

## 7. 핵심 메시지
### 7.1 메인 메시지
AI에게 뭘 시켜야 할지 모르겠다면, 직접 쓰지 말고 선택하세요.

### 7.2 보조 메시지
AI시킴은 몇 가지 선택만으로 ChatGPT·Claude·Gemini·Codex에 바로 넣을 수 있는 작업지시서를 만들어드립니다.

### 7.3 유료 상품 메시지
무료 결과는 기본 작업지시서 1개만 제공합니다.  
실제로 결과물을 완성하려면 첫 질문, 후속 질문, 수정 요청, 검수 질문까지 포함된 전체 작업 흐름이 필요합니다.

## 15. 이메일 수집 구조
### 15.1 수집 목적
- 무료 샘플팩 발송
- 서비스 업데이트 안내
- 유료 상품 안내
- 향후 신규 작업지시서팩 안내

### 15.2 동의 구조
- 샘플팩 발송을 위한 이메일 수집 동의
- 향후 서비스 업데이트 및 유료 상품 안내 수신 동의
- 언제든지 수신 거부 가능 문구 포함

### 15.3 입력 최소화 원칙
- MVP에서는 이메일만 받는 것을 기본 가정
- 이름, 회사명, 전화번호는 받지 않는 방향 우선 검토

## 16. 결제 연결 방식
### 16.1 MVP 원칙
- 자체 결제 시스템은 제외
- 외부 결제 링크 기반으로 우선 검증

### 16.2 검토 대상
- Tally 또는 간단한 신청폼 + 수동 안내/수동 발송
- 스마트스토어
- 크몽
- 수동 계좌이체 또는 기타 외부 결제 링크
- Lemon Squeezy

### 16.3 초기 MVP 우선안
- 1차 MVP에서는 Tally 또는 간단한 신청폼을 통해 신청을 받고, 수동 안내 및 수동 발송으로 운영하는 방식을 우선 검토한다.
- 실제 결제는 크몽, 스마트스토어, 수동 계좌이체, 기타 외부 결제 링크 중 운영 난이도와 신뢰도를 비교해 선택할 수 있게 설계한다.
- Lemon Squeezy는 해외형 디지털 상품 판매에는 적합하지만 국내 사용자 결제 경험 관점에서는 2순위 후보로 둔다.

### 16.4 결제 후 자료 제공 가정
- 기본 포맷: PDF
- 보조 포맷: Notion 링크

## 18. 모바일 UI 원칙
- 첫 화면에서 핵심 메시지와 CTA가 즉시 보여야 한다.
- 질문은 한 번에 하나씩 보여주는 방식 우선 검토
- 선택지는 터치하기 쉬운 카드형 UI 권장
- 결과 페이지는 복사하기 쉬운 구조여야 한다.
- 구매 유도는 과하지 않되, 무료와 유료 차이를 명확하게 보여야 한다.

## 20. 리스크와 대응
### 20.1 리스크
- 사용자가 "이게 왜 필요한지"를 즉시 이해하지 못할 수 있음
- 무료 결과만 보고 이탈할 수 있음
- 외부 결제 링크가 신뢰를 떨어뜨릴 수 있음
- 작업지시서 품질이 카테고리별로 균일하지 않을 수 있음

### 20.2 대응
- 랜딩페이지에서 문제와 해결 방식을 더 직관적으로 설명
- 무료 결과와 유료 스타터팩의 차이를 구체 예시로 비교
- 결제 후 제공 방식, 환불 안내, 자료 형식을 명확히 고지
- 초기에는 카테고리를 좁게 가져가 품질을 높임

## 23. 최종 정리
AI시킴 MVP의 본질은 "AI에게 물어볼 말을 직접 쓰게 하지 않고, 선택만으로 실행 가능한 작업지시서를 제공하는 것"입니다. 이 문서는 그 핵심을 흔들지 않기 위한 제품 기준 문서로 유지합니다.
