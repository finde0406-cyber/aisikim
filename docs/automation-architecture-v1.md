# AI시킴 자동화 아키텍처 v1

## 1. 문서 목적
이 문서는 AI시킴에서 무료 샘플팩 발송, 유료 스타터팩 발송, 향후 딥팩 발송까지 어떤 구조로 자동화할 수 있는지 정리한 기준 문서입니다.  
핵심은 `실시간 생성 자동화`가 아니라, `미리 만들어둔 고정 자산을 조건에 맞게 선택하고 자동 발송하는 구조`를 설계하는 것입니다.

## 2. 자동화의 기본 철학
AI시킴의 발송 자동화는 아래 원칙을 따릅니다.

1. 콘텐츠는 미리 완성해 둔다
2. 사용자의 선택 또는 구매 이벤트를 기준으로 분기한다
3. 그 분기에 맞는 파일/링크/메일을 자동으로 선택한다
4. 자동화는 편의를 위한 것이지, 허위 성공 상태를 보여주기 위한 것이 아니다

즉, AI시킴은 `즉석 생성형 서비스`보다 `고정 자산 자동 전달형 서비스`에 가깝습니다.

## 3. 자동화 대상

### 3.1 무료 샘플팩 자동화
- 사용자 이메일 수집
- 신청 정보 저장
- 신청 직후 메일 자동 발송
- 카테고리별 또는 공통 샘플팩 링크 자동 선택
- 관리자 알림

### 3.2 유료 스타터팩 자동화
- 결제 완료 확인
- 구매 상품 식별
- 스타터팩 PDF / Notion / 사용 가이드 자동 발송
- 구매 후 안내 메일 자동 발송

### 3.3 향후 딥팩 자동화
- 어떤 딥팩을 샀는지 식별
- 상품별 다른 메일/다른 링크 발송
- 업셀/후속 메일 자동화

## 4. 이벤트 기준 자동화 구조

### 4.1 무료 신청 이벤트
트리거:
- 사용자가 샘플팩 신청 폼 제출

필수 결과:
1. 신청 데이터 저장
2. 운영자 알림
3. 신청자 메일 발송
4. 신청 종류(공통 샘플팩 / 카테고리별 샘플팩)별 분기

### 4.2 유료 구매 이벤트
트리거:
- 결제 채널에서 결제 완료 이벤트 수신

필수 결과:
1. 어떤 상품이 결제됐는지 식별
2. 구매자 이메일 확인
3. 맞는 자료 링크 선택
4. 구매 후 안내 메일 발송

## 5. 1차 자동화 권장 구조

### 구조 요약
`폼 제출/결제 완료 -> 이벤트 수신 -> 고정 자산 선택 -> 메일 발송`

### 1차 MVP 권장 방식
- 무료 신청: `Tally`
- 메일 발송: `Tally 응답자 메일` 또는 `Webhook + Resend`
- 유료 발송: `외부 결제 완료 후 Webhook 또는 수동 확인 기반 자동 발송`

## 6. 현실적인 자동화 3단계

### 6.1 0단계: 수동 운영
- 신청은 폼으로 받는다
- 운영자가 직접 확인하고 수동 발송한다

장점:
- 가장 빨리 시작 가능
- 오류 원인 파악 쉬움

단점:
- 확장성 낮음
- 운영 피로도 높음

### 6.2 1단계: 반자동
- 신청은 폼으로 받는다
- 신청자/운영자 메일은 자동화한다
- 자료는 고정 링크를 자동으로 넣어 보낸다

장점:
- 운영 부담이 크게 줄어든다
- 가장 현실적인 초기 자동화 방식

단점:
- 결제와 연동이 완전히 매끄럽진 않을 수 있다

### 6.3 2단계: 완전자동
- 폼/결제 이벤트가 웹훅으로 들어온다
- 상품/카테고리 분기
- 메일 본문/링크 자동 선택
- 구매 직후 발송

장점:
- 운영 효율 높음
- 서비스 경험이 부드러움

단점:
- 구현 난이도와 점검 항목 증가

## 7. 무료 샘플팩 자동화 설계

### 7.1 공통 샘플팩만 보낼 때
가장 단순한 방식입니다.

흐름:
1. 이메일 입력
2. 신청 저장
3. 공통 샘플팩 메일 발송

장점:
- 운영 단순
- 가장 빨리 자동화 가능

### 7.2 카테고리별 샘플팩으로 나눌 때
선택값에 따라 다른 메일/링크를 보냅니다.

흐름:
1. 이메일 입력
2. hidden field 또는 선택값 저장
3. `블로그 / 업무 / 개발 / 공통` 중 분기
4. 해당 샘플팩 발송

장점:
- 체감 개인화가 높아짐

주의:
- 실제로 보낼 자산도 카테고리별로 준비돼 있어야 함

## 8. 유료 스타터팩 자동화 설계

### 8.1 가장 단순한 구조
1. 결제 완료
2. 구매자 이메일 확보
3. 스타터팩 PDF / Notion / 가이드 링크 발송

### 8.2 향후 확장 구조
1. 상품 ID 식별
2. 스타터팩인지 딥팩인지 구분
3. 상품별 다른 메일 본문과 링크 발송

## 9. 자동 발송 시스템에 반드시 필요한 운영 값

자동화를 실제로 돌리려면 아래 값이 먼저 정해져 있어야 합니다.

1. 발신 메일 주소
- 예: `hello@`, `support@`, `contact@`

2. 신청 데이터 저장 위치
- Tally 응답
- Google Sheets
- Notion / Airtable / DB

3. 발송 자산 링크
- 샘플팩 PDF
- 샘플팩 Notion
- 스타터팩 PDF
- 스타터팩 Notion
- 사용자 가이드

4. 결제 완료 이벤트를 어디서 받을지
- 외부 결제 플랫폼 webhook
- 수동 검수 후 발송

## 10. 자동화에서 절대 하면 안 되는 것
- 실제 신청/결제가 없는데 완료처럼 보이게 하는 것
- 아직 없는 자료 링크를 메일에 넣는 것
- 운영자가 확인할 수 없는 자동 발송 구조
- 파일 버전이 바뀌는데 링크 관리가 안 되는 구조

## 11. AI시킴에 가장 현실적인 권장안

### 지금 당장
- 공통 샘플팩 1개 자동 발송
- 스타터팩은 구매 후 자동 메일 발송 구조 설계
- 실제 발송 자산은 고정 링크 기반

### 그 다음
- 카테고리별 샘플팩 분기
- 딥팩 상품별 자동 분기
- 운영 메일 시퀀스 고도화

## 12. Claude Code가 필요한 시점
문서만으로 충분한 단계가 아니라 아래가 확정되면 Claude Code가 필요합니다.

1. 실제 폼 도구 확정
2. 실제 발신 메일 도구 확정
3. 실제 발송 링크 확정
4. 결제 완료 이벤트 수신 방식 확정

즉, `운영값이 정해지는 순간`부터 Claude Code가 구현을 맡는 것이 가장 효율적입니다.

## 13. 최종 기준
AI시킴의 자동화는 “AI가 실시간으로 새 콘텐츠를 만들어 보내는 구조”가 아니라,  
“미리 만든 좋은 자산을 적절한 순간에 자동으로 전달하는 구조”여야 합니다.  
좋은 자동화는 신뢰를 높이고, 나쁜 자동화는 오해를 만듭니다.  
따라서 자동화 속도보다 운영 진실성과 링크 정확성이 우선입니다.
