# AI시킴 자동 발송 흐름도 v1

## 1. 문서 목적
이 문서는 AI시킴의 무료 샘플팩과 유료 스타터팩이 어떤 흐름으로 자동 발송되어야 하는지 사용자 관점과 운영 관점으로 나눠 정리한 문서입니다.

## 2. 무료 샘플팩 자동 발송 흐름

### 2.1 사용자 관점
1. 결과 페이지에서 샘플팩 신청 버튼 클릭
2. 이메일 입력
3. 동의 문구 확인
4. 신청 완료
5. 메일 수신
6. PDF 또는 Notion에서 샘플팩 확인

### 2.2 운영 관점
1. 폼 제출 이벤트 발생
2. 제출 데이터 저장
3. 운영자 알림 수신
4. 신청자 메일 자동 발송
5. 발송 로그 확인 가능

### 2.3 발송 메일에 들어가야 할 것
- 왜 이 메일을 받았는지
- 무엇이 들어 있는지
- 무엇부터 써야 하는지
- PDF / Notion 링크
- 다음 단계 안내

## 3. 유료 스타터팩 자동 발송 흐름

### 3.1 사용자 관점
1. 스타터팩 결제 버튼 클릭
2. 외부 결제 완료
3. 구매 완료
4. 구매 후 안내 메일 수신
5. PDF / Notion / 사용 가이드 확인

### 3.2 운영 관점
1. 결제 완료 이벤트 수신
2. 구매 상품 식별
3. 구매자 이메일 확인
4. 구매 후 메일 자동 발송
5. 발송 로그 확인

### 3.3 구매 후 메일에 들어가야 할 것
- 구매 감사
- 받은 자료 목록
- 무엇부터 써야 하는지
- PDF / Notion / 사용 가이드 링크
- 문의 메일 주소

## 4. 카테고리별 분기 가능 구조

### 4.1 무료
- 공통 샘플팩 1개 발송
- 또는 선택 카테고리 기준 분기 발송

### 4.2 유료
- 스타터팩 1개 공통 발송
- 향후 딥팩은 상품 ID에 따라 분기 발송

## 5. 가장 단순한 1차 흐름

### 무료
폼 제출 -> 공통 샘플팩 자동 메일 발송

### 유료
결제 완료 -> 스타터팩 자동 메일 발송

이 구조가 가장 먼저 자동화하기 쉬운 MVP형입니다.

## 6. 2차 고도화 흐름

### 무료
폼 제출 -> 카테고리 식별 -> 카테고리별 샘플팩 자동 발송

### 유료
결제 완료 -> 상품 ID 식별 -> 스타터팩/딥팩별 다른 메일 발송

## 7. 실패 상황 대응 흐름

### 7.1 무료 신청 실패
- 폼 오류
- 메일 발송 실패
- 링크 누락

운영 대응:
1. 운영자 알림 확인
2. 수동 발송
3. 실패 로그 점검

### 7.2 유료 발송 실패
- 결제 완료는 됐지만 메일 미발송
- 구매자 메일 누락
- 링크 오류

운영 대응:
1. 결제 로그 확인
2. 구매자 확인
3. 수동 발송
4. 재발송 구조 점검

## 8. 운영자가 반드시 확인해야 하는 대시보드/저장 위치
자동화가 돌아가더라도 운영자는 아래를 확인할 수 있어야 합니다.

1. 신청된 이메일 목록
2. 발송 성공/실패 여부
3. 어떤 자료가 발송됐는지
4. 어떤 결제가 어떤 구매자에게 연결됐는지

## 9. 지금 당장 결정해야 하는 운영 값
1. 무료 신청 데이터는 어디에 저장할지
2. 자동 발송은 어떤 도구로 보낼지
3. 실제 발신 주소는 무엇인지
4. 스타터팩 결제 완료 이벤트를 어디서 받을지

## 10. 최종 기준
자동 발송 흐름은 사용자가 “신청했으니 자료가 와야 한다”, “결제했으니 바로 받아야 한다”는 기대를 정확히 충족해야 합니다.  
즉, 자동화는 편리함보다 신뢰가 먼저이며, 모든 링크와 상태 문구는 실제와 정확히 일치해야 합니다.
