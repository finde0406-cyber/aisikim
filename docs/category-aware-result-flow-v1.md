# AI시킴 카테고리 분기형 결과·전환 구조 v1

## 1. 문서 목적
이 문서는 사용자가 진단에서 고른 카테고리에 따라 결과 페이지와 유료 전환 구조를 다르게 보여주는 기준을 정리한 문서입니다.

핵심 목적은 아래와 같습니다.
- 고객이 “내 문제에 맞는 추천을 받는다”고 느끼게 합니다.
- 집중팩 3개 모두를 실제 구매 가능한 메인 상품으로 보이게 합니다.
- 번들은 상위 옵션으로 자연스럽게 뒤에 배치합니다.

---

## 2. 왜 카테고리 분기가 필요한가

현재 사용자는 카테고리를 직접 선택합니다.
- 블로그/콘텐츠
- 업무/보고서
- 앱/웹사이트 개발

그런데 결과 페이지와 유료 전환이 모두 동일하게 보이면, 고객은 이렇게 느낄 수 있습니다.
- 내가 개발을 골랐는데 왜 모든 사람에게 똑같은 상품을 보여주지?
- 내 문제를 이해한 것 같지 않다

즉, 선택을 받았으면 전환도 그 선택을 반영해야 합니다.

---

## 3. 기본 구조

### 무료 결과
- 사용자가 선택한 카테고리를 반영한 기본 작업지시서 1개 제공

### 샘플팩
- 무료 다음 단계
- 신뢰 형성

### 메인 유료 전환
- 사용자가 선택한 카테고리에 맞는 `집중팩`

### 상위 옵션
- 통합 스타터팩 50개 번들

즉 구조는 이렇게 고정합니다.

1. 무료 결과
2. 샘플팩
3. 선택한 카테고리의 집중팩
4. 더 넓게 쓰고 싶은 사람을 위한 번들

---

## 4. 카테고리별 메인 전환

### 4.1 블로그/콘텐츠 선택자

#### 결과 페이지 메인 유료 제안
- 블로그/콘텐츠 집중팩

#### 강조 포인트
- 제목
- 도입부
- 구조
- CTA
- 전체 검수

#### 보여줘야 하는 감정
- 글이 막힐 때 계속 이어갈 수 있겠다
- 초안만이 아니라 끝까지 다듬을 수 있겠다

### 4.2 업무/보고서 선택자

#### 결과 페이지 메인 유료 제안
- 업무/보고서 집중팩

#### 강조 포인트
- 보고서
- 요약본
- 실행안
- 이메일
- 회의록

#### 보여줘야 하는 감정
- 상사에게 보여줄 문장을 더 빠르게 만들 수 있겠다
- 실무에 바로 써먹을 수 있겠다

### 4.3 앱/웹사이트 개발 선택자

#### 결과 페이지 메인 유료 제안
- 앱/웹사이트 개발 집중팩

#### 강조 포인트
- 기능 정의
- 요구사항 정리
- 사용자 흐름
- 버그 설명
- 검수

#### 보여줘야 하는 감정
- 개발자에게 말할 때 덜 막히겠다
- 아이디어를 실제 작업지시로 바꿀 수 있겠다

---

## 5. 결과 페이지 UI 원칙

### 5.1 항상 같아야 하는 것
- 무료 결과 1개
- 샘플팩 CTA
- 번들 옵션 존재

### 5.2 바뀌어야 하는 것
- 메인 유료 카드 제목
- 메인 유료 카드 설명
- 메인 CTA 문구
- 번들 앞에 나오는 유료 설득 문장

---

## 6. 카피 예시 방향

### 개발 선택자
- 개발자에게 전달하기 전, 요구사항을 더 명확하게 정리해보세요

### 업무 선택자
- 보고서와 실행안을 더 빠르고 단정하게 정리해보세요

### 콘텐츠 선택자
- 제목부터 초안, CTA까지 더 자연스럽게 이어가보세요

---

## 7. 홈과 결과의 역할 차이

### 홈
- 공통 랜딩
- 서비스 이해
- 무료 작업지시서 생성 시작

### 결과 페이지
- 개인화 전환
- 선택한 분야에 맞는 집중팩 제안

즉, 홈은 모두에게 같아도 되지만 결과는 달라져야 합니다.

---

## 8. 번들의 위치

통합 스타터팩 번들은 항상 아래 역할로 둡니다.
- 여러 분야를 넓게 써보고 싶은 사람용
- 상위 옵션
- 업셀 상품

즉:
- 집중팩을 가리는 메인 상품이 아니라
- 집중팩 이후의 선택지

---

## 9. 최종 판단
AI시킴은 무료 진단에서 이미 카테고리를 묻고 있으므로,  
결과 페이지와 유료 전환도 그 카테고리를 반영하는 것이 맞습니다.

즉:
- 홈은 공통 랜딩
- 결과는 카테고리 분기
- 유료 메인 상품은 선택한 카테고리의 집중팩
- 번들은 그 뒤의 상위 옵션
