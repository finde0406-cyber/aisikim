# AI시킴 카테고리별 PDF 분리 설계 v1

## 1. 문서 목적
이 문서는 현재 통합 스타터팩 50개를 실제 고객 판매용으로 분리할 때, 어떤 방식으로 카테고리별 PDF/Notion 패키지를 만들어야 하는지 정리한 설계 문서입니다.

---

## 2. 기본 원칙
- 고객 판매용은 `통합 1개 PDF`만으로 끝내지 않는다.
- 실제 판매는 `카테고리별 집중팩 PDF + Notion + 사용 가이드`가 기본이다.
- 통합 스타터팩 PDF는 유지하되, 판매 메인 상품이 아니라 번들/상위 상품으로 포지셔닝한다.

---

## 3. 분리 대상

### 3.1 1차 분리 대상
1. 앱/웹사이트 개발 집중팩
2. 업무/보고서 집중팩
3. 블로그/콘텐츠 집중팩

### 3.2 2차 분리 대상
4. 결과물 검수/수정 집중팩
5. 공통 AI 활용/작업설계 집중팩

---

## 4. 각 집중팩 권장 파일 구성

### 4.1 필수 파일
1. PDF 본문 1개
2. Notion 최종 원본 1개
3. 사용 가이드 1개

### 4.2 보조 파일
4. 구매 후 발송 메일 본문
5. 링크 레지스트리용 관리 메모

### 4.3 반응형 품질 필수 조건
- 각 작업지시서는 `변수 슬롯`을 반드시 포함해야 한다.
- 각 작업지시서는 `보정 가이드` 또는 `활용 맥락`을 포함해야 한다.
- 각 작업지시서는 `후속 질문 / 수정 요청 / 검수 요청`까지 이어져야 한다.
- 즉 고객이 “내 상황에 맞게 조절해서 쓸 수 있는 패키지”처럼 느껴야 한다.

---

## 5. PDF 구조 권장안

### 공통 구조
1. 표지
2. 이 집중팩이 어떤 문제를 해결하는지
3. 어떻게 사용하면 좋은지
4. 빠른 시작 가이드
5. 핵심 작업지시서 본문
6. 관련 검수/수정 작업지시서
7. 마지막 활용 팁

### 중요한 점
- 단순히 카테고리 10개만 복사해서 붙이지 않는다.
- 실제 고객은 `내가 무엇부터 꺼내 써야 하는지`를 바로 알아야 한다.
- 따라서 카테고리별로 빠른 시작 순서와 추천 사용 흐름을 붙여야 한다.
- 결과물 형식, AI 도구, 톤 차이를 흡수할 수 있도록 각 항목 안의 반응형 구조가 보여야 한다.

---

## 6. Notion 구조 권장안

### 공통 구조
1. 상단 소개
2. 어떤 사람에게 맞는지
3. 빠른 시작 가이드
4. 작업지시서 목록
5. 각 작업지시서 토글 또는 하위 페이지
6. 마지막 활용 팁

### Notion에서 더 중요한 것
- 복사 편의
- 탐색 속도
- 모바일 읽기

즉 PDF보다 더 짧은 안내와 빠른 이동 구조가 중요하다.

---

## 7. 카테고리별 권장 묶음 방식

### 7.1 앱/웹사이트 개발 집중팩
권장 포함:
- 기능 요구사항을 처음 정리하고 싶을 때
- 사용자 흐름을 화면 단위로 정리하고 싶을 때
- 개발자에게 전달할 작업 지시문을 만들고 싶을 때
- 버그 상황을 더 정확하게 설명하고 싶을 때
- UI 수정 요청을 더 구체적으로 하고 싶을 때
- API 연동 작업을 설명하고 싶을 때
- MVP 범위와 추후 확장 범위를 나누고 싶을 때
- 코드를 직접 짜기 전 구조 제안을 받고 싶을 때
- 이미 나온 코드나 구현안을 개선 요청하고 싶을 때
- 개발 결과물을 최종 검수하고 싶을 때
- 보조: 수정/검수형 2~5개

### 7.2 업무/보고서 집중팩
권장 포함:
- 업무 보고서의 기본 구조를 잡고 싶을 때
- 보고서 목차를 더 설득력 있게 만들고 싶을 때
- 회의록을 실무 문서로 정리하고 싶을 때
- 상사 보고용 요약본을 짧게 만들고 싶을 때
- 기획서 초안을 항목별로 채우고 싶을 때
- 업무 이메일을 더 명확하게 쓰고 싶을 때
- 실행 계획을 체크리스트로 정리하고 싶을 때
- 문제 보고 문서를 더 차분하고 정확하게 쓰고 싶을 때
- 제안서를 읽는 사람이 바로 이해하게 고치고 싶을 때
- 완성된 보고서나 기획서를 최종 검수하고 싶을 때
- 보조: 공통 AI 활용/검수형 2~5개

### 7.3 블로그/콘텐츠 집중팩
권장 포함:
- 블로그 글의 첫 구조를 잡고 싶을 때
- 글 제목 후보를 여러 방향으로 뽑고 싶을 때
- 블로그 도입부를 더 강하게 쓰고 싶을 때
- 소제목 구조를 더 읽기 좋게 정리하고 싶을 때
- 정보형 글을 더 구체적으로 확장하고 싶을 때
- 판매형 콘텐츠 문구를 자연스럽게 녹이고 싶을 때
- 같은 내용을 짧은 SNS용 문구로 바꾸고 싶을 때
- 글 초안을 대상 독자에 맞게 다시 다듬고 싶을 때
- 블로그 글의 마무리와 CTA를 더 좋게 쓰고 싶을 때
- 완성된 글을 전체 검수하고 수정하고 싶을 때
- 보조: 공통 AI 활용/검수형 2~5개

---

## 8. 통합 스타터팩과의 관계

### 통합 스타터팩은 그대로 유지
- 내부 마스터 원본
- 상위 번들 판매 상품
- 집중팩 2개 이상 필요할 때의 업셀 상품

### 고객에게 보여주는 우선순위
1. 내가 지금 필요한 집중팩
2. 샘플팩
3. 통합 스타터팩 번들

즉 보여주는 순서도 바뀌어야 한다.

---

## 9. 최종 판단
실제 판매용 상품성이 높으려면,  
`카테고리별 집중팩 PDF/Notion 패키지`를 먼저 만들고,  
현재의 통합 스타터팩은 번들/상위 상품으로 두는 구조가 더 적절합니다.
