# Claude Code용 홈 압축 · 결과 전환형 UX 개선 프롬프트 v1

```text
AI시킴의 홈/결과 UX 개선 작업을 진행하세요.

중요:
- 이번 작업 목적은 홈을 더 압축하고, 결과 페이지를 더 단계형 전환 구조로 바꾸는 것입니다.
- 사용자 승인 범위는 아래 2가지입니다.
  1. 홈 랜딩페이지 압축 개선
  2. 결과 페이지 전환형 구조 보강
- 사용자 승인 없이 commit/push하지 마세요.
- 작업 전 계획 보고를 남기고, 작업 후에는 handoff 파일을 갱신하세요.

반드시 먼저 확인할 파일:
- docs/home-compression-result-flow-v1.md
- docs/user-flow.md
- docs/conversion-copy-principles-v1.md
- docs/customer-product-architecture-v1.md
- docs/handoffs/project-status.md
- docs/handoffs/codex-latest-review.md
- AGENTS.md
- CLAUDE.md

배경:
현재 홈은 많이 좋아졌지만 여전히 아래 섹션을 다 읽기보다, 첫 화면에서 행동 여부가 결정될 가능성이 큽니다.
AI시킴은 설명형 랜딩보다 “눌러보게 만드는 랜딩”이 더 중요합니다.
반대로 결과 페이지는 더 분명한 다음 단계 선택 흐름으로 바꾸는 것이 전환에 유리합니다.

이번 작업 목표:
1. 홈은 더 짧고 강하게
2. 결과 페이지는 더 단계적으로
3. 샘플팩 → 집중팩 → 번들 흐름을 더 자연스럽게

작업 방향 1: 홈 랜딩페이지
- 홈은 설명 페이지보다 진입 페이지여야 합니다.
- 핵심 메시지 + 신뢰 보강 + 메인 CTA 중심으로 더 압축하세요.
- 아래 섹션은 줄이거나 묶어서 정보 밀도를 낮추세요.
- CTA 반복은 최소화하고 각 CTA의 역할을 더 분명히 하세요.

가능한 방향 예시:
- Hero 유지
- 문제 공감 섹션은 짧게 유지
- 사용 방법 / 카테고리 / 집중팩 흐름 중 일부는 축약 또는 병합 검토
- 샘플 미리보기와 유료 구조는 남기되 더 짧고 강하게

작업 방향 2: 결과 페이지
- 결과 페이지를 “정보 나열”보다 “다음 단계 선택 화면”처럼 보이게 개선하세요.
- 추천 흐름:
  1. 지금 만든 작업지시서 확인
  2. 복사해서 써보기
  3. 샘플팩 5개 더 받아보기
  4. 내 분야 집중팩 보기
  5. 더 넓게 쓰고 싶다면 번들 보기

- 샘플팩 CTA는 가장 먼저
- 집중팩 CTA는 메인 유료 전환
- 번들은 상위 옵션으로 뒤에

주의:
- 홈 전체를 앱처럼 멀티 스텝으로 바꾸지 마세요.
- 대신 결과 이후 흐름을 더 단계형으로 만드는 쪽을 우선하세요.
- 기존 고객-facing 카피 톤(`-요`체)은 유지하세요.
- 내부 개발 상태 문구는 계속 숨기세요.

수정 가능 파일 예시:
- app/page.tsx
- app/result/page.tsx
- components/home/*
- components/result/*

작업 전 먼저 보고할 것:
## 현재 저장소 확인 결과
## 이해한 개선 목표
## 수정 예정 파일
## 홈 압축 방식
## 결과 페이지 단계형 전환 방식
## 리스크 또는 확인사항

작업 후 반드시 할 것:
1. docs/handoffs/claude-latest-report.md 갱신
2. docs/handoffs/project-status.md 갱신
3. 변경 파일 목록과 git status만 간단히 보고
4. commit/push는 하지 않음
```
