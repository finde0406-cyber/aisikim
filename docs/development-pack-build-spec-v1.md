# AI시킴 앱/웹사이트 개발 집중팩 제작 기준 v1

## 1. 문서 목적
이 문서는 초기 메인 판매 상품으로 가장 적합한 `앱/웹사이트 개발 집중팩`을 실제 고객 판매용으로 제작할 때 필요한 기준을 정리한 문서입니다.

---

## 2. 왜 개발 집중팩이 첫 상품에 적합한가
- 문제 강도가 선명하다
- 비개발자/기획자/사이드프로젝트 사용자에게 직접적인 고통이 있다
- 무료 결과와 유료팩의 차이를 보여주기 쉽다
- “어떻게 요청하지?”라는 문제는 지불 의사가 생기기 쉽다

---

## 3. 이 집중팩의 핵심 약속
이 상품은 “AI로 개발을 대신해준다”가 아니라,
`개발과 관련된 요청·정리·전달·검수를 훨씬 잘하게 도와주는 패키지`
여야 한다.

즉 고객이 느껴야 하는 핵심은 아래다.
- 개발자에게 말이 훨씬 잘 정리된다
- 기능 정의가 더 선명해진다
- 화면 흐름과 예외 상황을 더 잘 설명하게 된다
- 개발 결과물 검수 질문도 훨씬 좋아진다

---

## 4. 권장 본문 구성

### 4.1 핵심 10개
1. 기능 요구사항을 처음 정리하고 싶을 때
2. 사용자 흐름을 화면 단위로 정리하고 싶을 때
3. 개발자에게 전달할 작업 지시문을 만들고 싶을 때
4. 버그 상황을 더 정확하게 설명하고 싶을 때
5. UI 수정 요청을 더 구체적으로 하고 싶을 때
6. API 연동 작업을 설명하고 싶을 때
7. MVP 범위와 추후 확장 범위를 나누고 싶을 때
8. 코드를 직접 짜기 전 구조 제안을 받고 싶을 때
9. 이미 나온 코드나 구현안을 개선 요청하고 싶을 때
10. 개발 결과물을 최종 검수하고 싶을 때

### 4.2 보조 5개
- 빠진 핵심 요소가 있는지 점검하고 싶을 때
- 수정 요청을 어떻게 이어갈지 설계하고 싶을 때
- 검수 질문을 어떻게 던질지 정리하고 싶을 때
- 같은 작업을 다른 AI 도구에 맞게 바꾸고 싶을 때
- 전체 작업 흐름을 한 번에 설계하고 싶을 때

즉 이 집중팩은 `핵심 10 + 보조 5` 구조가 가장 상품성이 높다.

---

## 5. 변수 반응형 기준

### 5.1 반드시 흡수해야 하는 변수
- 현재 막힌 부분
- 원하는 결과물 형식
- 사용할 AI 도구
- 원하는 톤/스타일

### 5.2 집중팩 안에서의 처리 방식
- 각 작업지시서에 변수 슬롯을 둔다
- 결과물 형식별 보정 가이드를 붙인다
- AI 도구 변경 시 보정 문구를 넣는다
- 후속 질문/수정 요청/검수 요청까지 함께 제공한다

### 5.3 고객이 받아야 하는 느낌
- 개발만 필요한 사람에게는 이 한 팩으로 충분히 여러 상황을 커버할 수 있다
- 내가 어떤 결과물을 원하느냐에 따라 응용할 수 있다
- 단순 복붙 자료가 아니라 실제 전달 도구 같다

## 8. 판매 문구 방향

### 좋은 방향
- 개발을 몰라도 개발자에게 더 정확하게 요청할 수 있게 도와주는 작업지시서
- 기능 정의부터 검수까지 실제 개발 커뮤니케이션 흐름을 정리해주는 패키지
- 막연한 아이디어를 바로 전달 가능한 문장으로 바꿔주는 실전팩

### 피해야 하는 방향
- AI가 앱을 대신 만들어준다
- 개발을 몰라도 모든 걸 자동으로 해결한다
- 복붙하면 바로 완성된다

---

## 9. 최종 기준
앱/웹사이트 개발 집중팩은 단순히 `개발용 작업지시서 10개`가 아니라,
`개발 관련 커뮤니케이션과 기획 전달을 훨씬 잘하게 만드는 반응형 실전팩`
처럼 느껴져야 한다.

이 수준이 되어야 첫 유료 상품으로 내놓아도 논란이 적고, 구매자가 “돈값 한다”고 느낄 가능성이 높다.
