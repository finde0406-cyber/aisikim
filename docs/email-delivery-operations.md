# AI시킴 이메일 발송 운영 구조

## 1. 문서 목적
이 문서는 AI시킴의 샘플팩 이메일 발송 구조와 운영 원칙을 정의합니다.  
이메일 수집 UI만 있는 상태가 아니라, 사용자가 실제로 어떤 메일을 받고 어떤 경험을 하게 되는지까지 기준을 정리합니다.

## 2. 핵심 원칙
### 2.1 신청 완료처럼 속이면 안 된다
- 실제 수집이나 발송이 되지 않는데 "접수 완료"처럼 보이면 안 된다.
- 외부 폼 URL이나 발송 구조가 없으면 준비 중 상태를 명확히 보여줘야 한다.

### 2.2 메일은 파일 전달만 하면 안 된다
- 샘플팩 링크나 PDF만 던지고 끝내면 신뢰가 약하다.
- 짧은 사용 가이드와 다음 행동 제안까지 함께 제공해야 한다.

### 2.3 판매 메일보다 신뢰 메일이 먼저다
- 첫 메일은 판매보다 사용 경험과 만족도를 우선해야 한다.
- "이걸 바로 써보니 좋다"가 먼저 나오고, 그 다음 스타터팩 소개가 와야 한다.

## 3. 사용자 흐름
1. 결과 페이지에서 샘플팩 신청
2. 이메일 입력 및 동의
3. 실제 수집 성공
4. 샘플팩 발송 메일 수신
5. 샘플팩 사용
6. 교육형 메일 3~5개 수신
7. 유료 스타터팩 안내
8. 이후 딥팩 또는 추가 상품 안내

## 4. 결과 페이지 신청 상태 기준
### 4.1 연결 전
- "신청이 접수되었습니다" 문구 사용 금지
- "아직 신청 연결 준비 중입니다" 또는 "외부 폼 연결 후 이용 가능합니다"처럼 명확히 안내

### 4.2 연결 후
- 실제 외부 폼 제출 또는 저장이 일어난 뒤에만 완료 문구 노출
- 사용자가 입력을 마친 후 어떤 일이 일어나는지 안내

### 4.3 완료 상태 문구 기준
- 입력하신 이메일로 샘플팩을 보내드립니다
- 발송 예상 시간 안내
- 바로 다음 행동 제안

## 5. 샘플팩 발송 메일 구조
### 5.1 제목 예시
[AI시킴] 요청하신 무료 작업지시서 샘플팩 5개를 보내드립니다

### 5.2 본문 구조
1. 신청 감사
2. 이 메일에 무엇이 들어있는지 설명
3. 샘플팩 링크 또는 첨부 안내
4. 어떻게 활용하면 좋은지
5. 샘플팩 5개 간단 소개
6. 다음 단계 안내
7. 수신 거부 안내

### 5.3 본문 예시 흐름
- 신청해주셔서 감사합니다.
- 이 메일에는 바로 복사해서 쓸 수 있는 작업지시서 샘플 5개가 들어 있습니다.
- 먼저 한 개만 복사해서 써보셔도 되고, 지금 막힌 작업과 가장 가까운 항목부터 써보셔도 됩니다.
- 각 샘플은 사용 상황, 기본 작업지시서, 후속 질문 예시까지 함께 구성되어 있습니다.
- 더 완성된 흐름이 필요하다면 스타터팩에서 후속 질문, 수정 요청, 검수 요청까지 이어지는 전체 구조를 확인하실 수 있습니다.

## 6. 샘플팩 메일에 반드시 포함할 요소
1. 왜 이 메일을 받는지
2. 샘플팩 접근 방법
3. 샘플팩을 어디부터 써보면 좋은지
4. 각 작업지시서를 내 상황에 맞게 바꾸는 간단한 팁
5. 유료 상품과의 차이 한 줄
6. 수신 거부 안내

## 7. 샘플팩 제공 방식
### 7.1 권장 방식
- 이메일 본문 + PDF 링크
- 이메일 본문 + Notion 링크
- 이메일 본문 + PDF 첨부 + Notion 보조 링크

### 7.2 권장 이유
- PDF는 저장과 전달이 쉽다.
- Notion은 복사와 탐색이 쉽다.
- 둘을 함께 주면 사용성과 신뢰가 높아진다.

## 8. 유료 스타터팩 안내 메일 구조
### 8.1 보내는 시점
- 샘플팩 발송 직후 즉시 판매하지 않는다.
- 최소 1~2번의 교육형 메일 또는 사용 유도 메일 뒤에 안내하는 것이 좋다.

### 8.2 제목 예시
[AI시킴] 기본 작업지시서에서 끝나지 않도록, 전체 흐름 50개를 준비했습니다

### 8.3 본문 핵심
1. 샘플팩을 먼저 써봤는지 상기
2. 왜 무료 결과와 샘플만으로는 부족할 수 있는지 설명
3. 스타터팩은 입문용 유료 상품이라는 점 설명
4. 50개 구성 요약
5. PDF + Notion 제공 방식
6. 구매 링크

## 9. 교육형 메일 시퀀스 운영 원칙
### 9.1 목적
- 단순 판매가 아니라 사용 습관 형성
- 작업지시서의 가치 이해
- 유료 전환 전 신뢰 확보

### 9.2 권장 순서
1. 작업 단위로 시켜야 하는 이유
2. 결과가 뻔할 때 바꾸는 방법
3. 후속 질문의 중요성
4. 실제 카테고리별 예시
5. 스타터팩 안내

## 10. 운영 체크리스트
- 외부 폼 연결 여부 확인
- 신청 완료 문구가 실제 상태와 맞는지 확인
- 발송 메일 템플릿 준비
- PDF/Notion 링크 정상 동작 확인
- 수신 거부 문구 포함 여부 확인
- 발송 후 다음 메일 일정 정리

## 11. 최종 기준
AI시킴의 이메일은 단순한 리드 수집 수단이 아니라, 사용자가 "이 서비스는 믿을 만하다"라고 느끼게 만드는 핵심 접점입니다.  
따라서 신청 UI, 발송 메일, 샘플팩 구성, 유료 전환 메일까지 모두 하나의 사용자 경험으로 설계해야 합니다.
