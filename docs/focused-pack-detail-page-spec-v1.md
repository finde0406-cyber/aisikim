# AI시킴 집중팩 상세 페이지 보강 기준 v1

## 1. 문서 목적
이 문서는 개발/업무/콘텐츠 3개 집중팩 상세 페이지를 실제 판매 가능한 수준으로 만들기 위한 기준을 정리한 문서입니다.

핵심 원칙은 단순합니다.
- 집중팩은 각기 다른 문제를 해결하는 상품처럼 느껴져야 합니다.
- 상세 페이지도 서로 다른 설득 포인트를 가져야 합니다.
- 고객이 “이건 내 문제를 위한 페이지다”라고 느껴야 합니다.

---

## 2. 공통 구조

각 집중팩 상세 페이지는 아래 순서를 기본으로 합니다.

1. 헤드라인
2. 이 상품이 필요한 문제 상황
3. 포함 구성
4. 첫 질문·후속 질문·수정 요청·검수 질문 흐름 설명
5. 실제 예시 미리보기
6. 무료와 유료 차이
7. FAQ
8. 구매 CTA

---

## 3. 카테고리별 설득 포인트

### 3.1 앱/웹사이트 개발 집중팩

#### 헤드라인 방향
- 개발을 몰라도 기능 요청을 더 명확하게 정리할 수 있어요

#### 고객이 보고 안심해야 하는 것
- 내가 개발자가 아니어도 괜찮다
- 기획이 정리되지 않아도 시작할 수 있다
- 개발자와의 대화가 덜 막히겠다

#### 강조해야 할 구성
- 기능 정의
- 화면 흐름
- 요구사항 정리
- API 연동 설명
- 버그 설명
- 최종 검수

### 3.2 업무/보고서 집중팩

#### 헤드라인 방향
- 보고서, 실행안, 이메일을 더 빠르고 단정하게 정리할 수 있어요

#### 고객이 보고 안심해야 하는 것
- 실무에 바로 붙일 수 있겠다
- 보고용 문체가 어색하지 않겠다
- 시간을 절약할 수 있겠다

#### 강조해야 할 구성
- 보고서 초안
- 요약본
- 실행안
- 체크리스트
- 이메일
- 회의록 정리

### 3.3 블로그/콘텐츠 집중팩

#### 헤드라인 방향
- 제목부터 초안, CTA까지 한 흐름으로 이어갈 수 있어요

#### 고객이 보고 안심해야 하는 것
- 첫 문장 막힘을 줄일 수 있겠다
- 초안만이 아니라 마무리까지 갈 수 있겠다
- 콘텐츠를 실제 게시 수준으로 다듬을 수 있겠다

#### 강조해야 할 구성
- 제목 후보
- 도입부
- 구조 잡기
- 본문 확장
- 판매형 문구
- 최종 검수

## 4. 페이지별 차별화 포인트

### 잘못된 상태
- 3개 상세 페이지가 제목만 다르고 사실상 같은 구조와 같은 설득 문장으로 보입니다.

### 좋은 상태
- 개발 페이지는 `전달/정리/구조`
- 업무 페이지는 `보고/요약/실무`
- 콘텐츠 페이지는 `초안/전개/완성`
을 더 강하게 느끼게 합니다.

즉, 같은 틀을 쓰더라도 핵심 문장과 예시가 달라야 합니다.

---

## 5. 실제 예시 섹션 기준

각 집중팩 상세 페이지에는 해당 분야 대표 예시가 들어가야 합니다.

### 개발
- 기능 정의 요청 예시

### 업무
- 보고서 초안 예시

### 콘텐츠
- 글 초안 예시

이 예시는 고객이 “이걸 사면 대충 이런 식으로 받는구나”를 이해하게 해주는 역할을 합니다.

---

## 6. 최종 판단
집중팩을 모두 높은 수준으로 판매하려면,  
상세 페이지 역시 각 분야의 통증과 해결 방식이 다르게 느껴져야 합니다.

즉:
- 홈은 공통
- 결과 페이지는 카테고리 분기
- 상세 페이지는 각 분야별 설득에 맞게 차별화
