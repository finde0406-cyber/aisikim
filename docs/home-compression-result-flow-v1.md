# AI시킴 홈 압축 · 결과 전환형 UX 개선안 v1

## 1. 문서 목적
이 문서는 현재 AI시킴의 홈 랜딩페이지와 결과 페이지를 다시 점검해,  
`홈은 더 짧고 강하게`, `결과 이후는 더 단계적으로` 만드는 UX 개선 방향을 정리한 문서입니다.

핵심 목적은 아래 2가지입니다.
- 홈에서 사용자가 너무 오래 읽지 않아도 바로 행동하게 만들기
- 결과 페이지 이후 전환을 한 단계씩 자연스럽게 이어가게 만들기

---

## 2. 기본 판단

### 2.1 홈은 다 읽히지 않는다
모바일 사용자는 대부분 아래 순서로 움직입니다.
1. 첫 화면 메시지 확인
2. CTA 확인
3. 신뢰할 만한지 짧게 판단
4. 바로 누르거나 이탈

즉, 홈의 아래 섹션은 “다 읽히기 위한 콘텐츠”가 아니라  
`CTA를 눌러도 되겠다`는 신뢰를 보강하는 장치로 보는 것이 맞습니다.

### 2.2 지금 메인 홈은 이미 좋아졌지만, 더 압축할 여지가 있다
현재 구조는 예전보다 훨씬 나아졌지만, 여전히 아래와 같은 개선 여지가 있습니다.
- 위쪽 CTA가 이미 강한 만큼 아래 반복 섹션은 더 짧아질 수 있음
- 첫 화면에서 거의 승부가 나므로, 아래는 “보조 설득” 역할로 더 선명해져야 함
- 홈 전체를 앱처럼 만들 필요는 없지만, `한 번 눌러보고 싶게 하는 페이지`라는 정체성은 더 강해질 수 있음

### 2.3 앱형 UX는 홈보다 결과 이후에 더 잘 맞는다
홈 전체를 멀티 스텝 앱처럼 만드는 것은 조심해야 합니다.
대신 아래 구간은 더 단계형 흐름으로 바꾸는 것이 유리합니다.
- 결과 확인
- 샘플팩 받기
- 집중팩 보기
- 통합 번들 보기

즉, 홈은 `압축형 랜딩`, 결과는 `전환형 플로우`가 더 적합합니다.

---

## 3. 추천 UX 원칙

### 3.1 홈
- 첫 화면에서 거의 승부를 본다
- 메시지, 신뢰, CTA를 1~2스크롤 안에 끝낸다
- 아래 섹션은 보조 설득용으로 짧게 둔다
- 반복 CTA는 최소화하고 역할을 분리한다

### 3.2 퀴즈
- 지금처럼 자동 전환형 유지
- 마찰을 줄이고 수정은 뒤로 가기로 처리

### 3.3 결과 페이지
- 단순 정보 나열보다 `다음 단계`를 선택하게 만드는 화면으로 설계
- 무료 결과 확인 → 샘플팩 → 집중팩 → 번들 순으로 자연스럽게 이동

---

## 4. 홈 개선 방향

### 4.1 유지해야 하는 것
- 강한 Hero 메시지
- 무료 작업지시서 만들기 CTA
- 작업지시서 샘플 미리보기
- 집중팩/번들 구분

### 4.2 줄여도 되는 것
- 홈 하단 반복 안내
- 설명이 겹치는 섹션
- 비슷한 CTA의 반복

### 4.3 남기는 것이 좋은 섹션
아래 4개 정도가 핵심입니다.
1. Hero
2. 문제 공감
3. 작업지시서 샘플 미리보기
4. 유료 구조 요약

보조로 아래 중 일부만 유지 가능합니다.
- 사용 방법
- 카테고리 미리보기
- 집중팩 흐름 설명

즉, 홈은 앞으로 `설명형 랜딩`보다 `빠른 진입형 랜딩` 쪽으로 더 기울어야 합니다.

---

## 5. 결과 페이지 개선 방향

### 5.1 현재 결과 페이지의 역할
현재 결과 페이지는:
- 무료 결과를 보여준다
- 샘플팩 CTA를 준다
- 유료 전환으로 이어지게 한다

이 역할 자체는 맞습니다. 다만 앞으로는 더 명확하게
`다음 단계`를 밟게 만드는 플로우 페이지처럼 느껴지게 할 수 있습니다.

### 5.2 추천 단계 구조
1. 지금 만든 작업지시서 확인
2. 복사해서 바로 써보기
3. 샘플팩 5개 더 받아보기
4. 내 분야 집중팩 보기
5. 더 넓게 쓰고 싶다면 번들 보기

즉, 결과 페이지는 한 번에 모든 정보를 설명하는 곳보다  
`다음 행동을 고르게 만드는 단계형 화면`으로 바뀌는 것이 더 좋습니다.

### 5.3 고객이 느껴야 하는 감정
- 지금 결과만으로도 꽤 괜찮다
- 그런데 다음 것도 좀 더 보고 싶다
- 샘플팩을 받아보면 더 확신이 생길 것 같다
- 내 분야 집중팩이면 돈 내볼 만하다

---

## 6. 추천 구조 요약

### 홈
- 짧고 강하다
- CTA가 빠르다
- 신뢰는 짧게 보강한다

### 결과
- 다음 단계가 분명하다
- 샘플팩이 먼저 보인다
- 집중팩이 메인 유료로 보인다
- 번들은 상위 옵션으로 뒤에 보인다

---

## 7. 구현 우선순위 제안
1. 홈 섹션 압축
2. 결과 페이지를 단계형 전환 구조로 재배치
3. 샘플팩 → 집중팩 → 번들 흐름 강화
4. 운영값 연결 이후 실제 전환 테스트

---

## 8. 최종 판단
홈은 전부 읽히는 페이지가 아니라,  
`무료 작업지시서를 한 번 만들어보고 싶게 만드는 페이지`
여야 합니다.

결과 페이지는 정보를 한꺼번에 보여주는 곳이 아니라,  
`지금 결과 → 다음 단계 → 유료 전환`
으로 자연스럽게 이어지는 단계형 화면이 되어야 합니다.

즉 AI시킴은:
- 홈은 더 압축하고
- 결과 이후는 더 플로우형으로
가장 잘 작동할 가능성이 높습니다.
