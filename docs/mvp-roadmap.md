# AI시킴 MVP 로드맵

## 1. 문서 목적
이 문서는 문서 단계부터 판매 실험 단계까지의 MVP 진행 순서를 스프린트 단위로 정리합니다.

## 2. Sprint 0 문서 세팅
### 목표
- 기준 문서 확정
- 에이전트 작업 규칙 확정
- MVP 범위와 제외 범위 고정

### 산출물
- PRD v1.0
- 사업기획서 v1.0
- 수익 모델, 사용자 흐름, 결제 전략, 이메일 퍼널 문서
- AGENTS.md, CLAUDE.md

## 3. Sprint 1 랜딩페이지
### 목표
- 홈 메시지와 CTA 구조 확정
- 모바일 우선 정보 구조 설계

### 핵심 작업
- 헤드라인
- 문제 공감 섹션
- 서비스 설명 섹션
- 무료 진단 CTA
- 유료 스타터팩 예고

## 4. Sprint 2 선택형 진단
### 목표
- 질문 흐름 완성
- 선택지 설계
- 초기 MVP 카테고리 3개 기준으로 결과물 매핑 논리 정리

### 핵심 작업
- 질문 5개 화면 구조
- 초기 노출 카테고리 3개 확정
- 선택 상태 관리 방식 설계
- 결과 생성 규칙 정의

## 5. Sprint 3 결과 페이지
### 목표
- 무료 결과 1개를 명확하게 제시
- 유료와의 차이를 자연스럽게 설명

### 핵심 작업
- 기본 작업지시서 노출
- 복사 CTA
- 샘플팩 CTA
- 스타터팩 CTA

## 6. Sprint 4 이메일 수집
### 목표
- 이메일 입력 흐름 설계
- 동의 문구 확정
- 샘플팩 전달 방식 연결

### 핵심 작업
- 폼 설계
- 필수/선택 동의 구조
- 발송 안내 문구

## 7. Sprint 5 유료 상품 페이지
### 목표
- 스타터팩의 구성과 필요성을 설득력 있게 설명

### 핵심 작업
- 상품 소개
- 무료와 유료 차이 비교
- 구성 목록
- 자료 제공 방식
- FAQ 및 고지문

## 8. Sprint 6 결제 링크 연결
### 목표
- 외부 결제 링크 방식 중 MVP 우선안을 적용
- 구매 후 자료 수령 흐름 확정

### 핵심 작업
- Tally 또는 간단한 신청폼 + 수동 안내/수동 발송 우선안 반영
- 실제 결제 채널 비교 결과 반영
- 구매 버튼 연결
- 결제 후 PDF + Notion 보조 링크 안내 문구 작성

## 9. Sprint 7 배포/테스트
### 목표
- 모바일 환경 기준 품질 점검
- 링크, 폼, 고지문, CTA 동작 점검

### 핵심 작업
- Vercel 배포 준비
- 모바일 브라우저 확인
- 이메일 폼 확인
- 결제 링크 확인

## 10. Sprint 8 판매 실험
### 목표
- 첫 유입 확보
- 첫 유료 판매 검증

### 핵심 작업
- 유입 채널 운영
- 메시지 테스트
- 전환 데이터 수집
- 개선 우선순위 정리

## 11. 운영 원칙
- 각 스프린트는 이전 문서 기준을 깨지 않는 범위에서만 진행
- 기능 추가보다 메시지와 전환 구조 검증 우선
- 자동화보다 빠른 검증 우선
