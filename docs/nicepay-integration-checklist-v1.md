# AI시킴 나이스페이 결제 연동 준비 체크리스트 v1

## 1. 목표

AI시킴에서 사용자가 바이브코딩 웹서비스 출시 작업지시서팩을 결제하면, 결제 성공 여부를 서버에서 확인하고 구매자가 입력한 이메일로 PDF 자료를 자동 발송한다.

최종 흐름은 다음과 같다.

`상품 페이지 -> 결제창 -> 나이스페이 인증 -> 서버 승인 -> 금액·상품 검증 -> 결제 완료 메일과 PDF 발송`

## 2. 나이스페이 화면에서 먼저 할 일

### 2.1 KEY 정보

개발정보 화면의 `KEY 정보`에서 테스트용 KEY를 발급한다.

필요한 값:

- MID 또는 상점 ID
- Merchant Key 또는 상점 키
- 테스트/운영 환경 구분
- 사용할 결제수단

Merchant Key는 채팅창, 문서, GitHub, 화면 캡처에 보내지 않는다. 로컬 `.env.local`과 Vercel 환경변수에 직접 입력한다.

### 2.2 웹훅 URL

나이스페이가 비동기 결제 상태를 통보할 서버 주소를 등록한다.

예정 경로:

`https://aisikim.com/api/payment-webhook`

카드 결제만 먼저 사용할 경우에는 서버 승인 응답으로 결제 성공을 확인할 수 있으므로 웹훅을 먼저 등록할 필요가 없다. 가상계좌처럼 입금 시점이 나중에 확정되는 결제수단을 사용할 때 웹훅을 추가한다.

이 주소는 실제 나이스페이 통보 payload와 검증 코드를 반영한 뒤 등록한다. 지금 코드의 웹훅은 임시 공통 형식이라 바로 등록하면 안 된다.

### 2.3 IP 보안

개발정보 화면의 `IP보안(REST API 접근제한)`은 서버에서 나이스페이 승인 API를 호출할 때 확인할 항목이다.

주의할 점:

- 집이나 개인 PC의 IP를 등록하지 않는다.
- Vercel 서버리스의 외부 호출 IP가 고정되는지 먼저 확인한다.
- 고정 IP가 필요하다면 나이스페이에 Vercel 환경 사용 가능 여부를 문의하거나 고정 출구 IP를 제공하는 별도 서버 구조를 검토한다.
- 테스트 단계에서는 IP 제한 정책을 먼저 확인하고, 운영 전 승인 API 호출이 차단되지 않는지 검증한다.

## 3. 우리에게 필요한 상품 정보

나이스페이 상점 설정과 주문 검증에 아래 값을 고정해야 한다.

- 상품명: `바이브코딩 웹서비스 출시 작업지시서팩`
- 가격: `9,900원`
- 상품 코드: `dev`
- 제공 자료: PDF
- 결제 완료 후 발송 이메일: 구매자가 결제창에 입력한 이메일
- 환불 안내: 디지털 상품 안내 문구와 이용약관 링크

상품명과 가격이 페이지, 결제창, 서버 검증, 이메일에서 다르면 결제 후 발송을 중단하도록 설계한다.

## 4. 웹사이트에서 필요한 URL

운영 도메인에 HTTPS가 적용되어 있어야 한다.

- 결제 요청 페이지: `https://aisikim.com/focused-pack/dev`
- 결제 인증 결과 수신 URL: 별도 서버 route 예정
- 결제 완료 페이지: 별도 결과 화면 또는 판매 페이지 복귀 경로 예정
- 결제 통보 URL: `https://aisikim.com/api/payment-webhook`
- 이용약관: `https://aisikim.com/legal/terms`
- 개인정보처리방침: `https://aisikim.com/legal/privacy`

결제 인증 결과 수신 URL과 결제 통보 URL은 같은 역할이 아닐 수 있으므로 나이스페이 상품 유형과 결제 방식에 맞춰 분리한다.

## 5. 구매자에게 받을 값

현재 임시 흐름에서는 이름·이메일·연락처를 받고 있다. 나이스페이 연동 시 아래 값을 결제 요청과 동일하게 연결한다.

- 구매자 이름
- 구매자 이메일
- 구매자 연락처
- 상품 코드
- 주문번호
- 결제 금액

이메일은 PDF 발송에 반드시 필요하다. 이름과 연락처는 나이스페이 결제 요청에 필요한 범위를 확인한 뒤 최소한으로 유지한다.

## 6. 서버에서 구현할 검증

결제 성공 화면만 보고 자료를 발송하지 않는다. 서버에서 다음 순서로 검증한다.

1. 인증 결과 코드가 성공인지 확인
2. 인증 응답의 금액과 상품 정보를 확인
3. 서버에서 나이스페이 승인 API 호출
4. 승인 응답의 결과 코드 확인
5. 승인 응답 Signature 검증
6. 주문번호 중복 발송 방지
7. 구매자 이메일로 PDF 발송
8. 관리자에게 결제와 발송 결과 알림

나이스페이 공식 문서상 인증 후 가맹점 서버에서 승인 API를 호출하고, 승인 결과의 Signature를 검증해야 한다.

공식 문서:

- 인증결제: https://developers.nicepay.co.kr/manual-auth.php
- 결제통보: https://developers.nicepay.co.kr/manual-noti.php
- 예외 및 위변조 검증: https://developers.nicepay.co.kr/manual-exception.php

## 7. 필요한 환경변수

```text
NICEPAY_MID=
NICEPAY_MERCHANT_KEY=
NICEPAY_ENV=test
NICEPAY_RETURN_URL=https://aisikim.com/api/payments/nicepay/return
NICEPAY_WEBHOOK_URL=https://aisikim.com/api/payment-webhook

DEV_PACK_PDF_URL=https://aisikim.com/downloads/aisikim-vibecoding-launch-pack-v2.pdf
MAIL_PROVIDER=resend
RESEND_API_KEY=
MAIL_FROM=hello@aisikim.com
ADMIN_NOTIFY_EMAIL=hello@aisikim.com
```

실제 변수명은 구현 단계에서 현재 프로젝트 규칙과 맞춰 확정한다. Merchant Key와 Resend API Key는 사용자에게 전달받지 않고 사용자가 직접 환경변수에 넣는 방식으로 진행한다.

## 8. 사용자에게 필요한 준비물

사용자가 준비해서 알려주면 되는 것은 아래와 같다.

- 나이스페이 테스트 상점 가입 여부
- MID를 확인했는지
- 테스트 결제를 사용할 수 있는 상태인지
- 사용할 결제수단: 카드만 우선할지, 계좌이체 등을 포함할지
- 운영 도메인과 HTTPS 상태
- PDF를 실제로 제공할 공개 URL을 사용할지 여부

알려주면 안 되는 것:

- Merchant Key 원문
- 결제 관련 비밀번호
- 관리자 계정 비밀번호
- Resend API Key

## 9. 구현 전 최종 확인

- 상품명과 가격이 최종 확정되었는가
- PDF 최종본이 준비되었는가
- 판매 페이지의 제공 방식 문구가 실제 자동 발송 방식과 일치하는가
- 결제 성공과 이메일 발송 실패를 따로 처리하는가
- 동일 주문의 중복 발송을 막는가
- 테스트 결제와 취소 테스트가 가능한가

## 10. 현재 결론

지금은 나이스페이 KEY 발급까지 완료된 상태다. 첫 출시를 카드 결제로 제한하면 IP 보안과 웹훅은 잠시 보류하고, 먼저 MID와 테스트 결제 상태를 확인한 뒤 결제창·서버 승인·자동 메일 발송을 구현한다. 가상계좌를 추가할 때 웹훅을 별도로 연결한다.

## 11. 임시오픈 테스트 주의사항

나이스페이 담당자 답변 기준으로 임시오픈 기간에도 연동과 테스트 결제가 가능하다.

- 결제 테스트 후 취소가 필요하면 반드시 결제일 자정 전 취소한다.
- 자정 이후에는 PG 수수료를 제외한 정산 데이터가 반영되어 취소가 불가능할 수 있다.
- 테스트는 평일 낮 시간에 진행하고, 결제 직후 승인 결과와 자동 발송을 확인한 뒤 바로 취소한다.
- 테스트 결제 전에 운영자가 취소할 거래의 주문번호와 결제 시각을 기록한다.
- 실제 판매를 시작하기 전에는 임시오픈 테스트와 운영 승인 상태를 분리해 확인한다.

## 12. 포스타트 결제경로 제출 기준

나이스페이 포스타트에서 받은 `(예시)인증_정기과금_결제경로.pptx` 기준으로, AI시킴은 정기과금이 아닌 단건 결제 상품이므로 단건 결제 경로만 제출한다. 예시 파일의 정기과금 경로는 제출 대상에서 제외한다.

제출용 단건 결제 경로에는 아래 화면을 순서대로 포함한다.

1. 홈페이지 하단 정보: 상호, 대표자명, 사업자번호, 주소, 전화번호, 이메일, 통신판매신고번호, 이용약관, 개인정보처리방침
2. 홈페이지 URL
3. 로그인 페이지 또는 비회원 결제 가능 여부
4. 상품 목록 또는 상품 상세 페이지
5. 결제수단에서 신용카드를 선택하는 화면
6. 결제모듈 화면

AI시킴에서 우선 준비할 캡처는 다음과 같다.

- `https://aisikim.com` 첫 화면
- 바이브코딩 웹서비스 출시 작업지시서팩 상품 상세 및 가격 화면
- 구매자 이메일 입력 화면
- 결제 버튼을 누르기 직전 화면
- 나이스페이 결제창에서 신용카드를 선택한 화면
- 결제 완료 화면

로그인 기능이 없으므로 로그인 화면은 만들지 않는다. 상품은 실제 판매 상품으로 표시하고, 화면 안에 `sample`, `test` 같은 문구가 남아 있지 않은지 확인한다. 결제경로 파일을 받기 전에는 임의의 양식으로 포스타트에 제출하지 않는다.
