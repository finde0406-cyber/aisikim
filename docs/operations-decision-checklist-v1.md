# AI시킴 운영값 결정 체크리스트 v1

## 1. 문서 목적
이 문서는 AI시킴의 자동 발송, 이메일 운영, 결제 후 자료 전달을 실제로 연결하기 전에 반드시 결정해야 하는 운영값을 한곳에 모아둔 체크리스트입니다.  
문서 기준은 충분히 정리되었으므로, 이제부터는 “무슨 도구를 쓸지”, “어떤 주소로 보낼지”, “어떤 링크를 넣을지” 같은 실제 운영값이 필요합니다.

## 2. 이 문서를 왜 먼저 채워야 하는가
Claude Code가 자동화나 연결 로직을 구현하려면 아래 값이 먼저 정해져 있어야 합니다.

- 폼 도구
- 발신 메일 주소
- 발송 도구
- PDF / Notion 링크
- 결제 완료 이벤트 수신 방식

즉, 구현보다 먼저 운영값을 확정해야 합니다.

## 3. 무료 샘플팩 운영값

### 3.1 신청 수집 도구
- 후보:
  - Tally
  - Google Form
  - 자체 폼 + 저장
- 현재 선택:
  - Tally

### 3.2 신청 데이터 저장 위치
- 후보:
  - Tally 응답 목록
  - Google Sheets
  - Airtable
  - Notion
  - 자체 DB
- 현재 선택:
  - Tally 응답 목록 + Google Sheets 보조

### 3.3 발신 메일 주소
- 예:
  - hello@
  - support@
  - contact@
- 현재 선택:
  - 임시 운영: 현재 사용 중인 Gmail 1개
  - 실제 출시 전 전환: hello@도메인

### 3.4 발송 도구
- 후보:
  - Tally 응답자 메일
  - Gmail / Google Workspace 수동 발송
  - Resend
  - 기타 메일 도구
- 현재 선택:
  - 초기: 운영자 수동 또는 반자동 발송
  - 추후: Webhook + 메일 도구 자동화

### 3.5 샘플팩 전달 자산
- PDF 링크:
  - 생성 필요
- Notion 링크:
  - 생성 필요
- 필요한 경우 첨부 파일 경로:
  - 추후 결정

### 3.6 자동 발송 방식
- 후보:
  - 신청 즉시 자동 발송
  - 신청 후 수동 승인 뒤 발송
- 현재 선택:
  - 초기 반자동

## 4. 유료 스타터팩 운영값

### 4.1 결제 방식
- 후보:
  - 외부 결제 링크
  - 스마트스토어
  - 향후 토스페이먼츠
- 현재 선택:
  - 외부 결제 링크

### 4.2 결제 완료 이벤트 수신 방식
- 후보:
  - 수동 확인
  - 결제 플랫폼 웹훅
  - 결제 완료 메일 기반 확인
- 현재 선택:
  - 초기에는 수동 확인 또는 반자동 확인

### 4.3 스타터팩 전달 자산
- PDF 링크:
  - 생성 필요
- Notion 링크:
  - 생성 필요
- 사용 가이드 링크:
  - 생성 필요

### 4.4 구매 후 메일 발송 방식
- 후보:
  - 수동 발송
  - 자동 발송
  - 결제 확인 후 반자동 발송
- 현재 선택:
  - 결제 확인 후 반자동 발송

### 4.5 문의/회신 메일 주소
- 현재 선택:
  - 임시 운영: 현재 사용 중인 Gmail 1개
  - 실제 출시 전 전환: hello@도메인 또는 support@도메인

## 5. 링크/파일 관리 정책

### 5.1 파일 저장 위치
- 후보:
  - Google Drive
  - Notion
  - Vercel public asset
  - 스토리지 서비스
- 현재 선택:
  - PDF: Google Drive 또는 고정 링크 관리 가능한 저장소
  - Notion: 공개 읽기 전용 링크

### 5.2 파일 버전 관리 방식
- 샘플팩 수정 시 같은 링크 유지 여부:
  - 예
- 스타터팩 수정 시 버전명 관리 여부:
  - 예

### 5.3 링크 공개 범위
- 누구나 링크로 접근 가능
- 메일 수신자만 접근
- 로그인 필요 없음
- 현재 선택:
  - 로그인 없이 링크 접근 가능

## 6. 메일 운영 정책

### 6.1 무료 샘플팩 메일 발송 시점
- 즉시
- 5분 이내
- 영업시간 내 수동
- 현재 선택:
  - 초기 반자동 기준: 운영 확인 후 가능한 빨리 발송

### 6.2 유료 스타터팩 메일 발송 시점
- 결제 직후 즉시
- 확인 후 수동
- 현재 선택:
  - 결제 확인 후 가능한 빨리 발송

### 6.3 수신 거부 처리 방식
- 폼 하단 안내만
- 메일 하단 링크
- 회신 요청
- 현재 선택:
  - 메일 하단 안내 문구 + 회신 요청 병행

## 7. 운영자 확인 항목

### 운영자가 항상 확인할 수 있어야 하는 것
1. 신청된 이메일 목록
2. 발송 성공/실패 여부
3. 어떤 자료가 발송됐는지
4. 어떤 결제가 어떤 구매자에게 연결됐는지

### 현재 확인 방법
- 무료 신청: Tally 응답 목록 + Google Sheets
- 유료 구매: 결제 확인 내역 + 발송 로그 수동 관리

## 8. Claude Code 구현 전 반드시 확정할 항목
아래 6개는 구현 전에 꼭 확정해야 합니다.

1. 무료 신청 수집 도구
2. 발신 메일 주소
3. 발송 도구
4. 샘플팩 PDF / Notion 링크
5. 스타터팩 PDF / Notion / 가이드 링크
6. 결제 완료 이벤트 수신 방식

## 9. 현재 가장 현실적인 1차 권장안

### 무료
- 수집 도구: Tally
- 데이터 저장: Tally + Google Sheets 보조
- 발송: 1차는 수동 또는 반자동
- 자료: PDF + Notion 링크

### 유료
- 결제: 외부 결제 링크
- 발송: 결제 확인 후 수동 또는 반자동
- 자료: PDF + Notion + 사용 가이드

## 10. 최종 기준
AI시킴은 “아이디어는 있는데 실제 운영값이 없는 상태”로 자동화를 붙이면 오히려 더 어색해집니다.  
따라서 이 문서를 먼저 채운 뒤, 그 값을 기준으로 Claude Code에게 구현을 맡기는 것이 가장 안전합니다.
