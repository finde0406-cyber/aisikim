# AI시킴 운영값 입력 가이드 v1

## 1. 문서 목적
이 문서는 [ops check](C:\Users\win10\Documents\AI시킴\docs\operations-decision-checklist-v1.md) 를 실제로 채울 때, 어떤 기준으로 운영값을 고르면 좋은지 설명하는 가이드입니다.  
AI시킴은 지금 서비스 완성도와 신뢰를 우선하는 단계이므로, “가장 멋진 도구”보다 “가장 덜 헷갈리고 가장 운영하기 쉬운 선택”을 우선하도록 돕는 것이 목적입니다.

## 2. 기본 원칙

### 2.1 지금은 복잡함보다 신뢰가 우선
- 신청했는데 메일이 안 오거나
- 결제했는데 자료가 안 오거나
- 링크가 틀리거나
- 운영자가 어디서 확인해야 하는지 모르면
서비스 신뢰가 바로 무너집니다.

### 2.2 처음엔 덜 자동이어도 괜찮다
- 완전자동보다 반자동이 더 안전할 수 있습니다.
- 실제 운영 경험이 쌓인 뒤 자동화를 더 올려도 늦지 않습니다.

### 2.3 모든 값은 나중에 바꿀 수 있어야 한다
- 도구를 바꿔도 서비스가 멈추지 않아야 합니다.
- 링크, 메일 주소, 발송 흐름은 교체 가능해야 합니다.

## 3. 무료 샘플팩 운영값 추천

### 3.1 신청 수집 도구
가장 현실적인 1차 추천:
- `Tally`

이유:
- 시작이 빠름
- 폼 만들기 쉬움
- 외부 링크 연결이 쉬움
- 초기 운영 실험에 적합

처음엔 피하는 게 좋은 선택:
- 자체 폼 + 자체 저장

이유:
- 구현과 운영 확인 포인트가 한 번에 늘어남

### 3.2 신청 데이터 저장 위치
가장 현실적인 1차 추천:
- `Tally 응답 + Google Sheets 보조`

이유:
- Tally에서 바로 확인 가능
- Sheets로 백업/정리 가능
- 운영자가 보기 쉬움

### 3.3 발신 메일 주소
가장 현실적인 1차 추천:
- `hello@도메인`
또는
- `support@도메인`

추천 기준:
- `hello@`는 브랜드형, 친근한 느낌
- `support@`는 운영/문의형, 실무적인 느낌

초기 AI시킴에는:
- `hello@`가 조금 더 어울릴 가능성이 큼

### 3.4 샘플팩 발송 도구
1차 추천:
- 수동 또는 반자동

권장 순서:
1. 처음엔 수동 또는 간단한 반자동
2. 흐름 확인
3. 이후 Webhook + 메일 도구 자동화

이유:
- 지금은 메일 본문, 링크, 발신 경험을 먼저 안정화해야 함

## 4. 유료 스타터팩 운영값 추천

### 4.1 결제 방식
현재 단계 추천:
- 자사 서비스 내 설득
- 외부 결제 링크 방식

이유:
- 서비스는 독립적으로 보이게 유지
- 결제는 더 신뢰되거나 쉬운 채널로 연결

### 4.2 결제 완료 이벤트 수신 방식
1차 추천:
- `수동 확인` 또는 `반자동 확인`

이유:
- 아직 판매량이 크지 않은 초기엔
- 결제 실수나 발송 실수를 직접 보는 편이 더 안전함

2차 추천:
- `결제 채널 웹훅`

### 4.3 구매 후 메일 발송 방식
1차 추천:
- `결제 확인 후 반자동 발송`

이유:
- 자료 누락/오발송 리스크를 줄임
- 운영자가 처음 몇 건을 직접 보면서 기준을 잡을 수 있음

## 5. 링크/파일 관리 추천

### 5.1 파일 저장 위치
1차 추천:
- PDF: 고정 링크로 관리 가능한 저장소
- Notion: 별도 공유 링크

조건:
- 링크가 바뀌지 않거나
- 바뀌어도 운영자가 한 곳에서 수정 가능해야 함

### 5.2 버전 관리
추천:
- 샘플팩은 `same-link update` 방식 가능
- 스타터팩은 버전명 관리 권장

이유:
- 유료 상품은 어떤 버전을 받았는지 운영자가 알아야 함

예:
- `starter-pack-v1`
- `starter-pack-v1.1`

## 6. 메일 운영 정책 추천

### 6.1 무료 샘플팩 메일
1차 추천:
- 신청 후 가능한 빨리
- 완전자동이 아니면 “영업일 기준 몇 시간/1일 내” 같은 기준 명시

### 6.2 유료 스타터팩 메일
1차 추천:
- 결제 확인 후 빠르게 발송
- 사용자 기대는 “결제하면 바로 받아야 한다”에 가까우므로 지연 시 안내 필요

### 6.3 수신 거부
추천:
- 메일 하단 문구 + 문의 회신 방식 병행

## 7. 지금 AI시킴에 가장 현실적인 1차 조합

### 무료
- 신청 수집: Tally
- 데이터 저장: Tally + Sheets
- 발송 방식: 수동 또는 반자동
- 자료: PDF + Notion
- 발신 주소: hello@

### 유료
- 결제: 외부 결제 링크
- 완료 확인: 수동 또는 반자동
- 자료: PDF + Notion + 사용 가이드
- 발신 주소: hello@ 또는 support@

## 8. Claude Code를 부르기 전에 채워야 할 최소값
아래 6개만 채워도 구현 프롬프트가 명확해집니다.

1. 무료 폼 도구
2. 무료 발신 주소
3. 샘플팩 PDF 링크
4. 샘플팩 Notion 링크
5. 스타터팩 PDF/Notion/가이드 링크
6. 유료 결제 완료 확인 방식

## 9. 최종 기준
AI시킴 운영값은 “이론상 좋은 것”보다 “실제로 덜 틀리고, 운영자가 바로 확인할 수 있는 것”이 더 중요합니다.  
처음에는 조금 수동이어도 괜찮고, 한 번 판매와 발송이 안정적으로 돌아간 뒤 자동화를 높이는 편이 더 안전합니다.
