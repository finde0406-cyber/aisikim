# AI시킴 샘플팩 5개 초안 v1

## 1. 문서 목적
이 문서는 무료 샘플팩 발송용 초안입니다.  
실제 발송 전에는 문구 다듬기, 복사 테스트, PDF/Notion 배치 조정이 필요하지만, 현재 단계에서 샘플팩이 어떤 품질과 구조를 가져야 하는지 검증할 수 있는 첫 실물 초안으로 사용합니다.

## 2. 샘플팩 구성
1. 블로그 글 초안 만들기
2. 업무 보고서 초안 정리
3. 앱/웹사이트 기능 정의 요청하기
4. 공통 AI 활용/작업설계 시작하기
5. AI 결과물 수정 및 검수 요청하기

## 샘플 1. 블로그 글 초안을 빠르게 잡고 싶을 때

### 이 작업지시서가 필요한 상황
블로그 글을 써야 하는데, 제목과 흐름을 어떻게 잡아야 할지 막막할 때 사용합니다.

### 언제 쓰면 좋은지
- 처음 질문을 시작할 때
- 글 초안이 필요할 때
- AI가 너무 일반적인 블로그 구조만 줄 때

### 바로 복사해서 쓸 본문
```text
지금 저는 [주제]에 대한 블로그 글을 쓰려고 합니다.
이번 글의 목적은 [정보 제공 / 제품 소개 / 경험 공유 / 문제 해결]입니다.
읽을 대상은 [대상 독자]입니다.

먼저 이 글에서 꼭 다뤄야 할 핵심 포인트가 있다면 짚어주세요.
그 다음 제목 후보 3개를 제안하고, 가장 적절한 구조를 골라 소제목과 본문 초안을 작성해 주세요.

답변은 너무 추상적이지 않게, 바로 블로그에 옮겨 적을 수 있을 정도로 구체적으로 써주세요.
도입부, 본문, 마무리가 자연스럽게 이어지게 해주세요.
```

### 바꿔야 할 부분
- `[주제]`: 예) ChatGPT로 글쓰기, 직장인 아침 루틴, AI시킴 사용 후기
- `[정보 제공 / 제품 소개 / 경험 공유 / 문제 해결]`: 글 목적에 맞게 선택
- `[대상 독자]`: 예) AI 초보자, 직장인, 1인 사업자

### 후속 질문 예시
- 위 초안을 대상 독자가 더 쉽게 이해할 수 있도록 다시 써줘.
- 제목은 유지하고, 소제목만 더 클릭하고 싶게 바꿔줘.

### 수정 요청 예시
- 너무 일반적인 문장은 줄이고 실제 예시를 더 넣어줘.
- 문단 길이를 줄이고 모바일에서 읽기 쉽게 다시 정리해줘.

### 활용 팁
첫 결과가 무난하면 바로 후속 질문으로 더 구체화하세요. 제목, 도입부, 마무리만 따로 다시 시켜도 결과 품질이 많이 올라갑니다.

## 샘플 2. 업무 보고서 초안을 정리하고 싶을 때

### 이 작업지시서가 필요한 상황
업무 보고서나 기획 메모를 정리해야 하는데, 어떤 항목 구조로 써야 할지 막막할 때 사용합니다.

### 언제 쓰면 좋은지
- 보고서 초안이 필요할 때
- 상사나 팀에 공유할 정리 문서가 필요할 때
- AI가 너무 장황하거나 실무감 없이 답할 때

### 바로 복사해서 쓸 본문
```text
지금 저는 [업무 주제]에 대한 보고서 초안을 정리해야 합니다.
이 문서는 [상사 / 팀원 / 고객 / 이해관계자]가 읽을 예정입니다.
보고 목적은 [현황 공유 / 문제 보고 / 제안 / 실행 계획 정리]입니다.

먼저 보고서에 꼭 들어가야 할 핵심 항목이 있다면 질문해 주세요.
그 다음 목차를 먼저 제안하고, 각 항목별로 바로 공유 가능한 수준의 초안을 작성해 주세요.

답변은 실무 문서처럼 명확하게 정리해 주세요.
가능하면 배경, 현재 상황, 핵심 이슈, 제안 또는 다음 행동이 보이게 구성해 주세요.
```

### 바꿔야 할 부분
- `[업무 주제]`: 예) 신규 서비스 출시 준비, 고객 문의 대응 현황, 콘텐츠 운영 계획
- `[상사 / 팀원 / 고객 / 이해관계자]`: 실제 독자에 맞게 변경
- `[현황 공유 / 문제 보고 / 제안 / 실행 계획 정리]`: 보고 목적 선택

### 후속 질문 예시
- 이 보고서를 더 짧고 임원 보고용으로 다시 정리해줘.
- 핵심 이슈 3개만 먼저 보이도록 구조를 바꿔줘.

### 수정 요청 예시
- 문장을 더 단정하게 바꾸고 군더더기를 줄여줘.
- 읽는 사람이 바로 결정할 수 있게 제안 항목을 더 선명하게 써줘.

### 활용 팁
보고서는 처음부터 완벽한 본문보다 `목차 → 핵심 문장 → 상세 본문` 순서로 다듬는 게 좋습니다.

## 샘플 3. 앱/웹사이트 기능 정의를 요청하고 싶을 때

### 이 작업지시서가 필요한 상황
만들고 싶은 기능은 있는데, 개발자나 AI에게 어떻게 설명해야 할지 모르겠을 때 사용합니다.

### 언제 쓰면 좋은지
- 기능 정의가 막막할 때
- 개발 지시 전에 요구사항을 정리하고 싶을 때
- AI가 너무 기술적이거나 반대로 너무 추상적으로 답할 때

### 바로 복사해서 쓸 본문
```text
지금 저는 [서비스 또는 화면]에 들어갈 [기능]을 정의하고 싶습니다.
이 기능의 목적은 [사용자 문제 / 운영 효율 / 전환율 개선 등]입니다.

먼저 이 기능을 정의하기 전에 꼭 확인해야 할 핵심 질문이 있다면 먼저 물어봐 주세요.
그 다음 아래 기준으로 기능 정의를 정리해 주세요.

1. 이 기능이 해결하려는 문제
2. 사용자가 어떤 흐름으로 쓰는지
3. 꼭 필요한 핵심 요소
4. 개발자가 이해할 수 있는 수준의 요구사항
5. 빠르게 MVP로 만들 때 우선 구현할 범위

답변은 비개발자도 이해할 수 있게 설명하되, 개발자에게 전달 가능한 수준으로 구체적으로 써주세요.
```

### 바꿔야 할 부분
- `[서비스 또는 화면]`: 예) AI시킴 결과 페이지, 관리자 메모 화면, 회원가입 화면
- `[기능]`: 예) 이메일 수집 폼, 결제 버튼, 복사 기능, 필터 기능
- `[사용자 문제 / 운영 효율 / 전환율 개선 등]`: 목적 입력

### 후속 질문 예시
- 위 기능 정의를 개발자 전달용 문서 형식으로 다시 정리해줘.
- 이 기능에서 MVP와 추후 확장 범위를 나눠서 보여줘.

### 수정 요청 예시
- 너무 추상적인 표현은 줄이고 실제 화면 요소 기준으로 써줘.
- 사용자 흐름을 단계별로 더 구체적으로 설명해줘.

### 활용 팁
기능 정의는 "무엇을 만들지"보다 "왜 필요한지"를 먼저 분명히 하면 결과가 좋아집니다.

## 샘플 4. AI 작업을 어떤 순서로 시작해야 할지 모르겠을 때

### 이 작업지시서가 필요한 상황
AI를 쓰고 싶지만 어디서부터 물어봐야 하는지 막막할 때, 전체 작업 흐름을 먼저 잡는 용도로 사용합니다.

### 언제 쓰면 좋은지
- 처음 AI를 써볼 때
- 여러 번 이어서 시켜야 하는데 순서가 안 잡힐 때
- 단일 질문이 아니라 작업 설계가 먼저 필요할 때

### 바로 복사해서 쓸 본문
```text
지금 저는 [하고 싶은 작업]을 AI로 진행하고 싶습니다.
하지만 무엇부터 어떤 순서로 시켜야 할지 잘 모르겠습니다.

먼저 이 작업을 잘 진행하기 위해 꼭 확인해야 할 질문을 해주세요.
그 다음 아래 형식으로 전체 흐름을 설계해 주세요.

1. 첫 질문에서 확인해야 할 것
2. 첫 결과를 받은 뒤 이어서 물어볼 후속 질문
3. 결과가 마음에 안 들 때 수정 요청하는 방법
4. 마지막에 품질을 높이기 위한 검수 질문

답변은 초보자도 그대로 따라갈 수 있게 단계별로 설명해 주세요.
```

### 바꿔야 할 부분
- `[하고 싶은 작업]`: 예) 블로그 글쓰기, 보고서 작성, 기능 정의, 마케팅 문구 만들기

### 후속 질문 예시
- 위 흐름을 더 짧게 핵심 단계만 남겨서 다시 정리해줘.
- 각 단계마다 바로 복사해서 쓸 문장 예시까지 붙여줘.

### 수정 요청 예시
- 너무 설명형으로 쓰지 말고 실제 요청 문장 중심으로 다시 써줘.
- 단계별 목적이 더 분명하게 보이도록 정리해줘.

### 활용 팁
이 작업지시서는 결과물 자체를 받기보다, `AI를 어떻게 쓸지의 순서`를 잡을 때 특히 유용합니다.

## 샘플 5. AI 결과물을 더 좋게 수정하고 검수하고 싶을 때

### 이 작업지시서가 필요한 상황
이미 AI 답변이나 초안은 나왔지만, 품질이 아쉽고 어떻게 수정 요청해야 할지 모를 때 사용합니다.

### 언제 쓰면 좋은지
- 초안은 나왔는데 만족스럽지 않을 때
- 방향은 맞지만 완성도가 낮을 때
- 마지막 검수 단계에서 빠진 걸 점검하고 싶을 때

### 바로 복사해서 쓸 본문
```text
[아래에 검토받고 싶은 AI 결과물을 붙여 넣겠습니다]

아래 결과물은 현재 방향은 맞지만, 아직 완성도가 부족합니다.
무조건 다시 처음부터 쓰기보다, 어떤 부분을 고치면 더 좋아지는지 먼저 점검해 주세요.

특히 아래 기준으로 검토해 주세요.
1. 너무 일반적이거나 추상적인 부분
2. 빠져 있는 핵심 요소
3. 더 구체적으로 바꾸면 좋은 부분
4. 읽는 사람이 바로 이해하기 어려운 부분

그 다음 수정 방향을 짧게 설명하고, 수정 반영본까지 함께 다시 작성해 주세요.
```

### 바꿔야 할 부분
- `[아래에 검토받고 싶은 AI 결과물을 붙여 넣겠습니다]` 자리에 실제 AI 결과물을 붙여 넣기

### 후속 질문 예시
- 수정본에서 여전히 부족한 부분이 있다면 한 번 더 검수해줘.
- 이 결과를 더 짧고 강하게 바꾼 버전도 하나 추가해줘.

### 수정 요청 예시
- 너무 추상적인 표현은 줄이고 실제 상황에 맞는 표현으로 다시 써줘.
- 핵심 메시지는 유지하되 더 읽기 쉽게 구조를 다시 나눠줘.

### 활용 팁
많은 사용자가 첫 질문보다 `수정 요청`에서 막힙니다. 이 샘플은 초안 이후 품질을 끌어올리는 데 특히 중요합니다.

## 10. 샘플팩 사용 안내 문구 초안
- 먼저 지금 가장 막힌 작업과 가까운 샘플 1개부터 복사해서 써보세요.
- 첫 답변이 마음에 들지 않으면, 각 샘플에 붙은 후속 질문과 수정 요청까지 이어서 써보세요.
- 무료 결과 1개보다 더 실전적인 흐름을 경험해보는 것이 이 샘플팩의 핵심입니다.

## 11. 샘플팩 발송용 구성안
### 11.1 PDF 기준
- 표지 1페이지
- 사용 안내 1페이지
- 샘플 5개 본문
- 마지막 페이지에 스타터팩 안내 1페이지

### 11.2 Notion 기준
- 상단에 사용 순서 안내
- 샘플 5개를 개별 토글 또는 구분 섹션으로 정리
- 각 샘플 안에 `복사해서 쓸 본문`, `후속 질문`, `수정 요청` 순서 유지

### 11.3 메일 본문에 함께 넣을 짧은 안내
- 먼저 지금 가장 막힌 작업과 가장 가까운 샘플 1개부터 써보세요.
- 첫 답변이 마음에 들지 않으면 바로 아래의 후속 질문과 수정 요청까지 이어서 사용해보세요.
- 더 완성된 흐름이 필요하다면 스타터팩에서 후속 질문, 수정 요청, 검수 요청까지 이어지는 전체 구조를 확인할 수 있습니다.
