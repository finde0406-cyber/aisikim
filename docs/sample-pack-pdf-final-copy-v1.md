# AI시킴 샘플팩 PDF 최종 문안 v1

## 1. 문서 목적
이 문서는 AI시킴 샘플팩 PDF에 실제로 들어갈 최종 문안을 페이지 순서대로 정리한 문서입니다.  
이 문안은 바로 PDF 작업에 옮겨갈 수 있는 기준본으로 사용합니다.

---

## 페이지 1. 표지

### 메인 제목
AI시킴 무료 작업지시서 샘플팩

### 부제
지금 막힌 작업부터 바로 써볼 수 있는  
실전 작업지시서 5개

### 짧은 안내 문구
처음부터 전부 읽기보다,  
지금 가장 필요한 샘플 1개부터 먼저 써보세요.

## 페이지 2. 이 자료는 어떻게 쓰나요

### 섹션 제목
이 자료는 이렇게 쓰면 좋습니다

### 본문
이 자료는 AI에게 한 번 던지고 끝내는 문장 모음이 아닙니다.  
지금 가장 막힌 작업과 가까운 작업지시서 1개를 먼저 골라서 써보고,  
첫 답변이 약하면 바로 아래에 붙은 `후속 질문`, `수정 요청`, `검수 요청`까지 이어서 사용하는 자료입니다.

### 가장 추천하는 사용 순서
1. 지금 가장 급한 작업과 맞는 샘플 1개를 고릅니다.
2. `바로 복사해서 쓸 본문`을 먼저 사용합니다.
3. 결과가 마음에 안 들면 `후속 질문` 또는 `수정 요청`을 바로 이어서 씁니다.
4. 마지막으로 `검수 요청`으로 품질을 한 번 더 점검합니다.

### 꼭 기억하면 좋은 점
- 대괄호 `[]` 안의 내용은 내 상황에 맞게 꼭 바꿔야 합니다.
- 첫 답변이 평범해 보여도 바로 포기하지 말고 2차, 3차 질문까지 이어가야 결과가 좋아집니다.
- AI가 답을 너무 넓게 주면 `구체적으로`, `예시 중심으로`, `실제로 바로 쓸 수 있게`라는 표현을 다시 넣어주세요.

## 페이지 3. 무엇부터 시작하면 좋을까요

### 섹션 제목
지금 막힌 작업에 맞춰 여기서 시작하세요

### 추천 시작 경로
- 글이 막히는 사람 → 샘플 1. 블로그 글 초안 만들기
- 보고서가 막히는 사람 → 샘플 2. 업무 보고서 초안 정리
- 기능 정의가 막히는 사람 → 샘플 3. 앱/웹사이트 기능 정의 요청하기
- AI를 어떤 순서로 써야 할지 모르겠는 사람 → 샘플 4. 공통 AI 활용/작업설계 시작하기
- 이미 나온 결과가 아쉬운 사람 → 샘플 5. AI 결과물 수정 및 검수 요청하기

### 짧은 안내
지금 가장 가까운 항목 1개부터 써보세요.  
한 번에 5개를 다 보려 하기보다, 1개를 써보고 후속 질문까지 이어가는 것이 훨씬 중요합니다.

## 페이지 4. 샘플 1

### 제목
샘플 1. 블로그 글 초안을 빠르게 잡고 싶을 때

### 이런 상황에서 쓰세요
- 글 주제는 정했는데 제목과 흐름이 안 잡힐 때
- AI가 너무 흔한 블로그 구조만 줄 때
- 초안을 빨리 만든 뒤 내가 고치고 싶을 때

### 이 작업지시서로 기대할 수 있는 결과
- 제목 후보
- 소제목 구조
- 도입부 초안
- 본문 핵심 흐름
- 마무리 방향

### 바로 복사해서 쓸 본문
```text
지금 저는 [주제]에 대한 블로그 글을 쓰려고 합니다.
이번 글의 목적은 [정보 제공 / 제품 소개 / 경험 공유 / 문제 해결]입니다.
읽을 대상은 [대상 독자]이며, 이 독자는 [현재 수준 / 관심사 / 자주 겪는 문제]를 가지고 있습니다.

먼저 이 글에서 꼭 다뤄야 할 핵심 포인트가 무엇인지 짚어주세요.
그 다음 아래 순서로 결과를 작성해 주세요.

1. 제목 후보 5개
2. 그중 가장 적합한 제목 1개와 선택 이유
3. 소제목 구조
4. 도입부 초안
5. 각 소제목별 핵심 문장
6. 마무리 문장

답변은 너무 추상적이지 않게, 실제 블로그 초안으로 바로 옮겨 쓸 수 있을 정도로 구체적으로 작성해 주세요.
읽는 사람이 중간에 이탈하지 않도록 흐름이 자연스럽게 이어지게 해주세요.
```

### 바꿔야 할 부분
- `[주제]`
- `[정보 제공 / 제품 소개 / 경험 공유 / 문제 해결]`
- `[대상 독자]`
- `[현재 수준 / 관심사 / 자주 겪는 문제]`

### 후속 질문
- 위 구조를 유지한 채 도입부만 더 강하게 다시 써줘.
- 소제목은 유지하고, 각 소제목 아래에 넣을 실제 예시를 더 추가해줘.

### 수정 요청
- 너무 흔한 블로그 표현은 줄이고, 실제 경험이 느껴지는 표현으로 바꿔줘.
- 문단 길이를 줄이고 모바일에서 읽기 쉽게 다시 정리해줘.

### 검수 요청
- 이 글 구조에서 빠진 핵심 요소가 있는지 점검해줘.
- 대상 독자가 읽었을 때 공감이 약할 부분이 있다면 짚어줘.

### 사용 팁
블로그는 첫 초안보다 `후속 질문`에서 품질 차이가 크게 납니다.  
제목, 도입부, 마무리를 따로 한 번 더 요청하면 훨씬 좋아집니다.

### 제목
샘플 2. 업무 보고서 초안을 정리하고 싶을 때

### 이런 상황에서 쓰세요
- 보고서나 기획 메모 구조가 안 잡힐 때
- 상사나 팀에 공유할 문서를 빠르게 정리해야 할 때
- AI 답변이 실무감 없이 길기만 할 때

### 이 작업지시서로 기대할 수 있는 결과
- 한 줄 요약
- 배경 정리
- 현재 상황 정리
- 핵심 이슈
- 제안 또는 다음 행동

### 바로 복사해서 쓸 본문
```text
지금 저는 [업무 주제]에 대한 보고서 초안을 정리해야 합니다.
이 문서는 [상사 / 팀원 / 고객 / 이해관계자]가 읽을 예정입니다.
보고 목적은 [현황 공유 / 문제 보고 / 제안 / 실행 계획 정리]입니다.
현재 읽는 사람이 가장 빨리 이해해야 하는 것은 [핵심 이슈 / 제안 / 요청 사항]입니다.

먼저 이 문서에 꼭 들어가야 할 핵심 항목이 있다면 질문해 주세요.
그 다음 아래 형식으로 보고서 초안을 작성해 주세요.

1. 한 줄 요약
2. 배경
3. 현재 상황
4. 핵심 이슈
5. 제안 또는 다음 행동

답변은 실무 문서처럼 단정하고 명확하게 정리해 주세요.
불필요하게 장황하지 않게 쓰되, 실제 공유 가능한 수준으로 내용 밀도를 유지해 주세요.
```

### 바꿔야 할 부분
- `[업무 주제]`
- `[상사 / 팀원 / 고객 / 이해관계자]`
- `[현황 공유 / 문제 보고 / 제안 / 실행 계획 정리]`
- `[핵심 이슈 / 제안 / 요청 사항]`

### 후속 질문
- 이 문서를 임원 보고용으로 더 짧게 다시 정리해줘.
- 핵심 이슈 3개가 먼저 보이도록 요약형 버전도 추가해줘.

### 수정 요청
- 문장을 더 단정하게 바꾸고 군더더기를 줄여줘.
- 읽는 사람이 바로 의사결정할 수 있게 제안 부분을 더 선명하게 써줘.

### 검수 요청
- 이 보고서에서 빠진 핵심 항목이 있는지 점검해줘.
- 상사가 읽었을 때 바로 이해하기 어려운 부분이 있는지 검수해줘.

### 사용 팁
보고서는 `한 줄 요약 → 핵심 이슈 → 상세 본문` 순으로 다듬는 편이 훨씬 좋습니다.

## 페이지 6. 샘플 3

### 제목
샘플 3. 앱/웹사이트 기능 정의를 요청하고 싶을 때

### 이런 상황에서 쓰세요
- 만들고 싶은 기능은 있는데 설명이 안 잡힐 때
- 개발자나 AI에게 요구사항을 어떻게 전달할지 모를 때
- MVP 범위와 확장 범위를 나눠야 할 때

### 이 작업지시서로 기대할 수 있는 결과
- 문제 정의
- 사용자 흐름
- 핵심 요소
- MVP 범위
- 개발자 전달용 요구사항 요약

### 바로 복사해서 쓸 본문
```text
지금 저는 [서비스 또는 화면]에 들어갈 [기능]을 정의하고 싶습니다.
이 기능의 목적은 [사용자 문제 해결 / 운영 효율 / 전환율 개선 / 사용성 개선]입니다.
현재 가장 중요하게 보고 싶은 것은 [사용자 흐름 / 핵심 요소 / MVP 범위 / 개발자 전달용 요구사항]입니다.

먼저 이 기능을 정의하기 전에 꼭 확인해야 할 질문이 있다면 먼저 물어봐 주세요.
그 다음 아래 형식으로 기능 정의를 정리해 주세요.

1. 이 기능이 해결하려는 문제
2. 사용자가 이 기능을 쓰는 흐름
3. 꼭 필요한 핵심 요소
4. MVP에서 우선 구현할 범위
5. 추후 확장 가능 요소
6. 개발자에게 전달할 수 있는 요구사항 요약

답변은 비개발자도 이해할 수 있게 설명하되, 개발자가 읽어도 바로 작업을 시작할 수 있을 정도로 구체적으로 써주세요.
```

### 바꿔야 할 부분
- `[서비스 또는 화면]`
- `[기능]`
- `[사용자 문제 해결 / 운영 효율 / 전환율 개선 / 사용성 개선]`
- `[사용자 흐름 / 핵심 요소 / MVP 범위 / 개발자 전달용 요구사항]`

### 후속 질문
- 위 기능 정의를 개발자 전달용 문서 형식으로 다시 정리해줘.
- 사용자 흐름을 화면 단위로 더 세분화해서 보여줘.

### 수정 요청
- 너무 추상적인 표현은 줄이고 실제 화면 요소 기준으로 써줘.
- 기술 설명보다 먼저 사용자 문제와 목적이 더 잘 보이게 다시 정리해줘.

### 검수 요청
- 이 기능 정의에서 빠진 핵심 요소가 있는지 점검해줘.
- 개발자가 읽었을 때 애매하게 느낄 부분이 있는지 검수해줘.

### 사용 팁
개발 관련 작업은 “무엇을 만들지”보다 “왜 필요한지”와 “어디까지가 MVP인지”를 먼저 분명히 하면 결과가 좋아집니다.

## 페이지 7. 샘플 4

### 제목
샘플 4. AI 작업을 어떤 순서로 시작해야 할지 모르겠을 때

### 이런 상황에서 쓰세요
- AI를 처음 써보는 사람
- 무엇부터 물어봐야 할지 전혀 감이 안 올 때
- 한 번 질문으로 끝나지 않는 작업을 설계하고 싶을 때

### 이 작업지시서로 기대할 수 있는 결과
- 첫 질문 설계
- 후속 질문 순서
- 수정 요청 방향
- 마지막 검수 질문

### 바로 복사해서 쓸 본문
```text
지금 저는 [하고 싶은 작업]을 AI로 진행하고 싶습니다.
하지만 무엇부터 어떤 순서로 시켜야 할지 잘 모르겠습니다.

먼저 이 작업을 잘 진행하기 위해 꼭 확인해야 할 질문을 먼저 해주세요.
그 다음 아래 형식으로 전체 작업 흐름을 설계해 주세요.

1. 첫 질문에서 확인해야 할 것
2. 첫 결과를 받은 뒤 이어서 물어볼 후속 질문
3. 결과가 마음에 안 들 때 수정 요청하는 방법
4. 마지막에 품질을 높이기 위한 검수 질문
5. 사용자가 흔히 놓치는 포인트

답변은 처음 해보는 사람도 그대로 따라갈 수 있게 단계별로 설명해 주세요.
가능하면 각 단계마다 바로 복사해서 쓸 문장 예시도 함께 붙여 주세요.
```

### 바꿔야 할 부분
- `[하고 싶은 작업]`

### 후속 질문
- 위 흐름을 더 짧게 핵심 단계만 남겨서 다시 정리해줘.
- 각 단계에서 실패하기 쉬운 포인트까지 같이 알려줘.

### 수정 요청
- 설명형 문장을 줄이고 실제 복사해서 쓸 문장 중심으로 다시 정리해줘.
- 단계별 목적이 더 분명하게 보이도록 순서를 다시 다듬어줘.

### 검수 요청
- 이 흐름에서 빠진 핵심 단계가 있는지 점검해줘.
- 초보자가 따라가다가 막힐 만한 구간이 있는지 검수해줘.

### 사용 팁
이 샘플은 결과물을 바로 만드는 용도보다, `AI를 어떻게 써야 할지의 순서`를 잡는 데 특히 강합니다.

## 페이지 8. 샘플 5

### 제목
샘플 5. AI 결과물을 더 좋게 수정하고 검수하고 싶을 때

### 이런 상황에서 쓰세요
- 초안은 나왔지만 만족스럽지 않을 때
- 방향은 맞는데 완성도가 낮을 때
- 마지막 검수 단계에서 빠진 부분을 점검하고 싶을 때

### 이 작업지시서로 기대할 수 있는 결과
- 약한 부분 진단
- 수정 방향 정리
- 보완된 최종본
- 마지막 검수 포인트

### 바로 복사해서 쓸 본문
```text
[아래에 검토받고 싶은 AI 결과물을 붙여 넣겠습니다]

아래 결과물은 방향은 맞지만, 아직 완성도가 부족합니다.
무조건 처음부터 다시 쓰기보다, 현재 결과를 바탕으로 무엇을 고치면 더 좋아지는지 먼저 짚어주세요.

특히 아래 기준으로 검토해 주세요.
1. 너무 일반적이거나 추상적인 부분
2. 빠져 있는 핵심 요소
3. 더 구체적으로 바꾸면 좋은 부분
4. 읽는 사람이 바로 이해하기 어려운 부분
```

### 후속 질문
- 수정본에서 여전히 부족한 부분이 있다면 한 번 더 검수해줘.
- 이 결과를 더 짧고 강하게 바꾼 버전도 하나 추가해줘.

### 수정 요청
- 너무 추상적인 표현은 줄이고 실제 상황에 맞는 표현으로 다시 써줘.
- 핵심 메시지는 유지하되 더 읽기 쉽게 구조를 다시 나눠줘.

### 검수 요청
- 이 결과가 초보자도 바로 써먹을 수 있는 수준인지 검수해줘.
- 제출 직전 기준으로 빠진 핵심 요소가 있다면 짚어줘.

### 사용 팁
많은 사람은 첫 질문보다 `수정 요청`에서 더 많이 막힙니다.  
이 샘플은 “아쉬운 초안”을 “쓸 만한 결과”로 끌어올릴 때 특히 중요합니다.
