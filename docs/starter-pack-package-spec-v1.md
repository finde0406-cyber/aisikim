# AI시킴 스타터팩 패키징 설계 v1

## 1. 문서 목적
이 문서는 유료 `AI 작업지시서 스타터팩`을 실제 구매자에게 전달할 때 어떤 순서와 구성으로 보여줘야 상품처럼 느껴지는지를 정리한 패키징 설계 문서입니다.  
스타터팩은 단순한 텍스트 묶음이 아니라, 사용자가 받자마자 이해하고 바로 활용할 수 있는 실행형 디지털 상품이어야 한다는 기준으로 설계합니다.

## 2. 스타터팩이 전달해야 하는 첫 인상
스타터팩을 처음 연 사용자는 아래 느낌을 받아야 합니다.

1. 생각보다 정리가 잘 되어 있다
2. 뭘 먼저 써야 할지 바로 알겠다
3. 그냥 문장 모음이 아니라 실전 도구 같다
4. 돈값 한다는 느낌이 난다

## 3. 전달물 구성
스타터팩은 아래 4개 묶음으로 제공하는 것을 권장합니다.

### 3.1 메인 PDF
- 표지
- 이 상품이 필요한 사람
- 사용법
- 카테고리별 인덱스
- 작업지시서 50개
- 마지막 활용 안내

### 3.2 Notion 보조 링크
- 카테고리별 빠른 탐색
- 검색/복사/업데이트 편의
- 모바일 복사 편의

### 3.3 사용자 가이드
- 어디부터 써야 하는지
- 어떤 순서로 쓰는지
- 답변이 약할 때 어떻게 이어가는지

### 3.4 구매 후 안내 메일
- 어떤 자료를 받았는지
- 가장 먼저 써볼 작업지시서 추천
- PDF / Notion / 가이드 위치 안내

## 4. 메인 PDF 권장 페이지 흐름

### 4.1 표지
- 제목: `AI 작업지시서 스타터팩`
- 부제: `결과물을 완성하기 위한 단계별 작업지시서 50개`
- 짧은 문장: `한 번 묻고 끝내는 문장 모음이 아니라, 초안부터 수정·검수까지 이어지는 실전용 세트`

### 4.2 1~2페이지: 이 상품이 필요한 사람
- AI에게 무엇을 어떻게 시켜야 할지 모르겠는 사람
- 첫 질문만 던지고 결과가 별로라 자꾸 막히는 사람
- 블로그, 업무, 개발, 검수 작업을 더 잘하고 싶은 사람

### 4.3 3~5페이지: 가장 먼저 읽어야 할 사용법
- 이 상품을 어떻게 쓰는지
- 추천 사용 순서
- 대괄호 `[]` 안은 무엇을 바꾸는지
- 첫 답변이 약할 때 재시도 규칙
- 1개만 던지는 게 아니라 조합해서 써야 한다는 점

### 4.4 6~7페이지: 카테고리 인덱스
- 블로그/콘텐츠 10개
- 업무/보고서 10개
- 앱/웹사이트 개발 10개
- 결과물 검수/수정 10개
- 공통 AI 활용/작업설계 10개

각 카테고리마다:
- 언제 먼저 보면 좋은지
- 대표적으로 어떤 문제가 있을 때 쓰는지

### 4.5 본문 50개
각 작업지시서는 아래 구조를 유지합니다.
1. 제목
2. 한 줄 설명
3. 이런 상황에서 쓰세요
4. 이 작업지시서로 기대할 수 있는 결과
5. 바로 복사할 본문
6. 바꿔야 할 부분
7. 후속 질문
8. 수정 요청
9. 검수 요청
10. 자주 하는 실수
11. 이 순서에서 쓰면 좋습니다
12. 사용 팁

### 4.6 마지막 페이지: 다음 단계 안내
- 스타터팩 활용 팁
- 가장 자주 쓰게 되는 조합 예시
- 향후 딥팩 예고 문구

## 5. Notion 보조 링크 권장 구조

### 상단 고정 안내
- 처음 보는 사람은 어디부터 읽어야 하는지
- 지금 막힌 카테고리부터 찾는 법
- 자주 쓰는 조합 예시

### 카테고리별 탐색
- 블로그/콘텐츠
- 업무/보고서
- 앱/웹사이트 개발
- 결과물 검수/수정
- 공통 AI 활용/작업설계

### 각 작업지시서 표시 방식
- 제목
- 한 줄 설명
- 복사 본문
- 후속 질문
- 수정 요청
- 검수 요청

### 하단
- 문의/업데이트 안내
- 추후 확장 상품 안내 자리

## 6. 구매 후 메일에서 꼭 전달해야 할 것
1. 어떤 자료를 받았는지
2. PDF / Notion / 사용 가이드 링크
3. 지금 바로 써볼 추천 3개
4. 처음엔 1개만 고르고 후속 질문까지 써보라는 안내
5. 문의/회신 가능한 메일 주소

## 7. 사용자 입장에서 좋은 스타터팩의 조건
- 받자마자 길을 잃지 않는다
- 어디부터 시작해야 할지 바로 안다
- 같은 내용을 여러 번 읽지 않아도 된다
- 본문이 바로 복사하기 좋다
- 무료보다 확실히 다르다고 느낀다

## 8. 스타터팩에서 반드시 피해야 할 것
- 본문만 길게 나열된 PDF
- 설명서 없이 작업지시서만 던지는 방식
- 카테고리 구분이 약한 구성
- 같은 표현이 반복되는 본문
- “개수만 많은 상품”처럼 느껴지는 포장

## 9. 실제 판매 전 확인 질문
- 첫 5분 안에 이 상품이 어떻게 쓰이는지 이해되는가
- 처음 구매한 사용자가 어디부터 써야 할지 바로 아는가
- 대표 15개만 봐도 무료와 차이가 분명한가
- PDF와 Notion이 역할을 잘 나누는가
- 구매 후 바로 만족감을 줄 수 있는가

## 10. 최종 기준
스타터팩은 좋은 문장을 많이 넣는 것이 목적이 아니라,  
사용자가 결과물을 더 빨리, 더 제대로 완성하게 돕는 `실행형 상품`이어야 합니다.  
품질은 본문에서, 만족감은 패키징과 전달 경험에서 완성됩니다.
