# AI시킴 스타터팩 대표 5개 초안 v1

## 1. 문서 목적
이 문서는 스타터팩 우선 제작 15개 중 1단계 대표 5개를 먼저 실물 초안으로 정리한 문서입니다.  
스타터팩 전체 톤과 품질을 검증하기 위한 첫 유료용 본문 초안으로 사용합니다.

## 2. 포함된 대표 5개
1. 블로그 글의 첫 구조를 잡고 싶을 때
2. 업무 보고서의 기본 구조를 잡고 싶을 때
3. 기능 요구사항을 처음 정리하고 싶을 때
4. 너무 일반적인 답변을 더 구체적으로 바꾸고 싶을 때
5. AI 작업을 어떤 순서로 시작해야 할지 모르겠을 때

---

## 1. 블로그 글의 첫 구조를 잡고 싶을 때

### 목적
막막한 상태에서 바로 쓸 수 있는 블로그 글 구조와 초안을 빠르게 잡기 위한 작업지시서입니다.

### 언제 쓰는지
- 블로그 글을 처음 시작할 때
- 주제는 정했는데 구조가 안 잡힐 때
- AI가 너무 일반적인 블로그 틀만 줄 때

### 바로 복사할 본문
```text
지금 저는 [주제]에 대한 블로그 글을 작성하려고 합니다.
이번 글의 목적은 [정보 제공 / 제품 소개 / 경험 공유 / 문제 해결]입니다.
이 글을 읽을 대상은 [대상 독자]입니다.

먼저 이 글에서 꼭 다뤄야 할 핵심 포인트가 무엇인지 짚어주세요.
그 다음 아래 순서로 결과를 작성해 주세요.

1. 제목 후보 3개
2. 가장 적절한 제목 1개 선택 이유
3. 소제목 구조
4. 도입부 초안
5. 각 소제목별 핵심 문장
6. 마무리 문장

답변은 너무 추상적이지 않게, 실제로 블로그 초안으로 바로 옮겨 쓸 수 있을 정도로 구체적으로 작성해 주세요.
읽는 사람이 중간에 이탈하지 않도록 흐름이 자연스럽게 이어지게 해주세요.
```

### 바꿔야 할 부분
- `[주제]`: 예) AI로 블로그 글쓰기, 직장인 아침 루틴, 제품 사용 후기
- `[정보 제공 / 제품 소개 / 경험 공유 / 문제 해결]`: 글 목적 선택
- `[대상 독자]`: 예) AI 초보자, 직장인, 1인 사업자

### 후속 질문 예시
- 위 구조를 유지한 채 도입부를 더 강하게 다시 써줘.
- 소제목은 유지하고, 본문만 더 구체적인 사례 중심으로 확장해줘.

### 수정 요청 예시
- 너무 흔한 블로그 표현은 줄이고 실제 경험이 느껴지게 바꿔줘.
- 모바일에서 읽기 쉽게 문단 길이를 더 짧게 나눠줘.

### 검수 요청 예시
- 이 글 구조에서 빠진 핵심 요소가 있는지 점검해줘.
- 대상 독자가 봤을 때 이해하기 어려운 부분이 있는지 검수해줘.

## 2. 업무 보고서의 기본 구조를 잡고 싶을 때

### 목적
업무 보고서, 기획 메모, 공유 문서를 실무자가 바로 볼 수 있는 형태로 빠르게 정리하기 위한 작업지시서입니다.

### 언제 쓰는지
- 보고서 초안을 처음 만들 때
- 내용을 알고는 있지만 문서 구조가 막힐 때
- 상사나 팀에 공유할 문서를 빠르게 정리해야 할 때

### 바로 복사할 본문
```text
지금 저는 [업무 주제]에 대한 보고서 초안을 정리해야 합니다.
이 문서는 [상사 / 팀원 / 고객 / 이해관계자]가 읽을 예정입니다.
보고 목적은 [현황 공유 / 문제 보고 / 제안 / 실행 계획 정리]입니다.

먼저 이 문서에 꼭 들어가야 할 핵심 항목이 있다면 먼저 질문해 주세요.
그 다음 아래 형식으로 보고서 초안을 작성해 주세요.

1. 한 줄 요약
2. 배경
3. 현재 상황
4. 핵심 이슈
5. 제안 또는 다음 행동

답변은 실무 문서처럼 단정하고 명확하게 정리해 주세요.
불필요하게 장황하지 않게 쓰되, 실제 공유 가능한 수준으로 내용 밀도를 유지해 주세요.
```

### 바꿔야 할 부분
- `[업무 주제]`: 예) 신규 서비스 출시 준비, 고객 문의 대응 현황, 콘텐츠 운영 계획
- `[상사 / 팀원 / 고객 / 이해관계자]`: 실제 독자에 맞게 변경
- `[현황 공유 / 문제 보고 / 제안 / 실행 계획 정리]`: 문서 목적 선택

### 후속 질문 예시
- 이 문서를 임원 보고용으로 더 짧게 다시 정리해줘.
- 핵심 이슈 3개만 먼저 보이도록 요약형 버전도 추가해줘.

### 수정 요청 예시
- 문장을 더 단정하게 바꾸고 군더더기를 줄여줘.
- 읽는 사람이 바로 의사결정할 수 있게 제안 부분을 더 선명하게 써줘.

### 검수 요청 예시
- 이 보고서에서 빠진 핵심 항목이 있는지 점검해줘.
- 상사가 읽었을 때 바로 이해하기 어려운 부분이 있는지 검수해줘.

## 3. 기능 요구사항을 처음 정리하고 싶을 때

### 목적
비개발자도 AI와 함께 기능 요구사항을 정리하고, 개발자에게 전달할 수 있는 수준으로 문서를 만드는 작업지시서입니다.

### 언제 쓰는지
- 만들고 싶은 기능은 있는데 설명이 안 잡힐 때
- 개발 요청 전에 기능 정의를 정리하고 싶을 때
- MVP 범위와 핵심 요소를 먼저 잡아야 할 때

### 바로 복사할 본문
```text
지금 저는 [서비스 또는 화면]에 들어갈 [기능]을 정의하고 싶습니다.
이 기능의 목적은 [사용자 문제 / 운영 효율 / 전환율 개선 / 사용성 개선]입니다.

먼저 이 기능을 정의하기 전에 꼭 확인해야 할 질문이 있다면 먼저 물어봐 주세요.
그 다음 아래 형식으로 기능 요구사항을 정리해 주세요.

1. 이 기능이 해결하려는 문제
2. 사용자가 이 기능을 쓰는 흐름
3. 꼭 필요한 핵심 요소
4. MVP에서 우선 구현할 범위
5. 추후 확장 가능 요소
6. 개발자에게 전달할 수 있는 요구사항 요약

답변은 비개발자도 이해할 수 있게 설명하되, 개발자가 읽어도 바로 작업을 시작할 수 있을 정도로 구체적으로 써주세요.
```

### 바꿔야 할 부분
- `[서비스 또는 화면]`: 예) AI시킴 결과 페이지, 관리자 화면, 결제 페이지
- `[기능]`: 예) 이메일 수집 폼, 결제 버튼, 복사 기능, 필터 기능
- `[사용자 문제 / 운영 효율 / 전환율 개선 / 사용성 개선]`: 기능 목적 입력

### 후속 질문 예시
- 위 기능 정의를 개발자 전달용 문서 형식으로 다시 정리해줘.
- 사용자 흐름을 화면 단위로 더 세분화해서 보여줘.

### 수정 요청 예시
- 너무 추상적인 표현은 줄이고 실제 화면 요소 기준으로 써줘.
- 기술적 설명보다 먼저 사용자 문제와 목적이 보이게 다시 정리해줘.

### 검수 요청 예시
- 이 기능 정의에서 빠진 핵심 요소가 있는지 점검해줘.
- 개발자가 읽었을 때 애매하게 느낄 부분이 있는지 검수해줘.

## 4. 너무 일반적인 답변을 더 구체적으로 바꾸고 싶을 때

### 목적
AI가 방향은 맞지만 지나치게 일반적이거나 뜬구름 잡는 답을 줄 때, 더 실전적인 결과로 바꾸기 위한 수정 작업지시서입니다.

### 언제 쓰는지
- 답변이 맞는 말이지만 써먹기 어려울 때
- 예시나 구체성이 부족할 때
- 결과를 실제 작업에 바로 적용하기 어려울 때

### 바로 복사할 본문
```text
지금 답변은 방향은 맞지만, 너무 일반적이라서 실제로 바로 쓰기 어렵습니다.
막연한 설명보다, 제 상황에 실제로 적용할 수 있는 수준으로 더 구체화해 주세요.

특히 아래 기준으로 다시 써주세요.
1. 추상적인 표현을 줄일 것
2. 실제 예시를 넣을 것
3. 바로 실행 가능한 문장으로 바꿀 것
4. 필요하면 항목을 더 세분화할 것

가능하면 "설명"보다 "실제로 바로 쓸 수 있는 결과" 중심으로 다시 정리해 주세요.
```

### 바꿔야 할 부분
- 필요하면 위 작업지시서 아래에 현재 AI 답변을 함께 붙여 넣기

### 후속 질문 예시
- 위 답변을 내 상황에 맞는 예시 중심으로 한 번 더 바꿔줘.
- 지금 버전에서 실제로 바로 쓸 수 있는 문장만 따로 뽑아줘.

### 수정 요청 예시
- 설명형 문장을 줄이고 실제 표현으로 다시 써줘.
- 너무 넓은 범위의 조언은 빼고 우선순위가 높은 것만 남겨줘.

### 검수 요청 예시
- 여전히 추상적인 부분이 있는지 점검해줘.
- 이 결과를 초보자가 바로 써먹을 수 있는 수준인지 검수해줘.

## 5. AI 작업을 어떤 순서로 시작해야 할지 모르겠을 때

### 목적
AI를 쓰고 싶지만 첫 질문, 후속 질문, 수정 요청, 검수 질문의 흐름이 안 잡힐 때 전체 설계부터 잡기 위한 작업지시서입니다.

### 언제 쓰는지
- AI를 처음 써볼 때
- 무엇부터 물어봐야 할지 전혀 감이 안 올 때
- 한 번 질문으로 끝나지 않는 작업을 설계하고 싶을 때

### 바로 복사할 본문
```text
지금 저는 [하고 싶은 작업]을 AI로 진행하고 싶습니다.
하지만 무엇부터 어떤 순서로 시켜야 할지 잘 모르겠습니다.

먼저 이 작업을 잘 진행하기 위해 꼭 확인해야 할 질문을 먼저 해주세요.
그 다음 아래 형식으로 전체 작업 흐름을 설계해 주세요.

1. 첫 질문에서 확인해야 할 것
2. 첫 결과를 받은 뒤 이어서 물어볼 후속 질문
3. 결과가 마음에 안 들 때 수정 요청하는 방법
4. 마지막에 품질을 높이기 위한 검수 질문
5. 사용자가 흔히 놓치는 포인트

답변은 처음 해보는 사람도 그대로 따라갈 수 있게 단계별로 설명해 주세요.
가능하면 각 단계마다 바로 복사해서 쓸 문장 예시도 함께 붙여 주세요.
```

### 바꿔야 할 부분
- `[하고 싶은 작업]`: 예) 블로그 글쓰기, 보고서 작성, 기능 정의, 판매 문구 만들기

### 후속 질문 예시
- 위 흐름을 더 짧게 핵심 단계만 남겨서 다시 정리해줘.
- 각 단계에서 실패하기 쉬운 포인트까지 같이 알려줘.

### 수정 요청 예시
- 설명형 문장을 줄이고 실제 복사해서 쓸 문장 중심으로 다시 정리해줘.
- 단계별 목적이 더 분명하게 보이도록 순서를 다시 다듬어줘.

### 검수 요청 예시
- 이 흐름에서 빠진 핵심 단계가 있는지 점검해줘.
- 초보자가 따라가다가 막힐 만한 구간이 있는지 검수해줘.
