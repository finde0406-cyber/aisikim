# AI시킴 스타터팩 대표 5개 프리미엄 초안 v2-b

## 1. 문서 목적
이 문서는 스타터팩 우선 제작 15개 중 2단계 대표 5개를 `실제 판매 기준`에 맞춰 고도화한 프리미엄 초안입니다.  
1단계 프리미엄 초안과 함께, 사용자가 “상황에 따라 꺼내 쓰는 유료 도구 세트”처럼 느끼게 만드는 것을 목표로 합니다.

## 2. 이 문서의 사용 방식
- 결과가 아예 없는 상태보다, 이미 초안이 있거나 방향은 있는 상태에서 더 강하게 체감됩니다.
- `바로 복사할 본문`으로 시작합니다.
- 원하는 방향이 더 선명해지면 `후속 질문`으로 확장합니다.
- 결과가 어중간하면 `수정 요청`으로 압축합니다.
- 마지막에 `검수 요청`으로 마감 품질을 끌어올립니다.

## 1. 글 제목 후보를 여러 방향으로 뽑고 싶을 때

### 한 줄 설명
하나의 주제로 서로 다른 결의 제목을 빠르게 비교하고, 가장 잘 먹히는 방향을 고르는 제목 확장형 작업지시서입니다.

### 이런 상황에서 특히 잘 맞습니다
- 제목이 너무 평범하게 느껴질 때
- 같은 주제로 정보형, 클릭형, 실전형 제목을 비교하고 싶을 때
- 글 구조는 있는데 제목만 약할 때

### 이 작업지시서로 기대할 수 있는 결과
- 성격이 다른 제목 후보 7개
- 각 제목의 방향 차이
- 가장 추천하는 제목 1개와 이유
- 이후 소제목 확장 포인트

### 언제 쓰는지
- 초안 작성 전 제목 브레인스토밍 단계
- 글 구조는 있는데 제목을 못 고르겠는 시점

### 바로 복사할 본문
```text
지금 저는 [주제]에 대한 글을 쓰려고 합니다.
이 글의 목적은 [정보 제공 / 제품 소개 / 경험 공유 / 문제 해결]입니다.
읽을 대상은 [대상 독자]이며, 이 독자가 가장 끌릴 만한 포인트는 [관심 포인트]입니다.

아래 기준으로 제목 후보를 7개 제안해 주세요.

1. 정보형 제목
2. 문제 해결형 제목
3. 경험 공유형 제목
4. 호기심 유도형 제목
5. 비교/대조형 제목
6. 실전 팁형 제목
7. 가장 추천하는 제목 1개와 그 이유

제목은 너무 자극적이지 않되, 읽는 사람이 클릭할 이유가 보이게 써주세요.
가능하면 각 제목의 성격 차이도 짧게 설명해 주세요.
검색 유입과 클릭 유도의 균형도 함께 고려해 주세요.
```

### 바꿔야 할 부분
- `[주제]`: 예) AI시킴 사용법, 직장인 업무 자동화
- `[정보 제공 / 제품 소개 / 경험 공유 / 문제 해결]`: 글 목적
- `[대상 독자]`: 예) AI 초보자, 직장인, 1인 사업자
- `[관심 포인트]`: 예) 시간 절약, 쉬운 시작, 실전 활용

### 후속 질문
- 위 제목 중 1번과 4번 방향으로 각각 3개씩 더 뽑아줘.
- 가장 추천한 제목을 기준으로 소제목 구조도 같이 제안해줘.

### 수정 요청
- 너무 흔한 표현은 줄이고 더 신선한 표현으로 바꿔줘.
- 클릭 유도는 유지하되 과장된 느낌은 줄여줘.

### 검수 요청
- 이 제목들이 대상 독자에게 실제로 매력적으로 보일지 검수해줘.
- 검색 유입과 클릭 유도 측면에서 아쉬운 제목이 있다면 바꿔줘.

### 자주 하는 실수
- 독자 없이 제목만 뽑아달라고 한다
- 제목의 방향 차이를 안 나눠서 비슷한 것만 받는다
- 제목만 받고 끝내고 구조까지 안 이어간다

### 이 순서에서 쓰면 좋습니다
1. 블로그 초안 생성형으로 구조를 만든다
2. 이 작업지시서로 제목을 강화한다
3. 독자 맞춤 수정형으로 본문 톤을 다듬는다

### 사용 팁
제목은 글의 입구입니다.  
좋은 본문도 제목이 약하면 클릭되지 않으므로, 제목은 별도 작업지시서로 따로 다루는 편이 훨씬 낫습니다.

## 2. 상사 보고용 요약본을 짧게 만들고 싶을 때

### 한 줄 설명
긴 문서나 정리 메모를 상사가 30초 안에 이해할 수 있는 보고형 요약본으로 압축하는 작업지시서입니다.

### 이런 상황에서 특히 잘 맞습니다
- 이미 긴 문서가 있는데 핵심만 보고해야 할 때
- 임원/상사 보고 전에 핵심 정리가 필요할 때
- 문서는 있지만 판단 포인트가 흐릴 때

### 이 작업지시서로 기대할 수 있는 결과
- 한 줄 요약
- 핵심 이슈 3개
- 판단 포인트
- 요청 사항 또는 다음 행동

### 언제 쓰는지
- 초안이 이미 있을 때
- 공유 전 `압축본`이 필요할 때

### 바로 복사할 본문
```text
아래 내용은 현재 [보고서 / 기획서 / 메모 / 회의 정리]의 전체 초안입니다.
이 내용을 [상사 / 임원 / 팀 리더]가 빠르게 이해할 수 있도록 짧은 요약본으로 다시 정리해 주세요.

정리 기준은 아래와 같습니다.
1. 한 줄 요약
2. 지금 가장 중요한 핵심 이슈 3개
3. 바로 판단해야 할 포인트
4. 다음 행동 또는 요청 사항

문장은 짧고 단정하게 써주세요.
읽는 사람이 30초 안에 전체 맥락을 파악할 수 있게 정리해 주세요.
설명보다 판단이 쉬운 구조를 우선해 주세요.
```

### 바꿔야 할 부분
- `[보고서 / 기획서 / 메모 / 회의 정리]`: 원문 성격
- `[상사 / 임원 / 팀 리더]`: 실제 독자
- 아래에 실제 원문 붙여 넣기

### 후속 질문
- 위 요약본을 더 짧게 5문장 안으로 줄여줘.
- 지금 버전을 유지하되 보고용 어조를 더 단정하게 바꿔줘.

### 수정 요청
- 설명형 문장을 줄이고 판단 포인트가 먼저 보이게 바꿔줘.
- 읽는 사람이 바로 결정할 수 있게 요청 사항을 더 선명하게 써줘.

### 검수 요청
- 이 요약본만 읽어도 맥락이 충분히 보이는지 검수해줘.
- 빠진 핵심 정보가 있다면 최소 범위에서 보완해줘.

### 자주 하는 실수
- 원문을 너무 많이 압축해서 맥락이 사라진다
- 핵심 이슈와 요청 사항을 분리하지 않는다
- 독자의 역할에 따라 요약 방식이 달라져야 한다는 점을 놓친다

### 이 순서에서 쓰면 좋습니다
1. 보고서 초안 생성형으로 기본 구조를 만든다
2. 이 작업지시서로 요약본을 만든다
3. 제출 전 검수형으로 최종 확인한다

### 사용 팁
보고용 요약본은 “잘 쓴 요약”보다 “의사결정하기 쉬운 요약”이 더 중요합니다.

## 3. 개발자에게 전달할 작업 지시문을 만들고 싶을 때

### 한 줄 설명
기획자나 운영자가 떠올린 요구사항을 개발자가 오해 없이 착수할 수 있는 작업 지시문으로 바꾸는 작업지시서입니다.

### 이런 상황에서 특히 잘 맞습니다
- 슬랙, 노션, 티켓에 올릴 개발 요청이 필요할 때
- 기능은 정했지만 전달 문장이 막막할 때
- 비개발자가 개발자와 협업할 때

### 이 작업지시서로 기대할 수 있는 결과
- 작업 목적
- 해결하려는 문제
- 작업 범위
- 핵심 요구사항
- 제외 범위
- 완료 후 기대 상태

### 언제 쓰는지
- 개발 요청 직전
- 문서화가 필요한 협업 단계

### 바로 복사할 본문
```text
지금 저는 [서비스 / 화면 / 기능]에 대해 개발자에게 작업 요청을 해야 합니다.
현재 제가 이해하고 있는 목적은 [사용자 문제 / 전환율 개선 / 운영 효율 / 사용성 개선]입니다.
특히 이번 요청에서 가장 중요한 것은 [핵심 동작 / 사용자 흐름 / 구현 우선순위 / 완료 기준]입니다.

먼저 개발자가 이해하기 위해 부족한 정보가 있다면 먼저 질문해 주세요.
그 다음 아래 형식으로 개발자 전달용 작업 지시문을 작성해 주세요.

1. 작업 목적
2. 해결하려는 문제
3. 작업 범위
4. 꼭 필요한 요구사항
5. 제외해도 되는 범위
6. 완료 후 기대 상태

문장은 애매하지 않게 써주세요.
비개발자가 읽어도 이해할 수 있어야 하지만, 개발자가 읽었을 때 바로 착수 가능한 수준으로 정리해 주세요.
모호한 표현보다 실제 동작이 떠오르는 표현을 우선해 주세요.
```

### 바꿔야 할 부분
- `[서비스 / 화면 / 기능]`: 예) AI시킴 이메일 수집 폼
- `[사용자 문제 / 전환율 개선 / 운영 효율 / 사용성 개선]`: 실제 목적
- `[핵심 동작 / 사용자 흐름 / 구현 우선순위 / 완료 기준]`: 우선 포인트

### 후속 질문
- 위 작업 지시문을 티켓 등록용 형태로 더 짧게 다시 써줘.
- 완료 기준이 더 명확하게 보이도록 다시 정리해줘.

### 수정 요청
- 너무 추상적인 표현은 줄이고 실제 동작 기준으로 써줘.
- 개발 범위와 제외 범위를 더 선명하게 나눠줘.

### 검수 요청
- 개발자가 읽었을 때 애매하게 느낄 부분이 있는지 검수해줘.
- 빠진 요구사항이 있다면 최소한으로 보완해줘.

### 자주 하는 실수
- “이거 만들어줘” 식으로 목적 없이 요청한다
- 완료 상태를 정의하지 않는다
- 제외 범위를 안 적어서 요청 범위가 계속 커진다

### 이 순서에서 쓰면 좋습니다
1. 기능 정의형으로 문제와 흐름을 정리한다
2. 이 작업지시서로 전달 문서를 만든다
3. 구현안이 나온 뒤 개선 요청형으로 이어간다

### 사용 팁
개발자 전달 문서는 “예쁘게 써진 설명”보다 “오해 없이 일 시작할 수 있는 문장”이 더 중요합니다.

## 4. 방향은 맞지만 완성도가 낮은 결과를 다듬고 싶을 때

### 한 줄 설명
결과의 뼈대는 맞지만 밀도와 설득력이 약한 초안을, 제출 가능한 수준으로 끌어올리는 고도화형 작업지시서입니다.

### 이런 상황에서 특히 잘 맞습니다
- 초안은 나왔지만 완성도가 아쉬울 때
- 구조는 맞는데 문장이 약할 때
- “거의 맞는데 뭔가 부족하다”는 느낌이 들 때

### 이 작업지시서로 기대할 수 있는 결과
- 약한 부분 진단
- 구조 보완 포인트
- 더 설득력 있는 보완본
- 최종 제출 수준의 개선본

### 언제 쓰는지
- 초안 이후 2차 개선 단계
- 무료 결과보다 확실히 더 좋은 결과를 만들고 싶을 때

### 바로 복사할 본문
```text
아래 결과물은 방향 자체는 맞지만, 아직 완성도가 부족합니다.
다시 처음부터 새로 쓰기보다, 현재 결과를 기반으로 무엇을 보완하면 더 좋아지는지 먼저 짚어주세요.

특히 아래 기준으로 점검해 주세요.
1. 구조는 맞지만 약한 부분
2. 더 구체적으로 써야 하는 부분
3. 빠져 있는 핵심 요소
4. 읽는 사람이 덜 설득될 수 있는 부분
5. 지금 상태에서 가장 먼저 고치면 좋아지는 한 가지

그 다음 아래 방식으로 답변해 주세요.
1. 현재 결과의 약한 부분 요약
2. 수정 방향
3. 보완한 최종본

최종본은 바로 제출하거나 공유할 수 있는 수준으로 다듬어 주세요.
가능하면 수정 이유도 짧게 설명해 주세요.
```

### 바꿔야 할 부분
- 아래에 현재 결과물 원문 붙여 넣기
- 필요 시 독자나 제출 목적 한 줄 추가

### 후속 질문
- 보완본을 유지한 채 더 짧고 강한 버전도 하나 추가해줘.
- 지금 수정본에서 가장 약한 한 부분만 한 번 더 다듬어줘.

### 수정 요청
- 표현은 유지하되 더 설득력 있게 다시 써줘.
- 추상적인 문장은 줄이고 실제 표현으로 다시 정리해줘.

### 검수 요청
- 이 결과가 처음보다 실제로 더 완성도 있게 보이는지 검수해줘.
- 여전히 약한 부분이 있다면 마지막으로 한 번 더 짚어줘.

### 자주 하는 실수
- 현재 결과물을 같이 붙이지 않는다
- 무엇이 약한지 먼저 안 짚고 “그냥 더 좋게”만 요청한다
- 제출 기준이 무엇인지 안 적는다

### 이 순서에서 쓰면 좋습니다
1. 초안 생성형으로 기본 결과를 만든다
2. 이 작업지시서로 고도화한다
3. 최종 검수형으로 제출 전 점검한다

### 사용 팁
고도화는 “새로 쓰기”보다 “무엇이 약한지 짚고 보완하기”가 훨씬 잘 먹힙니다.

## 5. 첫 질문을 더 잘 시작하고 싶을 때

### 한 줄 설명
첫 질문의 질을 올려서 이후 AI 답변 품질을 끌어올리는 첫 질문 최적화형 작업지시서입니다.

### 이런 상황에서 특히 잘 맞습니다
- 항상 첫 답변이 뻔하게 나올 때
- 무엇부터 물어봐야 할지 감이 안 올 때
- 내 상황 설명을 더 잘 반영하고 싶을 때

### 이 작업지시서로 기대할 수 있는 결과
- 첫 질문에 꼭 들어가야 할 요소
- 좋지 않은 질문 예시
- 더 나은 질문 예시
- 바로 복사할 최종 질문 1개

### 언제 쓰는지
- 작업 시작 직전
- AI 결과가 자꾸 밋밋하게 나오는 패턴이 반복될 때

### 바로 복사할 본문
```text
지금 저는 [하고 싶은 작업]을 AI에게 요청하려고 합니다.
그런데 첫 질문을 어떻게 시작해야 결과가 더 좋아질지 잘 모르겠습니다.

먼저 이 작업에서 첫 질문에 꼭 들어가야 할 핵심 요소를 정리해 주세요.
그 다음 아래 순서로 결과를 만들어 주세요.

1. 첫 질문에 꼭 들어가야 할 요소
2. 좋지 않은 질문 예시
3. 더 나은 질문 예시
4. 내 상황에 맞게 바로 복사해서 쓸 최종 질문 1개

답변은 초보자도 바로 이해할 수 있게 설명해 주세요.
최종 질문은 너무 길지 않되, 결과 품질에 중요한 요소는 빠지지 않게 정리해 주세요.
가능하면 "왜 이 질문이 더 좋은지"도 짧게 설명해 주세요.
```

### 바꿔야 할 부분
- `[하고 싶은 작업]`: 예) 블로그 글쓰기, 보고서 작성, 기능 정의

### 후속 질문
- 위 최종 질문을 더 짧고 명확하게 다시 줄여줘.
- 같은 목적이지만 더 전문가적인 어조로 시작하는 질문도 하나 추가해줘.

### 수정 요청
- 설명형 부분은 줄이고 실제 복사해서 쓸 질문 문장에 더 집중해줘.
- 내 상황 설명이 더 잘 반영되게 다시 써줘.

### 검수 요청
- 이 첫 질문만으로도 충분히 좋은 출발점이 되는지 검수해줘.
- 빠진 핵심 정보가 있다면 최소한으로 보완해줘.

### 자주 하는 실수
- 목적 없이 “이거 해줘” 식으로 시작한다
- 결과물 형식과 대상 독자를 안 넣는다
- 첫 답변이 약한 이유를 질문 구조에서 찾지 않는다

### 이 순서에서 쓰면 좋습니다
1. 이 작업지시서로 첫 질문을 만든다
2. 초안 생성형 작업지시서로 들어간다
3. 이후 수정 요청형과 검수형으로 이어간다

### 사용 팁
첫 질문만 좋아져도 전체 작업 시간이 크게 줄어듭니다.  
좋은 첫 질문은 “짧아서 좋은 질문”이 아니라 “핵심 정보가 빠지지 않은 질문”입니다.

## 마지막 메모
이 5개는 스타터팩 대표 10개 중 `정교한 중간층` 역할을 합니다.  
1단계 프리미엄 초안이 시작점을 잡아준다면, 이 문서는 `확장`, `압축`, `전달`, `고도화`, `질문 최적화`를 담당합니다.  
이 수준까지 올라와야 사용자가 “이건 그냥 문장 모음이 아니라 실제로 계속 꺼내 쓸 자료다”라고 느낄 수 있습니다.
