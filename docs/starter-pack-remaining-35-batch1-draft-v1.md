# AI시킴 스타터팩 나머지 35개 1차 초안 v1

## 1. 문서 목적
이 문서는 스타터팩 나머지 35개 중에서 우선 체감 가치가 높고, 실제 판매 시 자주 꺼내 쓰게 될 가능성이 큰 항목들을 먼저 작성한 1차 실물 초안입니다.  
코어 15를 보완하면서 스타터팩 전체를 실제 판매 가능한 수준으로 확장하기 위한 문서입니다.

## 2. 이번 1차 초안에 포함한 항목
1. 블로그 도입부를 더 강하게 쓰고 싶을 때
2. 블로그 글의 마무리와 CTA를 더 좋게 쓰고 싶을 때
3. 보고서 목차를 더 설득력 있게 만들고 싶을 때
4. 회의록을 실무 문서로 정리하고 싶을 때
5. UI 수정 요청을 더 구체적으로 하고 싶을 때
6. 길기만 한 결과물을 더 짧고 명확하게 만들고 싶을 때
7. 내 상황을 AI에게 설명하는 문장을 만들고 싶을 때

---

## 1. 블로그 도입부를 더 강하게 쓰고 싶을 때

### 한 줄 설명
이미 정한 주제와 구조는 유지하되, 첫 문단에서 독자의 시선을 더 강하게 잡고 공감을 높이기 위한 도입부 강화형 작업지시서입니다.

### 이럴 때 가장 먼저 꺼내 쓰세요
- 제목과 본문 방향은 괜찮은데 첫 3~5문장이 약할 때
- 글 전체를 갈아엎고 싶지는 않지만 시작 구간의 흡입력만 높이고 싶을 때

### 이 항목이 다른 항목과 다른 점
이 항목은 글 전체 구조나 소제목을 다시 짜는 용도가 아니라, `독자가 읽기 시작하는 첫 진입 구간`만 집중적으로 강화하는 데 목적이 있습니다.

### 이런 상황에서 특히 잘 맞습니다
- 제목과 소제목은 괜찮은데 첫 문단이 밋밋할 때
- 도입부에서 독자의 문제를 충분히 건드리지 못할 때
- 클릭은 됐는데 읽기 시작 부분이 약할 때

### 이 작업지시서로 기대할 수 있는 결과
- 더 강한 첫 문장
- 독자 공감이 살아 있는 도입부
- 문제 제기와 기대 결과가 선명한 시작 구간

### 언제 쓰는지
- 글 구조가 나온 뒤 도입부를 다듬는 단계
- 초안 작성 후 “첫 문단이 약하다”는 느낌이 들 때

### 바로 복사할 본문
```text
아래는 제가 작성하려는 글의 제목과 구조입니다.
전체 흐름은 유지하되, 도입부만 더 강하게 다시 써주세요.

이번 글의 주제는 [주제]이고,
대상 독자는 [대상 독자]입니다.
이 독자가 가장 자주 느끼는 문제는 [핵심 문제]입니다.
이 글을 읽고 나면 독자가 얻어가야 하는 핵심은 [얻어가야 할 결과]입니다.

도입부는 아래 기준으로 다시 써주세요.
1. 첫 문장에서 독자의 문제를 더 분명하게 건드릴 것
2. 너무 추상적인 설명은 줄일 것
3. 독자가 "이 글은 나한테 필요하다"는 느낌을 빨리 받게 할 것
4. 글을 끝까지 읽고 싶게 만드는 흐름을 만들 것

답변은 아래 순서로 주세요.
1. 더 강한 첫 문장 3개
2. 그중 가장 추천하는 1개와 이유
3. 다듬은 도입부 최종본
```

### 바꿔야 할 부분
- `[주제]`
- `[대상 독자]`
- `[핵심 문제]`
- `[얻어가야 할 결과]`

### 후속 질문
- 위 도입부를 더 짧고 강하게 줄여줘.
- 같은 내용인데 더 친근한 말투 버전도 하나 추가해줘.

### 수정 요청
- 공감 표현은 유지하되 과장된 느낌은 줄여줘.
- 읽는 속도가 빨라지도록 문장을 더 짧게 나눠줘.

### 검수 요청
- 이 도입부가 대상 독자의 문제를 충분히 건드리는지 검수해줘.
- 첫 문장과 그 다음 문단 연결이 자연스러운지 점검해줘.

### 사용 팁
도입부는 글의 내용을 요약하는 자리보다, 독자에게 “계속 읽을 이유”를 주는 자리로 보는 것이 좋습니다.

## 2. 블로그 글의 마무리와 CTA를 더 좋게 쓰고 싶을 때

### 한 줄 설명
글 전체 흐름은 완성됐지만 마무리가 힘없이 끝날 때, 독자가 다음 행동을 하도록 돕는 마감 문장과 CTA를 강화하는 작업지시서입니다.

### 이런 상황에서 특히 잘 맞습니다
- 글이 끝나긴 하지만 여운이나 행동 유도가 약할 때
- 제품 소개/서비스 소개 글에서 CTA가 어색할 때
- 정보형 글도 마지막이 흐리게 끝날 때

### 이 작업지시서로 기대할 수 있는 결과
- 더 자연스러운 마무리 문장
- 과하지 않은 CTA
- 독자가 다음 행동을 이해하기 쉬운 끝부분

### 언제 쓰는지
- 글 최종 마감 단계
- 게시 직전 마무리 보완 단계

### 바로 복사할 본문
```text
아래 글 초안은 전체 구조는 괜찮지만, 마지막 마무리와 CTA가 약합니다.
전체 글의 목적은 [정보 제공 / 경험 공유 / 서비스 소개 / 제품 소개]입니다.
독자가 글을 다 읽은 뒤 했으면 하는 다음 행동은 [댓글 / 문의 / 신청 / 구매 / 저장 / 공유]입니다.

마무리 구간을 아래 기준으로 다시 써주세요.
1. 앞에서 다룬 핵심 내용을 짧게 정리할 것
2. 억지스럽지 않게 다음 행동으로 이어질 것
3. 정보형 글이면 신뢰감 있게, 판매형 글이면 부담 없이 행동을 유도할 것
4. 너무 흔한 마무리 표현은 줄일 것

답변은 아래 순서로 주세요.
1. 마무리 문장 2가지 버전
2. CTA 문장 3가지 버전
3. 둘을 합친 최종 마무리 블록
```

### 바꿔야 할 부분
- `[정보 제공 / 경험 공유 / 서비스 소개 / 제품 소개]`
- `[댓글 / 문의 / 신청 / 구매 / 저장 / 공유]`

### 후속 질문
- CTA는 더 부드럽게 바꾸고, 마무리 문장은 더 신뢰감 있게 다시 써줘.
- 정보형 글 기준으로 판매 느낌을 더 줄인 버전도 하나 추가해줘.

### 수정 요청
- CTA를 더 짧고 자연스럽게 바꿔줘.
- 글 전체 톤과 맞지 않는 표현은 줄여줘.

### 검수 요청
- 이 마무리가 글 전체 흐름과 잘 맞는지 검수해줘.
- CTA가 과하거나 갑작스럽게 느껴지는 부분이 있는지 점검해줘.

### 사용 팁
마무리는 새로운 내용을 추가하는 곳이 아니라, 독자가 다음 행동을 편하게 선택할 수 있도록 정리하는 곳입니다.

## 3. 보고서 목차를 더 설득력 있게 만들고 싶을 때

### 한 줄 설명
보고서나 기획서 초안이 있는데 목차 흐름이 약할 때, 읽는 사람이 더 빨리 이해하고 설득되도록 목차를 재구성하는 작업지시서입니다.

### 이럴 때 가장 먼저 꺼내 쓰세요
- 본문을 쓰기 전에 문서의 뼈대부터 설득력 있게 정리해야 할 때
- 보고서 내용을 손보기보다 `무슨 순서로 읽히게 할지`가 먼저 중요할 때

### 이 항목이 다른 항목과 다른 점
이 항목은 기획서 본문을 채우는 작업이 아니라, `읽는 사람의 이해 순서와 의사결정 흐름`에 맞게 목차를 재배열하는 데 집중합니다.

### 이런 상황에서 특히 잘 맞습니다
- 내용은 있는데 목차 순서가 어색할 때
- 목차만 봐도 무엇을 말하려는지 드러나지 않을 때
- 상사나 의사결정자가 빠르게 이해하게 만들고 싶을 때

### 이 작업지시서로 기대할 수 있는 결과
- 더 설득력 있는 목차 구조
- 중요 내용 우선 배치
- 읽는 흐름이 살아 있는 문서 구조

### 언제 쓰는지
- 보고서 초안 작성 초반
- 본문 쓰기 전 목차 정리 단계

### 바로 복사할 본문
```text
지금 저는 [문서 주제]에 대한 [보고서 / 기획서 / 제안서]를 작성하고 있습니다.
현재 초안은 있는데, 목차 순서와 흐름이 아직 설득력 있게 잡히지 않았습니다.
이 문서를 읽을 사람은 [상사 / 고객 / 팀 리더 / 의사결정자]입니다.
이 사람이 가장 먼저 이해해야 하는 것은 [핵심 이슈 / 제안 / 방향 / 요청 사항]입니다.

먼저 이 문서에서 가장 먼저 보여야 할 논리 흐름이 무엇인지 짚어주세요.
그 다음 아래 기준으로 목차를 다시 제안해 주세요.

1. 읽는 사람이 빠르게 이해할 수 있는 순서
2. 중요도가 높은 내용이 먼저 보이는 구조
3. 중복되거나 약한 항목은 정리
4. 문서 목적과 잘 맞는 흐름

답변은 아래 순서로 주세요.
1. 현재 목차가 약한 이유
2. 추천 목차 구조
3. 각 목차 항목에 들어갈 핵심 한 줄
```

### 바꿔야 할 부분
- `[문서 주제]`
- `[보고서 / 기획서 / 제안서]`
- `[상사 / 고객 / 팀 리더 / 의사결정자]`
- `[핵심 이슈 / 제안 / 방향 / 요청 사항]`

### 후속 질문
- 위 목차를 임원 보고용으로 더 짧게 압축해줘.
- 실무자용 상세 버전 목차도 따로 만들어줘.

### 수정 요청
- 목차 이름을 더 실무적으로 바꿔줘.
- 읽는 사람이 바로 핵심을 파악하기 쉬운 표현으로 수정해줘.

### 검수 요청
- 이 목차만 봐도 문서 목적이 충분히 드러나는지 검수해줘.
- 흐름상 어색하거나 순서를 바꾸는 게 더 좋은 항목이 있는지 점검해줘.

### 사용 팁
좋은 목차는 예쁘게 나열된 항목이 아니라, 읽는 사람이 “어떤 논리로 읽어야 하는지”를 미리 보여주는 구조입니다.

## 4. 회의록을 실무 문서로 정리하고 싶을 때

### 한 줄 설명
메모 수준의 회의 내용을 실제 실행 가능한 실무 문서로 바꾸는 회의록 정리형 작업지시서입니다.

### 이런 상황에서 특히 잘 맞습니다
- 회의 메모는 있는데 공유용 문서가 안 나올 때
- 누가 무엇을 해야 하는지 정리가 안 될 때
- 회의 후 액션 아이템이 흐려질 때

### 이 작업지시서로 기대할 수 있는 결과
- 회의 목적 요약
- 결정 사항
- 미결 사항
- 담당자별 액션 아이템

### 언제 쓰는지
- 회의 직후
- 팀 공유 문서 정리 단계

### 바로 복사할 본문
```text
아래는 회의 중 메모해둔 내용입니다.
이 내용을 팀이 실제로 바로 이해하고 움직일 수 있는 실무형 회의록으로 정리해 주세요.

회의 목적은 [회의 목적]이고,
참여자는 [참여자 성격 또는 역할]입니다.
이 회의에서 가장 중요한 것은 [결정 사항 / 미결 사항 / 다음 액션]입니다.

아래 형식으로 정리해 주세요.
1. 회의 목적 한 줄 요약
2. 핵심 논의 내용
3. 결정된 사항
4. 아직 미결정인 사항
5. 다음 액션 아이템
6. 담당자 또는 확인 필요 주체

답변은 길게 풀어쓰기보다, 실제 공유 문서처럼 바로 전달 가능한 형태로 정리해 주세요.
모호한 표현보다 누가 봐도 이해되는 구조를 우선해 주세요.
```

### 바꿔야 할 부분
- `[회의 목적]`
- `[참여자 성격 또는 역할]`
- `[결정 사항 / 미결 사항 / 다음 액션]`

### 후속 질문
- 이 회의록을 상사 공유용으로 더 짧게 다시 정리해줘.
- 액션 아이템만 별도 체크리스트 형태로 다시 뽑아줘.

### 수정 요청
- 논의 내용은 줄이고, 결정과 액션이 더 선명하게 보이게 바꿔줘.
- 담당자와 일정이 더 잘 보이게 구조를 다시 정리해줘.

### 검수 요청
- 이 회의록만 봐도 누가 무엇을 해야 하는지 충분히 보이는지 검수해줘.
- 빠진 핵심 결정 사항이 있다면 짚어줘.

### 사용 팁
회의록은 회의 내용을 “기록”하는 문서보다, 회의 이후 “행동”이 가능하게 만드는 문서로 보는 것이 좋습니다.

## 5. UI 수정 요청을 더 구체적으로 하고 싶을 때

### 한 줄 설명
막연한 디자인 피드백을 실제 수정 가능한 UI 요청 문장으로 바꾸는 작업지시서입니다.

### 이런 상황에서 특히 잘 맞습니다
- “뭔가 어색한데” 수준에서 더 구체적인 요청이 필요할 때
- 디자이너나 개발자에게 UI 수정 방향을 전달해야 할 때
- 색감, 간격, 위계, CTA 등 어느 부분이 문제인지 잘 정리되지 않을 때

### 이 작업지시서로 기대할 수 있는 결과
- 현재 UI 문제 진단
- 수정 우선순위
- 실제 전달 가능한 UI 수정 요청 문장

### 언제 쓰는지
- 화면 초안 검토 후
- 구현물 개선 요청 단계

### 바로 복사할 본문
```text
현재 UI를 보니 방향은 맞지만, 수정 요청을 더 구체적으로 정리하고 싶습니다.
이번 화면의 목적은 [전환 / 정보 전달 / 탐색 / 신청 / 구매 유도]입니다.
특히 사용자 입장에서 가장 중요한 요소는 [CTA / 정보 위계 / 가독성 / 신뢰감 / 모바일 사용성]입니다.

먼저 현재 UI에서 가장 먼저 손봐야 할 문제를 짚어주세요.
그 다음 아래 형식으로 수정 요청 문장을 정리해 주세요.

1. 현재 문제 요약
2. 왜 문제가 되는지
3. 우선 수정해야 할 부분 3개
4. 개발자/디자이너에게 전달할 수 있는 실제 수정 요청 문장

답변은 취향보다 사용자 경험 관점에서 정리해 주세요.
가능하면 "무엇을 어떻게 바꾸면 더 좋아지는지"가 바로 보이게 써주세요.
```

### 바꿔야 할 부분
- `[전환 / 정보 전달 / 탐색 / 신청 / 구매 유도]`
- `[CTA / 정보 위계 / 가독성 / 신뢰감 / 모바일 사용성]`

### 후속 질문
- 위 수정 요청 중 가장 효과가 큰 2개만 우선순위로 다시 정리해줘.
- 모바일 기준으로만 봤을 때 수정 요청 문장도 다시 써줘.

### 수정 요청
- 취향성 표현은 줄이고, 사용자 행동 기준으로 다시 써줘.
- 너무 추상적인 말 대신 실제 화면 요소 기준으로 바꿔줘.

### 검수 요청
- 이 수정 요청만 전달해도 상대가 실제로 손볼 수 있는 수준인지 검수해줘.
- 빠진 핵심 개선 포인트가 있다면 보완해줘.

### 사용 팁
좋은 UI 피드백은 “별로다”가 아니라 “어느 요소가 왜 문제인지, 그래서 무엇을 바꾸면 좋은지”가 함께 있어야 합니다.

## 6. 길기만 한 결과물을 더 짧고 명확하게 만들고 싶을 때

### 한 줄 설명
정보는 있는데 장황한 결과물을 핵심 위주로 다시 정리해 읽기 쉬운 결과로 바꾸는 압축형 작업지시서입니다.

### 이런 상황에서 특히 잘 맞습니다
- AI가 너무 길게 답해서 바로 못 쓸 때
- 핵심보다 설명이 많은 결과가 나왔을 때
- 공유용/보고용으로 더 짧은 버전이 필요할 때

### 이 작업지시서로 기대할 수 있는 결과
- 핵심만 남긴 요약본
- 읽기 쉬운 구조
- 짧지만 빠지지 않은 결과물

### 언제 쓰는지
- 초안 이후 압축 단계
- 공유용/보고용 짧은 버전 필요 시

### 바로 복사할 본문
```text
아래 결과물은 정보는 있지만 너무 길어서 실제로 바로 쓰기 어렵습니다.
핵심은 유지하되 더 짧고 명확한 형태로 다시 정리해 주세요.

아래 기준으로 압축해 주세요.
1. 중복되는 설명은 줄일 것
2. 꼭 필요한 핵심만 남길 것
3. 읽는 사람이 빠르게 이해할 수 있게 구조를 정리할 것
4. 너무 설명형인 문장은 줄일 것

답변은 아래 순서로 주세요.
1. 지금 결과에서 줄여도 되는 부분
2. 핵심만 남긴 요약본
3. 필요하면 3~5줄짜리 초압축 버전

짧게 만드는 것이 목적이지만, 핵심 내용이 빠지면 안 됩니다.
```

### 바꿔야 할 부분
- 아래에 현재 AI 결과 원문 붙여 넣기

### 후속 질문
- 이 요약본을 상사 공유용 톤으로 더 단정하게 바꿔줘.
- 지금 버전에서 한 문장 요약도 하나 추가해줘.

### 수정 요청
- 짧게는 유지하되 너무 건조하지 않게 다시 써줘.
- 핵심만 남기되 이해에 필요한 연결 문장은 보완해줘.

### 검수 요청
- 이 압축본이 원문 핵심을 충분히 담고 있는지 검수해줘.
- 너무 많이 생략해서 의미가 흐려진 부분이 있는지 점검해줘.

### 사용 팁
짧게 만든다고 좋은 게 아니라, “짧지만 판단 가능한 상태”가 되어야 실제로 쓸 수 있습니다.

## 7. 내 상황을 AI에게 설명하는 문장을 만들고 싶을 때

### 한 줄 설명
막연한 내 상황 설명을 AI가 제대로 이해할 수 있는 입력 문장으로 정리하는 상황 설명형 작업지시서입니다.

### 이런 상황에서 특히 잘 맞습니다
- 머릿속 상황은 있는데 글로 설명이 안 될 때
- AI가 자꾸 내 맥락을 잘못 이해할 때
- 문제는 있는데 어디부터 말해야 할지 모르겠을 때

### 이 작업지시서로 기대할 수 있는 결과
- 상황 설명에 꼭 들어가야 할 요소
- 잘못된 설명 예시와 더 나은 설명 예시
- 바로 복사할 나만의 상황 설명 문장

### 언제 쓰는지
- 첫 질문 전
- AI가 맥락을 계속 놓칠 때

### 바로 복사할 본문
```text
지금 저는 [하고 싶은 작업 또는 해결하고 싶은 문제]가 있습니다.
그런데 제 상황을 AI에게 어떻게 설명해야 할지 잘 모르겠습니다.

먼저 이 상황 설명에 꼭 들어가야 할 핵심 요소를 정리해 주세요.
그 다음 아래 순서로 답변해 주세요.

1. 상황 설명에 꼭 들어가야 할 요소
2. 좋지 않은 설명 예시
3. 더 나은 설명 예시
4. 제 상황에 맞게 바로 복사해서 쓸 최종 설명 문장

현재 제 상황의 핵심은 아래와 같습니다.
- 목적: [무엇을 하고 싶은지]
- 대상: [누가 보거나 쓰는지]
- 현재 막힌 부분: [어디서 막히는지]
- 원하는 결과: [어떤 상태를 원하는지]

답변은 초보자도 그대로 따라할 수 있게 쉽게 설명해 주세요.
최종 문장은 너무 길지 않되, AI가 오해하지 않을 정도로 필요한 정보는 담아 주세요.
```

### 바꿔야 할 부분
- `[하고 싶은 작업 또는 해결하고 싶은 문제]`
- `[무엇을 하고 싶은지]`
- `[누가 보거나 쓰는지]`
- `[어디서 막히는지]`
- `[어떤 상태를 원하는지]`

### 후속 질문
- 위 최종 설명 문장을 더 짧고 자연스럽게 줄여줘.
- 같은 내용을 더 전문가적인 어조로 설명하는 버전도 하나 추가해줘.

### 수정 요청
- 추상적인 표현은 줄이고 더 구체적인 문장으로 바꿔줘.
- 핵심은 유지하되 AI가 더 잘 이해하게 순서를 바꿔줘.

### 검수 요청
- 이 설명만 보고도 AI가 내 상황을 충분히 이해할 수 있을지 검수해줘.
- 빠진 핵심 정보가 있다면 짚어줘.

### 사용 팁
많은 사람은 질문 기술보다 “상황 설명”에서 먼저 막힙니다.  
상황을 잘 설명하면 이후 결과 품질이 훨씬 안정됩니다.
