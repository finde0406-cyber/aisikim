# AI시킴 스타터팩 나머지 35개 2차 초안 v1

## 1. 문서 목적
이 문서는 스타터팩 나머지 35개 중 2차 우선 제작 항목을 실제 판매 기준에 맞춰 작성한 실물 초안입니다.  
1차 초안과 함께, 스타터팩 전체 50개를 숫자 채우기가 아니라 실제로 반복 사용 가능한 유료 자산으로 확장하는 것이 목적입니다.

## 2. 이번 2차 초안에 포함한 항목
1. 소제목 구조를 더 읽기 좋게 정리하고 싶을 때
2. 판매형 콘텐츠 문구를 자연스럽게 녹이고 싶을 때
3. 기획서 초안을 항목별로 채우고 싶을 때
4. 문제 보고 문서를 더 차분하고 정확하게 쓰고 싶을 때
5. 사용자 흐름을 화면 단위로 정리하고 싶을 때
6. 독자나 대상에 맞게 톤을 바꾸고 싶을 때
7. 원하는 결과물 형식을 먼저 고정하고 싶을 때

---

## 1. 소제목 구조를 더 읽기 좋게 정리하고 싶을 때

### 한 줄 설명
이미 나온 글 구조를 더 읽기 쉬운 흐름으로 정리하고, 소제목만 봐도 전체 메시지가 자연스럽게 이어지도록 다듬는 작업지시서입니다.

### 이럴 때 가장 먼저 꺼내 쓰세요
- 본문 내용은 괜찮은데 소제목만 보면 흐름이 안 읽힐 때
- 글의 구조를 무너뜨리지 않고 `중간 안내 표지판`만 더 좋게 만들고 싶을 때

### 이 항목이 다른 항목과 다른 점
이 항목은 도입부 강화나 전체 글 검수와 다르게, `소제목 간 연결과 위계` 자체를 손보는 구조 보정용 작업지시서입니다.

### 이런 상황에서 특히 잘 맞습니다
- 소제목 수는 맞는데 흐름이 뚝뚝 끊길 때
- 제목은 괜찮은데 소제목이 너무 평범할 때
- 글 전체 메시지가 소제목만 봐도 잘 전달되길 원할 때

### 이 작업지시서로 기대할 수 있는 결과
- 더 읽기 쉬운 소제목 구조
- 중복 없는 소제목 배치
- 글 흐름이 자연스럽게 이어지는 구조

### 언제 쓰는지
- 글 초안이 나온 뒤 구조를 다듬는 단계
- 게시 전에 가독성을 높이고 싶을 때

### 바로 복사할 본문
```text
아래는 제가 작성 중인 글의 현재 제목과 소제목 구조입니다.
전체 주제와 방향은 유지하되, 소제목 구조를 더 읽기 좋고 자연스럽게 다시 정리해 주세요.

이번 글의 주제는 [주제]이고,
대상 독자는 [대상 독자]입니다.
이 글에서 가장 중요하게 전달해야 하는 핵심은 [핵심 메시지]입니다.

소제목 구조는 아래 기준으로 다시 정리해 주세요.
1. 읽는 사람이 순서대로 이해하기 쉬울 것
2. 서로 겹치거나 중복되는 소제목은 줄일 것
3. 소제목만 봐도 글 흐름이 보일 것
4. 너무 추상적이거나 흔한 표현은 줄일 것

답변은 아래 순서로 주세요.
1. 현재 소제목 구조의 약한 점
2. 다시 정리한 소제목 구조
3. 각 소제목 아래에 어떤 내용을 넣으면 좋은지 한 줄씩 설명
```

### 바꿔야 할 부분
- `[주제]`
- `[대상 독자]`
- `[핵심 메시지]`
- 아래에 현재 제목/소제목 구조 붙여 넣기

### 후속 질문
- 위 소제목 구조를 더 짧고 강하게 다시 다듬어줘.
- 초보자 기준으로 더 이해하기 쉬운 표현으로 바꿔줘.

### 수정 요청
- 소제목 간 역할이 더 분명하게 드러나도록 수정해줘.
- 비슷한 표현이 반복되는 부분은 줄여줘.

### 검수 요청
- 이 소제목 구조만 봐도 글 흐름이 충분히 보이는지 검수해줘.
- 읽는 사람이 중간에 이탈할 만한 구간이 있는지 점검해줘.

### 사용 팁
소제목은 본문 요약이 아니라, 독자에게 “다음에 어떤 이야기가 나올지”를 안내하는 구조여야 합니다.

## 2. 판매형 콘텐츠 문구를 자연스럽게 녹이고 싶을 때

### 한 줄 설명
정보 전달 위주의 글이나 소개문 안에 판매형 문구를 과하지 않게 녹여, 거부감 없이 전환을 유도하는 작업지시서입니다.

### 이런 상황에서 특히 잘 맞습니다
- 너무 대놓고 팔려는 느낌은 싫을 때
- 정보형 글인데도 전환 포인트는 넣고 싶을 때
- 서비스 소개 글이나 랜딩 문구가 딱딱할 때

### 이 작업지시서로 기대할 수 있는 결과
- 자연스러운 판매 문장
- 정보와 판매의 균형
- 과하지 않은 CTA 흐름

### 언제 쓰는지
- 글/페이지 초안 작성 후 전환 문구를 넣는 단계
- 소개 글이나 랜딩 카피 보완 단계

### 바로 복사할 본문
```text
아래 문구는 현재 [글 / 소개 페이지 / 랜딩 카피] 초안입니다.
전체적으로는 정보 전달 중심이지만, 너무 어색하지 않게 전환 요소도 함께 녹이고 싶습니다.

이번 문구의 목적은 [신뢰 형성 / 관심 유도 / 샘플팩 신청 / 스타터팩 관심 유도 / 구매 유도]입니다.
읽는 사람이 가장 먼저 느껴야 하는 것은 [공감 / 신뢰 / 이해 / 기대감]입니다.

아래 기준으로 문구를 다시 다듬어 주세요.
1. 너무 대놓고 파는 느낌은 줄일 것
2. 정보 전달 흐름은 유지할 것
3. 자연스럽게 다음 행동으로 이어질 것
4. 과장된 표현 없이 전환 포인트를 더 분명하게 만들 것

답변은 아래 순서로 주세요.
1. 현재 문구에서 어색한 판매 느낌이 나는 부분
2. 더 자연스럽게 바꾼 문구
3. CTA 문장 3가지 버전
```

### 바꿔야 할 부분
- `[글 / 소개 페이지 / 랜딩 카피]`
- `[신뢰 형성 / 관심 유도 / 샘플팩 신청 / 스타터팩 관심 유도 / 구매 유도]`
- `[공감 / 신뢰 / 이해 / 기대감]`

### 후속 질문
- 위 문구를 유지한 채 더 부드러운 CTA 버전도 추가해줘.
- 판매 느낌은 줄이고 샘플팩 관심 유도 쪽으로 더 맞춰줘.

### 수정 요청
- 과장된 느낌이 나는 표현은 줄여줘.
- 실제 사용자 입장에서 덜 부담스럽게 다시 정리해줘.

### 검수 요청
- 이 문구가 신뢰를 해치지 않으면서도 전환을 유도하는지 검수해줘.
- 지나치게 세거나 약한 구간이 있다면 짚어줘.

### 사용 팁
판매형 문구는 “사라”보다 “왜 지금 이걸 한 번 써봐야 하는지”를 더 잘 보여줄 때 강해집니다.

## 3. 기획서 초안을 항목별로 채우고 싶을 때

### 한 줄 설명
빈 기획서 템플릿이나 러프한 개요를 실제 항목별 문장으로 채워 넣는 구조화형 작업지시서입니다.

### 이럴 때 가장 먼저 꺼내 쓰세요
- 목차는 이미 정했는데 각 항목 본문이 비어 있을 때
- 기획서 흐름은 잡혔지만 `실제 문장 초안`이 하나도 안 써질 때

### 이 항목이 다른 항목과 다른 점
이 항목은 목차를 재구성하는 용도보다, `빈 항목을 실무 문장으로 채우는 초안 생산`에 더 초점이 맞춰져 있습니다.

### 이런 상황에서 특히 잘 맞습니다
- 목차는 있는데 본문이 안 써질 때
- 기획서를 처음부터 다 쓰기 막막할 때
- 항목별로 빠르게 초안을 채우고 싶을 때

### 이 작업지시서로 기대할 수 있는 결과
- 항목별 본문 초안
- 빠진 핵심 요소 보완
- 실제 공유 가능한 기획서 초안 구조

### 언제 쓰는지
- 기획서 작성 초반
- 항목별 초안 채우기 단계

### 바로 복사할 본문
```text
지금 저는 [기획서 주제]에 대한 기획서 초안을 작성하고 있습니다.
현재는 목차 또는 항목 구조만 있고, 각 항목을 실제 문장으로 채워 넣는 데 막히고 있습니다.

이 기획서는 [상사 / 고객 / 팀 / 이해관계자]가 읽을 예정이며,
가장 중요하게 봐야 하는 것은 [배경 / 문제 / 해결 방향 / 기대 효과 / 실행안]입니다.

아래 기준으로 기획서 항목을 채워 주세요.
1. 각 항목마다 왜 필요한지 짧게 드러날 것
2. 너무 추상적이지 않게 실제 문서처럼 쓸 것
3. 읽는 사람이 빠르게 이해할 수 있게 구조화할 것

답변은 아래 순서로 주세요.
1. 항목별 핵심 포인트
2. 각 항목의 초안 문장
3. 기획서에서 빠지면 안 되는 보완 항목
```

### 바꿔야 할 부분
- `[기획서 주제]`
- `[상사 / 고객 / 팀 / 이해관계자]`
- `[배경 / 문제 / 해결 방향 / 기대 효과 / 실행안]`

### 후속 질문
- 위 초안을 더 설득력 있는 보고용 어조로 다시 써줘.
- 항목별 문장을 더 짧게 정리한 버전도 같이 만들어줘.

### 수정 요청
- 추상적인 표현은 줄이고 실제 실행 문장처럼 바꿔줘.
- 읽는 사람이 바로 이해하기 쉬운 구조로 다시 정리해줘.

### 검수 요청
- 이 기획서 초안에서 빠진 핵심 항목이 있는지 검수해줘.
- 항목 간 흐름이 어색한 부분이 있다면 짚어줘.

### 사용 팁
기획서는 완벽하게 한 번에 쓰기보다, 항목별 초안을 먼저 채운 뒤 설득력을 더하는 방식이 훨씬 빠릅니다.

## 4. 문제 보고 문서를 더 차분하고 정확하게 쓰고 싶을 때

### 한 줄 설명
감정적이거나 두루뭉술한 문제 보고를, 사실 중심의 차분한 문서로 정리하는 문제 보고형 작업지시서입니다.

### 이런 상황에서 특히 잘 맞습니다
- 문제가 발생했는데 어떻게 보고해야 할지 애매할 때
- 지나치게 감정적이거나 방어적으로 쓰게 될 때
- 원인, 영향, 대응을 더 차분하게 정리하고 싶을 때

### 이 작업지시서로 기대할 수 있는 결과
- 문제 요약
- 영향 범위
- 현재 대응 상태
- 추가 확인 필요 사항

### 언제 쓰는지
- 이슈/장애/실수 보고 문서 작성 시
- 팀/상사/고객에게 사실 중심 보고가 필요할 때

### 바로 복사할 본문
```text
지금 저는 [문제 상황]에 대해 보고 문서를 작성해야 합니다.
이 문서는 [상사 / 팀 / 고객 / 이해관계자]가 읽을 예정입니다.
가장 중요한 것은 감정적인 설명보다, 사실과 영향, 현재 대응 상태를 차분하게 정리하는 것입니다.

아래 기준으로 문제 보고 문서를 정리해 주세요.
1. 무슨 일이 있었는지
2. 어떤 영향이 있었는지
3. 현재 확인된 원인 또는 가설
4. 지금까지의 대응
5. 추가 확인 또는 다음 조치

답변은 책임 회피처럼 보이지 않으면서도, 감정적 표현 없이 사실 중심으로 정리해 주세요.
읽는 사람이 현재 상황을 빠르게 파악하고 판단할 수 있게 써주세요.
```

### 바꿔야 할 부분
- `[문제 상황]`
- `[상사 / 팀 / 고객 / 이해관계자]`

### 후속 질문
- 위 문서를 상사 보고용으로 더 짧고 단정하게 다시 정리해줘.
- 고객 공유용으로 표현을 더 조심스럽게 다듬어줘.

### 수정 요청
- 감정적으로 읽힐 표현은 줄여줘.
- 영향과 대응이 더 선명하게 보이도록 구조를 다시 잡아줘.

### 검수 요청
- 이 문서가 사실 중심으로 충분히 정리됐는지 검수해줘.
- 읽는 사람이 오해할 수 있는 표현이 있는지 점검해줘.

### 사용 팁
문제 보고는 변명처럼 들리지 않는 것과, 핵심 정보가 빨리 보이는 것이 가장 중요합니다.

## 5. 사용자 흐름을 화면 단위로 정리하고 싶을 때

### 한 줄 설명
서비스 기능이나 화면 아이디어를 페이지/단계 단위로 정리해, 실제 UX 흐름이 보이도록 만드는 작업지시서입니다.

### 이런 상황에서 특히 잘 맞습니다
- 기능은 있는데 사용 흐름이 안 잡힐 때
- 화면이 여러 개 연결되는데 어디서 뭘 해야 할지 정리 안 될 때
- 기획자/개발자/디자이너가 같은 흐름을 보게 만들고 싶을 때

### 이 작업지시서로 기대할 수 있는 결과
- 단계별 사용자 흐름
- 화면별 역할
- 전환 지점과 이탈 지점 정리

### 언제 쓰는지
- 기능 정의 이후 UX 흐름 정리 단계
- 화면 설계 전/후 보완 단계

### 바로 복사할 본문
```text
지금 저는 [서비스/기능]의 사용자 흐름을 화면 단위로 정리하고 싶습니다.
이 흐름의 목적은 [신청 / 진단 / 구매 / 탐색 / 결과 확인]입니다.
가장 중요한 것은 사용자가 어느 화면에서 무엇을 하고, 다음 화면으로 왜 이동하는지가 분명히 보이는 것입니다.

아래 기준으로 사용자 흐름을 정리해 주세요.
1. 시작 화면
2. 다음 단계 화면들
3. 각 화면의 목적
4. 사용자가 해야 하는 행동
5. 다음 화면으로 이동하는 이유
6. 이탈 가능성이 큰 지점

답변은 화면 단위로 끊어서 정리해 주세요.
가능하면 비개발자도 이해할 수 있게 설명하되, 기획/개발 문서로 써도 될 정도로 분명하게 정리해 주세요.
```

### 바꿔야 할 부분
- `[서비스/기능]`
- `[신청 / 진단 / 구매 / 탐색 / 결과 확인]`

### 후속 질문
- 위 흐름을 모바일 사용자 기준으로 더 단순하게 다시 정리해줘.
- 각 화면의 핵심 CTA까지 같이 표시해줘.

### 수정 요청
- 화면 간 이동 이유가 더 잘 보이게 다시 써줘.
- 이탈 가능성이 높은 구간을 더 분명히 표시해줘.

### 검수 요청
- 이 흐름만 봐도 사용자가 어디서 무엇을 하는지 충분히 보이는지 검수해줘.
- 빠진 핵심 화면이 있는지 점검해줘.

### 사용 팁
사용자 흐름은 화면 개수보다 “왜 다음으로 이동하는지”가 선명해야 실제 설계가 쉬워집니다.

## 6. 독자나 대상에 맞게 톤을 바꾸고 싶을 때

### 한 줄 설명
이미 나온 결과의 핵심 내용은 유지하되, 읽는 대상에 맞게 어조와 표현 밀도를 조정하는 톤 전환형 작업지시서입니다.

### 이럴 때 가장 먼저 꺼내 쓰세요
- 내용은 괜찮은데 고객용, 상사용, 초보자용 중 누구에게 맞춰야 할지 바꿔야 할 때
- 구조와 정보량은 유지하고 `말투와 압력감`만 조정하고 싶을 때

### 이 항목이 다른 항목과 다른 점
이 항목은 설득력 강화나 구조 재편이 아니라, `같은 내용`을 누구에게 보여주느냐에 따라 어조와 난이도를 맞추는 데 집중합니다.

### 이런 상황에서 특히 잘 맞습니다
- 같은 내용을 초보자용/전문가용으로 나눠야 할 때
- 고객용/상사용/사용자용으로 문체를 바꿔야 할 때
- 내용은 맞는데 말투가 대상과 안 맞을 때

### 이 작업지시서로 기대할 수 있는 결과
- 대상 맞춤형 문체
- 더 적절한 표현 강도
- 내용은 유지한 채 읽기 쉬운 결과

### 언제 쓰는지
- 초안 이후 톤 조정 단계
- 공유 대상이 바뀌었을 때

### 바로 복사할 본문
```text
아래 결과물의 핵심 내용은 유지하되, 읽는 대상에 맞게 톤을 다시 조정하고 싶습니다.
이번 대상은 [초보자 / 실무자 / 상사 / 고객 / 일반 사용자]입니다.
이 대상에게는 [쉽고 친절한 느낌 / 단정하고 전문적인 느낌 / 짧고 명확한 느낌 / 신뢰감 있는 느낌]이 더 중요합니다.

아래 기준으로 다시 써주세요.
1. 내용의 핵심은 유지할 것
2. 대상에게 맞지 않는 표현은 조정할 것
3. 문장 길이와 난이도도 대상에 맞출 것
4. 읽는 사람이 부담 없이 이해할 수 있게 할 것

답변은 아래 순서로 주세요.
1. 현재 결과에서 대상과 맞지 않는 부분
2. 조정 방향
3. 다듬은 최종본
```

### 바꿔야 할 부분
- `[초보자 / 실무자 / 상사 / 고객 / 일반 사용자]`
- `[쉽고 친절한 느낌 / 단정하고 전문적인 느낌 / 짧고 명확한 느낌 / 신뢰감 있는 느낌]`

### 후속 질문
- 지금 버전보다 더 친절한 말투 버전도 하나 추가해줘.
- 더 짧고 단정한 버전으로도 다시 정리해줘.

### 수정 요청
- 대상과 맞지 않는 표현은 더 과감하게 바꿔줘.
- 말투는 조정하되 내용 밀도는 유지해줘.

### 검수 요청
- 이 결과가 설정한 대상에게 실제로 잘 맞는 톤인지 검수해줘.
- 지나치게 딱딱하거나 가벼운 부분이 있다면 짚어줘.

### 사용 팁
좋은 톤 조정은 내용을 바꾸는 것이 아니라, 같은 내용을 상대가 더 쉽게 받아들이게 만드는 일입니다.

## 7. 원하는 결과물 형식을 먼저 고정하고 싶을 때

### 한 줄 설명
AI가 어떤 형태로 답해야 하는지 먼저 고정해서, 결과물 형식이 흔들리지 않게 만드는 형식 고정형 작업지시서입니다.

### 이런 상황에서 특히 잘 맞습니다
- 내용보다 결과물 형태가 더 중요한 작업일 때
- 보고서, 체크리스트, 표, 단계형 결과처럼 형식을 먼저 잡고 싶을 때
- AI가 매번 다른 형식으로 답해서 재작업이 많을 때

### 이 작업지시서로 기대할 수 있는 결과
- 원하는 형식에 맞는 결과물
- 구조가 일관된 출력
- 재작업 감소

### 언제 쓰는지
- 첫 질문 전
- 원하는 출력 형식이 분명할 때

### 바로 복사할 본문
```text
지금 저는 [주제/작업]에 대한 결과를 받아야 하는데,
가장 중요한 것은 내용뿐 아니라 결과물의 형식이 분명하게 맞는 것입니다.

이번 결과물은 [보고서 / 체크리스트 / 표 / 단계별 설명 / 제목 목록 / 요약본 / 개발 지시문] 형식으로 받고 싶습니다.
이 형식에서 꼭 들어가야 하는 요소는 [필수 요소]입니다.

먼저 이 형식으로 답변할 때 빠지면 안 되는 구조가 있다면 짚어주세요.
그 다음 아래 기준으로 결과를 작성해 주세요.

1. 지정한 형식을 정확히 지킬 것
2. 불필요하게 다른 형식으로 새지 않을 것
3. 읽는 사람이 바로 사용할 수 있는 수준으로 정리할 것
4. 필요하면 각 항목 이름도 더 명확하게 붙일 것

답변은 실제로 바로 붙여 넣어 쓸 수 있는 결과물 형식으로 작성해 주세요.
```

### 바꿔야 할 부분
- `[주제/작업]`
- `[보고서 / 체크리스트 / 표 / 단계별 설명 / 제목 목록 / 요약본 / 개발 지시문]`
- `[필수 요소]`

### 후속 질문
- 같은 내용을 더 짧은 형식으로도 하나 추가해줘.
- 이 형식에서 빠지기 쉬운 요소가 있다면 보완해줘.

### 수정 요청
- 형식은 유지하되 더 보기 쉽게 정리해줘.
- 항목 간 위계가 더 선명하게 보이도록 다시 작성해줘.

### 검수 요청
- 이 결과가 요청한 형식을 충분히 정확하게 지키는지 검수해줘.
- 실사용에 불편한 부분이 있다면 짚어줘.

### 사용 팁
내용 품질이 흔들릴 때도 문제지만, 결과물 형식이 흔들리면 실무에서는 더 바로 못 쓰게 되는 경우가 많습니다.
