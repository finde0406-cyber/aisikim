# AI시킴 스타터팩 나머지 35개 3차 초안 v1

## 1. 문서 목적
이 문서는 스타터팩 나머지 35개 중 3차 우선 제작 항목을 실제 판매 기준에 맞춰 작성한 실물 초안입니다.  
이전 배치와 이어서, 스타터팩 50개 전체를 실제로 반복 사용 가능한 유료 자산으로 확장하는 데 목적이 있습니다.

## 2. 이번 3차 초안에 포함한 항목
1. 정보형 글을 더 구체적으로 확장하고 싶을 때
2. 같은 내용을 짧은 SNS용 문구로 바꾸고 싶을 때
3. 업무 이메일을 더 명확하게 쓰고 싶을 때
4. 실행 계획을 체크리스트로 정리하고 싶을 때
5. 버그 상황을 더 정확하게 설명하고 싶을 때
6. 빠진 핵심 요소가 있는지 점검하고 싶을 때
7. 후속 질문 흐름을 설계하고 싶을 때

---

## 1. 정보형 글을 더 구체적으로 확장하고 싶을 때

### 한 줄 설명
이미 잡힌 정보형 글 초안을 독자가 실제로 더 많이 얻어갈 수 있게, 예시와 세부 설명을 붙여 확장하는 작업지시서입니다.

### 이런 상황에서 특히 잘 맞습니다
- 글 구조는 있지만 내용 밀도가 약할 때
- 설명이 맞긴 한데 너무 얕게 끝날 때
- 독자가 “그래서 실제로 어떻게 하는 건데?”를 느낄 때

### 이 작업지시서로 기대할 수 있는 결과
- 더 구체적인 본문
- 예시가 붙은 설명
- 독자 체감이 높은 정보형 글 확장본

### 언제 쓰는지
- 정보형 글 초안이 나온 뒤 본문 확장 단계
- 초안은 있는데 깊이가 부족한 시점

### 바로 복사할 본문
```text
아래 글 초안은 전체 구조는 괜찮지만, 내용이 다소 얕아서 실제로 도움이 되는 느낌이 약합니다.
이번 글의 주제는 [주제]이고,
읽을 대상은 [대상 독자]입니다.
이 독자가 특히 궁금해할 부분은 [구체적으로 알고 싶은 지점]입니다.

아래 기준으로 본문을 더 구체적으로 확장해 주세요.
1. 추상적인 설명은 줄일 것
2. 실제 예시나 상황을 붙일 것
3. 독자가 바로 적용할 수 있는 표현을 넣을 것
4. 길어지기만 하지 않도록 핵심 구조는 유지할 것

답변은 아래 순서로 주세요.
1. 현재 글에서 더 구체화해야 하는 부분
2. 보강 방향
3. 확장한 본문 초안
```

### 바꿔야 할 부분
- `[주제]`
- `[대상 독자]`
- `[구체적으로 알고 싶은 지점]`

### 후속 질문
- 위 확장본에 실제 사례를 2개만 더 넣어줘.
- 초보자 기준으로 더 쉽게 이해되게 다시 써줘.

### 수정 요청
- 길이만 늘리지 말고 실질적인 정보가 늘어나게 다시 다듬어줘.
- 중복되는 설명은 줄이고 예시 위주로 바꿔줘.

### 검수 요청
- 이 확장본이 독자 입장에서 실제로 더 도움 되는지 검수해줘.
- 여전히 얕게 느껴질 수 있는 부분이 있다면 짚어줘.

### 사용 팁
정보형 글은 많이 쓰는 것보다, 독자가 바로 적용할 수 있는 구체성을 더하는 쪽이 훨씬 강합니다.

## 2. 같은 내용을 짧은 SNS용 문구로 바꾸고 싶을 때

### 한 줄 설명
긴 글이나 소개문을 SNS에 맞는 짧고 명확한 문구로 재가공하는 작업지시서입니다.

### 이런 상황에서 특히 잘 맞습니다
- 블로그/랜딩 내용을 SNS에도 활용하고 싶을 때
- 긴 내용을 짧게 압축해야 할 때
- 정보는 유지하되 더 빠르게 읽히게 하고 싶을 때

### 이 작업지시서로 기대할 수 있는 결과
- 짧은 SNS용 문구
- 핵심만 남긴 소개문
- 플랫폼에 맞는 리듬감 있는 표현

### 언제 쓰는지
- 원문이 이미 있는 상태에서 채널별 재가공 단계
- 게시 직전 짧은 카피 필요 시

### 바로 복사할 본문
```text
아래 원문은 내용은 괜찮지만 길어서 SNS에 그대로 쓰기 어렵습니다.
이 내용을 [인스타그램 / 스레드 / X / 카카오채널 / 짧은 피드형 문구]에 맞게 짧고 읽기 쉽게 바꿔 주세요.

가장 중요한 메시지는 [핵심 메시지]입니다.
읽는 사람이 느껴야 하는 것은 [공감 / 궁금증 / 신뢰 / 행동 욕구]입니다.

아래 기준으로 다시 작성해 주세요.
1. 핵심 메시지는 유지할 것
2. 길이를 짧게 줄일 것
3. 모바일에서 빠르게 읽히게 할 것
4. 너무 광고처럼 보이지 않게 할 것

답변은 아래 순서로 주세요.
1. 1문장 압축 버전
2. 3문장 버전
3. CTA가 들어간 버전 1개
```

### 바꿔야 할 부분
- `[인스타그램 / 스레드 / X / 카카오채널 / 짧은 피드형 문구]`
- `[핵심 메시지]`
- `[공감 / 궁금증 / 신뢰 / 행동 욕구]`

### 후속 질문
- 위 문구를 더 부드럽고 덜 홍보처럼 보이게 바꿔줘.
- 초보자 대상 기준으로 이해하기 쉽게 다시 써줘.

### 수정 요청
- 말맛은 유지하되 문장을 더 짧게 다듬어줘.
- 플랫폼 특성상 과한 문장부호나 과장은 줄여줘.

### 검수 요청
- 이 문구가 짧으면서도 원문의 핵심을 충분히 담는지 검수해줘.
- 너무 홍보처럼 느껴질 수 있는 표현이 있으면 짚어줘.

### 사용 팁
SNS 문구는 새로 쓰는 것보다, 원문에서 하나의 핵심 감정과 하나의 행동만 남기는 방식이 더 잘 먹힙니다.

## 3. 업무 이메일을 더 명확하게 쓰고 싶을 때

### 한 줄 설명
애매하거나 장황한 업무 이메일을, 읽는 사람이 바로 이해하고 행동할 수 있는 문장으로 정리하는 작업지시서입니다.

### 이런 상황에서 특히 잘 맞습니다
- 메일을 길게 써놓고도 전달이 안 된다고 느낄 때
- 요청/공유/확인 메일이 자꾸 애매해질 때
- 상대가 무엇을 해야 하는지 더 명확히 보이게 하고 싶을 때

### 이 작업지시서로 기대할 수 있는 결과
- 짧고 단정한 업무 메일
- 요청 사항이 분명한 문장
- 읽는 사람이 바로 이해하는 구조

### 언제 쓰는지
- 메일 발송 직전
- 초안이 있는데 더 명확히 다듬고 싶을 때

### 바로 복사할 본문
```text
아래 내용은 현재 보내려고 하는 업무 이메일 초안입니다.
내용은 맞지만, 더 짧고 명확하게 다듬고 싶습니다.

이 메일의 목적은 [공유 / 요청 / 확인 / 일정 조율 / 문제 전달]입니다.
받는 사람이 가장 먼저 이해해야 하는 것은 [핵심 요청 / 핵심 공유 내용 / 기한 / 필요한 행동]입니다.

아래 기준으로 메일을 다시 써주세요.
1. 불필요하게 긴 문장은 줄일 것
2. 메일 목적이 앞쪽에서 분명히 보일 것
3. 받는 사람이 해야 할 행동이 명확할 것
4. 실무 메일처럼 단정하게 쓸 것

답변은 아래 순서로 주세요.
1. 제목 제안 3개
2. 더 명확하게 다듬은 메일 본문
3. 한 줄 요약 문장
```

### 바꿔야 할 부분
- `[공유 / 요청 / 확인 / 일정 조율 / 문제 전달]`
- `[핵심 요청 / 핵심 공유 내용 / 기한 / 필요한 행동]`

### 후속 질문
- 위 메일을 더 짧고 단정한 버전으로 다시 써줘.
- 상사에게 보내는 버전으로 어조를 조금 더 조심스럽게 바꿔줘.

### 수정 요청
- 군더더기는 줄이고 핵심 문장은 더 앞으로 배치해줘.
- 상대가 해야 할 행동이 더 잘 보이게 수정해줘.

### 검수 요청
- 이 메일만 읽어도 수신자가 무엇을 해야 하는지 충분히 보이는지 검수해줘.
- 지나치게 애매하거나 부담스럽게 들릴 수 있는 표현이 있는지 점검해줘.

### 사용 팁
업무 이메일은 “예의 바름”도 중요하지만, 그보다 “읽는 사람이 바로 이해하는 구조”가 먼저입니다.

## 4. 실행 계획을 체크리스트로 정리하고 싶을 때

### 한 줄 설명
흩어진 실행 아이디어나 계획을 실제로 움직일 수 있는 체크리스트로 정리하는 작업지시서입니다.

### 이런 상황에서 특히 잘 맞습니다
- 해야 할 일은 많은데 순서가 안 잡힐 때
- 계획이 문장형으로만 되어 있어 실행이 어려울 때
- 팀이나 본인이 바로 체크하며 움직일 수 있는 형태가 필요할 때

### 이 작업지시서로 기대할 수 있는 결과
- 단계별 실행 체크리스트
- 우선순위가 보이는 계획
- 바로 실행 가능한 항목 정리

### 언제 쓰는지
- 계획 수립 직후
- 실행 전 정리 단계

### 바로 복사할 본문
```text
지금 저는 [목표 작업]을 실행해야 하는데, 현재 계획이 흩어져 있어 실제로 움직이기 어렵습니다.
이 계획을 바로 실행 가능한 체크리스트 형태로 정리해 주세요.

가장 중요한 것은 [우선순위 / 실행 순서 / 완료 기준 / 담당 구분]입니다.

아래 기준으로 정리해 주세요.
1. 해야 할 일을 단계별로 나눌 것
2. 우선순위가 보이게 할 것
3. 바로 체크할 수 있는 문장으로 쓸 것
4. 필요하면 "지금 / 다음 / 나중"으로 나눌 것

답변은 아래 순서로 주세요.
1. 핵심 목표 한 줄 요약
2. 실행 체크리스트
3. 가장 먼저 해야 할 3개
```

### 바꿔야 할 부분
- `[목표 작업]`
- `[우선순위 / 실행 순서 / 완료 기준 / 담당 구분]`

### 후속 질문
- 이 체크리스트를 하루 단위 계획으로 더 잘게 나눠줘.
- 혼자 실행할 때와 팀으로 실행할 때 버전을 나눠줘.

### 수정 요청
- 추상적인 실행 항목은 줄이고 더 바로 행동할 수 있게 바꿔줘.
- 우선순위가 더 명확히 보이게 정리해줘.

### 검수 요청
- 이 체크리스트만 봐도 실제로 움직일 수 있는지 검수해줘.
- 빠진 실행 단계가 있다면 보완해줘.

### 사용 팁
실행 계획은 멋진 문장보다 `체크 가능한 문장`이 훨씬 유용합니다.

## 5. 버그 상황을 더 정확하게 설명하고 싶을 때

### 한 줄 설명
애매한 버그 설명을 개발자나 AI가 바로 이해할 수 있는 재현 가능한 설명으로 바꾸는 작업지시서입니다.

### 이런 상황에서 특히 잘 맞습니다
- “이상하게 안 돼요” 수준에서 더 설명이 안 될 때
- 재현 조건과 기대 결과를 정리해야 할 때
- 개발자와 커뮤니케이션이 자꾸 엇갈릴 때

### 이 작업지시서로 기대할 수 있는 결과
- 버그 요약
- 재현 단계
- 실제 결과와 기대 결과 구분
- 추가 확인 포인트

### 언제 쓰는지
- 버그 보고 직전
- 개발자 전달용 이슈 정리 단계

### 바로 복사할 본문
```text
지금 저는 [버그/이상 현상]을 개발자에게 더 정확하게 설명하고 싶습니다.
현재 상태에서는 상황을 막연하게만 설명하고 있어서, 재현 가능하고 오해 없는 방식으로 정리하고 싶습니다.

아래 기준으로 버그 설명 문서를 정리해 주세요.
1. 어떤 화면/기능에서 발생하는지
2. 어떻게 하면 같은 현상이 재현되는지
3. 실제로 나타난 결과
4. 원래 기대했던 정상 결과
5. 추가로 확인하면 좋은 정보

답변은 아래 순서로 주세요.
1. 버그 한 줄 요약
2. 재현 단계
3. 실제 결과
4. 기대 결과
5. 개발자 전달용 요약 문장
```

### 바꿔야 할 부분
- `[버그/이상 현상]`

### 후속 질문
- 이 내용을 이슈 티켓 등록용 문장으로 더 짧게 다시 써줘.
- 개발자가 바로 재현할 수 있게 단계 설명을 더 구체적으로 보완해줘.

### 수정 요청
- 모호한 표현은 줄이고 재현 단계가 더 분명하게 보이게 바꿔줘.
- 실제 결과와 기대 결과 차이가 더 잘 드러나게 정리해줘.

### 검수 요청
- 이 설명만으로도 개발자가 상황을 이해할 수 있는지 검수해줘.
- 빠진 핵심 정보가 있다면 짚어줘.

### 사용 팁
버그 설명은 원인 추측보다 `재현 가능성`과 `기대 결과 대비 실제 결과`가 더 중요합니다.

## 6. 빠진 핵심 요소가 있는지 점검하고 싶을 때

### 한 줄 설명
이미 나온 결과물에서 빠진 핵심 요소를 빠르게 찾아내고 보완 방향을 잡는 점검형 작업지시서입니다.

### 이런 상황에서 특히 잘 맞습니다
- 결과물은 있는데 뭔가 허전할 때
- 큰 방향은 맞지만 빠진 요소가 있을까 불안할 때
- 제출 전에 누락 여부를 점검하고 싶을 때

### 이 작업지시서로 기대할 수 있는 결과
- 빠진 핵심 요소 목록
- 보완 우선순위
- 누락 반영 방향

### 언제 쓰는지
- 초안 이후 점검 단계
- 제출 전 체크 단계

### 바로 복사할 본문
```text
아래 결과물은 전체 방향은 맞지만, 혹시 빠진 핵심 요소가 없는지 점검하고 싶습니다.

이 결과물의 목적은 [보고 / 공유 / 게시 / 제안 / 전달]입니다.
읽는 사람은 [상사 / 고객 / 사용자 / 팀원 / 일반 독자]입니다.

아래 기준으로 점검해 주세요.
1. 빠진 핵심 요소가 있는지
2. 있어야 하는데 약하게 들어간 요소가 있는지
3. 지금 보완하면 가장 좋아지는 부분이 무엇인지

답변은 아래 순서로 주세요.
1. 누락 또는 약한 요소 요약
2. 우선 보완할 3가지
3. 보완 방향 또는 예시 문장
```

### 바꿔야 할 부분
- `[보고 / 공유 / 게시 / 제안 / 전달]`
- `[상사 / 고객 / 사용자 / 팀원 / 일반 독자]`

### 후속 질문
- 위에서 가장 중요한 1가지만 먼저 보완한 버전으로 다시 써줘.
- 빠진 요소를 반영한 최종본도 하나 만들어줘.

### 수정 요청
- 사소한 표현보다 실제로 중요한 누락 요소 중심으로 정리해줘.
- 보완 방향을 더 실전적으로 설명해줘.

### 검수 요청
- 지금 상태에서 정말 빠진 핵심 요소가 없는지 한 번 더 검수해줘.
- 보완 우선순위가 적절한지도 점검해줘.

### 사용 팁
결과물이 약할 때는 전체를 새로 쓰기보다, 빠진 요소 1~2개를 보완하는 쪽이 훨씬 빠를 때가 많습니다.

## 7. 후속 질문 흐름을 설계하고 싶을 때

### 한 줄 설명
첫 질문 이후 어떤 순서로 더 물어보면 결과 품질이 좋아지는지 설계하는 후속 질문 흐름형 작업지시서입니다.

### 이런 상황에서 특히 잘 맞습니다
- 첫 질문은 했는데 그 다음이 늘 막힐 때
- 한 번의 답변으로 끝내지 않고 더 깊게 이어가고 싶을 때
- AI 결과 품질이 2~3차 질문에서 갈리는 걸 느낄 때

### 이 작업지시서로 기대할 수 있는 결과
- 후속 질문 순서
- 각 질문의 목적
- 어떤 경우에 어떤 질문을 이어야 하는지 기준

### 언제 쓰는지
- 첫 답변을 받은 직후
- 전체 작업 흐름을 더 체계화하고 싶을 때

### 바로 복사할 본문
```text
지금 저는 [작업 주제]에 대해 첫 질문을 한 상태이거나, 곧 첫 질문을 하려고 합니다.
문제는 첫 질문 이후 어떤 순서로 더 물어봐야 결과 품질이 좋아지는지 잘 모르겠다는 점입니다.

이번 작업의 목적은 [무엇을 완성하고 싶은지]이고,
가장 자주 막히는 부분은 [현재 막히는 지점]입니다.

아래 기준으로 후속 질문 흐름을 설계해 주세요.
1. 첫 답변 직후 이어야 할 질문
2. 답변이 너무 일반적일 때 이어야 할 질문
3. 방향은 맞지만 약할 때 이어야 할 질문
4. 마지막 품질 점검 전에 물어볼 질문

답변은 아래 순서로 주세요.
1. 후속 질문 4단계 흐름
2. 각 질문이 필요한 이유
3. 바로 복사해서 쓸 실제 후속 질문 문장
```

### 바꿔야 할 부분
- `[작업 주제]`
- `[무엇을 완성하고 싶은지]`
- `[현재 막히는 지점]`

### 후속 질문
- 이 흐름을 더 짧은 실전형 버전으로 줄여줘.
- 초보자 기준으로 더 쉽게 따라갈 수 있게 다시 정리해줘.

### 수정 요청
- 설명보다는 실제 복사할 질문 문장 중심으로 바꿔줘.
- 단계 간 차이가 더 선명하게 보이게 다듬어줘.

### 검수 요청
- 이 흐름만 따라가도 결과 품질을 끌어올릴 수 있는지 검수해줘.
- 빠진 핵심 후속 질문이 있다면 보완해줘.

### 사용 팁
AI 품질 차이는 첫 질문보다 `그 다음에 무엇을 묻느냐`에서 더 크게 갈리는 경우가 많습니다.
