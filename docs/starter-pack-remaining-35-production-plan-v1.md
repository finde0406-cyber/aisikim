# AI시킴 스타터팩 나머지 35개 제작 계획 v1

## 1. 문서 목적
이 문서는 스타터팩 50개 중 이미 기준선이 잡힌 코어 15를 제외한 `나머지 35개`를 실제 판매 기준에 맞춰 완성하기 위한 제작 계획 문서입니다.  
목표는 단순히 50개 숫자를 채우는 것이 아니라, 코어 15와 같은 품질 수준으로 확장하는 것입니다.

---

## 2. 현재 상태

### 이미 기준선이 잡힌 것
- 코어 15 주제 선정 완료
- 코어 15 프리미엄 초안 완료
- 스타터팩 PDF/Notion 최종 문안 완료
- 사용 가이드, 패키징, 전달 메일 기준 완료

### 아직 필요한 것
- 나머지 35개 본문 실제 작성
- 카테고리별 중복 제거
- 코어 15 대비 얕아 보이지 않도록 품질 맞춤
- 최종 PDF/Notion 안으로 배치 가능한 수준 정리

---

## 3. 제작 원칙
- 코어 15보다 약한 품질의 문장은 넣지 않는다
- 비슷한 제목이라도 실제 역할이 다르지 않으면 제외한다
- `목적`, `언제 쓰는지`, `본문`, `후속 질문`, `수정 요청`, `검수 요청`, `사용 팁`을 기본 포함한다
- 각 카테고리 안에서 `초안 → 구체화 → 수정 → 검수` 흐름이 살아 있어야 한다

---

## 4. 카테고리별 잔여 제작 수

### 블로그/콘텐츠
- 총 10개 중 코어 3개 완료
- 잔여 7개 작성 필요

잔여 항목:
1. 도입부를 더 강하게 쓰고 싶을 때
2. 소제목 구조를 더 읽기 좋게 정리하고 싶을 때
3. 정보형 글을 더 구체적으로 확장하고 싶을 때
4. 판매형 콘텐츠 문구를 자연스럽게 녹이고 싶을 때
5. 같은 내용을 짧은 SNS용 문구로 바꾸고 싶을 때
6. 블로그 글의 마무리와 CTA를 더 좋게 쓰고 싶을 때
7. 완성된 글을 전체 검수하고 수정하고 싶을 때

### 업무/보고서
- 총 10개 중 코어 3개 완료
- 잔여 7개 작성 필요

잔여 항목:
1. 보고서 목차를 더 설득력 있게 만들고 싶을 때
2. 회의록을 실무 문서로 정리하고 싶을 때
3. 기획서 초안을 항목별로 채우고 싶을 때
4. 업무 이메일을 더 명확하게 쓰고 싶을 때
5. 실행 계획을 체크리스트로 정리하고 싶을 때
6. 문제 보고 문서를 더 차분하고 정확하게 쓰고 싶을 때
7. 완성된 보고서나 기획서를 최종 검수하고 싶을 때

### 앱/웹사이트 개발
- 총 10개 중 코어 3개 완료
- 잔여 7개 작성 필요

잔여 항목:
1. 사용자 흐름을 화면 단위로 정리하고 싶을 때
2. 버그 상황을 더 정확하게 설명하고 싶을 때
3. UI 수정 요청을 더 구체적으로 하고 싶을 때
4. API 연동 작업을 설명하고 싶을 때
5. MVP 범위와 추후 확장 범위를 나누고 싶을 때
6. 코드를 직접 짜기 전 구조 제안을 받고 싶을 때
7. 개발 결과물을 최종 검수하고 싶을 때

### 결과물 검수/수정
- 총 10개 중 코어 3개 완료
- 잔여 7개 작성 필요

잔여 항목:
1. 길기만 한 결과물을 더 짧고 명확하게 만들고 싶을 때
2. 독자나 대상에 맞게 톤을 바꾸고 싶을 때
3. 빠진 핵심 요소가 있는지 점검하고 싶을 때
4. 추상적인 표현을 실제 예시 중심으로 바꾸고 싶을 때
5. 읽기 쉬운 구조로 다시 나누고 싶을 때
6. 더 설득력 있게 다시 쓰고 싶을 때
7. 여러 수정 버전 중 더 나은 방향을 판단하고 싶을 때

### 공통 AI 활용/작업설계
- 총 10개 중 코어 3개 완료
- 잔여 7개 작성 필요

잔여 항목:
1. 내 상황을 AI에게 설명하는 문장을 만들고 싶을 때
2. 원하는 결과물 형식을 먼저 고정하고 싶을 때
3. 후속 질문 흐름을 설계하고 싶을 때
4. 수정 요청을 어떻게 이어갈지 설계하고 싶을 때
5. 검수 질문을 어떻게 던질지 정리하고 싶을 때
6. 같은 작업을 다른 AI 도구에 맞게 바꾸고 싶을 때
7. AI 답변이 뻔할 때 더 깊은 답을 끌어내고 싶을 때

## 5. 실제 제작 순서 추천

### 1차
- 각 카테고리에서 검수형 1개씩 먼저 완성
- 이유: 전체 패키지의 마무리 품질을 먼저 맞춰야 함

### 2차
- 각 카테고리에서 수정/구체화형 항목 작성
- 이유: 초안 이후 체감 품질 차이를 만드는 핵심 구간이기 때문

### 3차
- 남은 세부 상황형 항목 작성
- 이유: 깊이와 폭을 동시에 완성하기 위해

---

## 6. 완성 판정 기준
나머지 35개도 아래 기준을 모두 만족해야 합니다.

1. 코어 15와 톤 차이가 크지 않을 것
2. 무료 샘플팩보다 분명히 깊을 것
3. 유료라는 기대치에 맞는 구조일 것
4. 사용자가 실제로 반복 활용 가능한 형태일 것
5. PDF/Notion 안에서 읽기 부담이 과도하지 않을 것

---

## 7. 솔직한 판단
현재 AI시킴이 `완벽한 유료 상품`이 되려면, 결국 나머지 35개도 실제 본문 수준으로 다 작성되어야 합니다.  
코어 15만 강하다고 해서 50개 상품 전체가 완성된 것은 아닙니다.

따라서 다음 실무 단계는 명확합니다.
- 샘플팩 실물 제작
- 나머지 35개 본문 제작
- 스타터팩 최종 PDF/Notion 실물 제작

이 3개가 끝나야 비로소 “이보다 잘 만들 수 없다”에 가까운 상태를 말할 수 있습니다.
