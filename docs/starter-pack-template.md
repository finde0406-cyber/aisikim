# AI시킴 스타터팩 작업지시서 템플릿

## 1. 문서 목적
이 문서는 유료 `AI 작업지시서 스타터팩` 50개를 실제로 제작할 때 모든 작업지시서가 일정한 품질과 구조를 유지하도록 돕는 제작 템플릿입니다.

## 2. 스타터팩의 역할
- AI시킴의 첫 유료 구매 상품
- 여러 카테고리를 넓게 경험하는 입문용 유료 상품
- 사용자가 AI시킴 방식이 자신에게 맞는지 시험 구매하게 하는 상품
- 이후 카테고리별 딥팩으로 이어지는 관문 상품

## 3. 스타터팩 구성
1. 블로그/콘텐츠 작업지시서 10개
2. 업무/보고서 작업지시서 10개
3. 앱/웹사이트 개발 작업지시서 10개
4. 결과물 검수/수정 작업지시서 10개
5. 공통 AI 활용/작업설계 작업지시서 10개

총 50개 작업지시서

## 4. 각 작업지시서 공통 템플릿
각 작업지시서는 아래 8개 요소를 반드시 포함합니다.

1. 제목
2. 목적
3. 언제 쓰는지
4. 바로 복사할 본문
5. 바꿔야 할 부분
6. 후속 질문 예시
7. 수정 요청 예시
8. 검수 요청 예시

## 5. 세부 작성 템플릿
### 5.1 제목
- 사용자가 상황을 바로 이해할 수 있게 쓴다.
- 예:
  - 블로그 글의 첫 구조를 잡고 싶을 때
  - 업무 보고서를 더 설득력 있게 정리하고 싶을 때
  - 기능 요구사항을 개발자가 이해하게 정리하고 싶을 때

### 5.2 목적
- 이 작업지시서가 어떤 결과를 만들기 위한 것인지 1~2문장으로 설명한다.
- 예:
  - 막막한 시작점을 줄이고, 바로 사용할 수 있는 초안을 만들기 위한 작업지시서
  - AI 답변을 더 실무적으로 끌어올리기 위한 후속 요청 작업지시서

### 5.3 언제 쓰는지
- 사용 시점을 명확히 적는다.
- 예:
  - 첫 질문 단계에서 사용
  - 첫 답변 이후 구체화를 위해 사용
  - 결과물이 마음에 들지 않을 때 방향 수정용으로 사용
  - 최종 검수 단계에서 사용

### 5.4 바로 복사할 본문
- 실제로 복사해서 바로 AI에 넣을 수 있는 본문을 제공한다.
- 예시 형식:
```text
지금 저는 [상황]을 진행 중입니다.
이번에 필요한 결과물은 [결과물]입니다.

먼저 제가 놓치고 있는 핵심 요소가 있으면 질문해 주세요.
그 다음 [원하는 형식]으로 결과를 정리해 주세요.

답변은 [스타일]로 작성해 주세요.
가능하면 바로 실행하거나 제출할 수 있는 수준으로 만들어 주세요.
```

### 5.5 바꿔야 할 부분
- 사용자가 어떤 변수만 바꾸면 되는지 명확히 적는다.
- 예:
  - `[상황]`: 내 현재 작업
  - `[결과물]`: 글 초안 / 보고서 / 기능 정의 등
  - `[원하는 형식]`: 목차형 / 체크리스트형 / 문단형 등
  - `[스타일]`: 친절하게 / 전문가처럼 / 짧고 명확하게

### 5.6 후속 질문 예시
- 첫 결과를 더 좋게 만들기 위한 추가 질문
- 예:
  - 위 초안을 대상 독자 기준으로 다시 다듬어줘.
  - 지금 구조를 유지한 채 더 구체적인 예시를 넣어줘.
  - 항목별 우선순위를 붙여서 다시 정리해줘.

### 5.7 수정 요청 예시
- 결과물이 별로일 때 방향을 조정하는 문장
- 예:
  - 너무 일반적인 표현을 줄이고 실제 현장에서 바로 쓸 수 있게 바꿔줘.
  - 형식은 유지하되 더 짧고 강하게 다시 써줘.
  - 내 상황에 맞는 예시를 더 넣어서 현실감 있게 바꿔줘.

### 5.8 검수 요청 예시
- 최종 완성도를 높이는 질문
- 예:
  - 이 결과에서 빠진 핵심 요소가 있다면 체크해줘.
  - 초보자가 봐도 바로 이해되는지 검수해줘.
  - 너무 추상적인 부분이 있다면 더 구체적으로 바꿔줘.

## 6. 카테고리별 작성 방향
### 6.1 블로그/콘텐츠
- 제목, 구조, 도입부, 본문 흐름, 마무리까지 연결
- 정보형 / 판매형 / 브랜딩형 차이를 구분

### 6.2 업무/보고서
- 보고서, 이메일, 기획서, 회의록 등 실무 문서 중심
- 목적, 독자, 보고 형식을 더 명확히 반영

### 6.3 앱/웹사이트 개발
- 기능 정의, 개발 요청, 버그 수정, 화면 설명, API 연동 지시 등
- 코드 자체보다 "개발자가 이해할 수 있는 지시"까지 포함

### 6.4 결과물 검수/수정
- 방향 수정, 톤 조정, 누락 점검, 구체화, 압축, 확장
- 다른 카테고리 작업지시서와 함께 쓰기 쉽게 설계

### 6.5 공통 AI 활용/작업설계
- 어떤 순서로 AI를 써야 하는지
- 첫 질문을 어떻게 시작하는지
- 후속 질문, 수정 요청, 검수 질문을 어떻게 이어가는지

## 7. 유료팩 설명서 구성
스타터팩 본문 외에 별도의 사용 가이드 또는 앞부분 설명서를 포함하는 것을 권장합니다.

### 7.1 설명서에 포함할 항목
1. 이 상품이 필요한 사람
2. 어떻게 활용하면 좋은지
3. 어떤 순서로 쓰면 좋은지
4. 카테고리별 특징
5. 복사 후 꼭 바꿔야 할 부분
6. AI 답변이 별로일 때 재시도 방법

### 7.2 설명서 목적
- 사용자가 "자료를 받았지만 어떻게 써야 할지 모르겠다" 상태에 빠지지 않게 한다.
- 단순한 문장 묶음이 아니라 실행 가능한 상품처럼 느끼게 만든다.

## 8. 스타터팩 품질 체크리스트
- 각 작업지시서에 8개 요소가 모두 들어 있는가
- 카테고리별 목적이 분명히 다르게 느껴지는가
- 초안, 후속, 수정, 검수 흐름이 보이는가
- 무료 결과/샘플팩보다 체감 차이가 분명한가
- "돈값 한다"는 느낌이 나는가
- 사용법 설명서가 충분한가

## 9. 최종 기준
스타터팩은 "작업지시서 50개를 많이 준 상품"이 아니라, 사용자가 실제 결과물을 완성하도록 돕는 실행용 디지털 상품이어야 합니다.  
유료라는 사실만으로 기대치가 올라가므로, 품질과 설명력 모두 무료보다 분명히 높아야 합니다.
