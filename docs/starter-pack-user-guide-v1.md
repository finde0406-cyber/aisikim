# AI시킴 스타터팩 사용 가이드 초안 v1

## 1. 문서 목적
이 문서는 유료 `AI 작업지시서 스타터팩`을 구매한 사용자가 자료를 받자마자 바로 활용할 수 있도록 돕는 사용 가이드 초안입니다.  
스타터팩이 단순한 작업지시서 모음으로 보이지 않고, 실제 결과물을 완성하는 실행 도구처럼 느껴지게 만드는 것이 목적입니다.

## 2. 이 상품이 필요한 사람
- AI에게 무엇을 어떻게 시켜야 할지 모르겠는 사람
- 첫 질문만 던지고 결과가 별로라서 자꾸 막히는 사람
- 초안 생성뿐 아니라 후속 질문, 수정 요청, 검수 질문까지 한 번에 갖고 싶은 사람
- 블로그, 업무, 개발 등 실전 작업에서 AI를 더 제대로 써보고 싶은 사람

## 3. 이 상품을 어떻게 활용하면 좋은가
스타터팩은 한 번에 전부 읽는 자료가 아닙니다.  
지금 막힌 작업과 가장 가까운 카테고리 1개를 먼저 골라, 그 안의 작업지시서를 순서대로 꺼내 쓰는 방식이 가장 좋습니다.

예를 들어:
- 블로그 글을 쓰고 있다면 `블로그/콘텐츠`
- 업무 보고서를 정리해야 한다면 `업무/보고서`
- 기능 요구사항이나 개발 지시를 정리해야 한다면 `앱/웹사이트 개발`

## 4. 가장 추천하는 사용 순서
### 4.1 첫 단계
- 먼저 `공통 AI 활용/작업설계` 카테고리에서
  - 첫 질문
  - 후속 질문 흐름
  - 수정 요청 구조
  를 한 번 훑어봅니다.

### 4.2 두 번째 단계
- 지금 필요한 카테고리 1개를 선택합니다.
- 그 안에서 `초안 생성형` 작업지시서부터 사용합니다.

### 4.3 세 번째 단계
- 첫 답변이 나온 뒤에는 `후속 질문 예시`를 이어서 사용합니다.

### 4.4 네 번째 단계
- 결과가 마음에 들지 않으면 `수정 요청 예시`를 사용합니다.

### 4.5 다섯 번째 단계
- 마지막에는 `검수 요청 예시`로 결과물을 한 번 더 점검합니다.

## 5. 작업지시서를 볼 때 체크할 것
각 작업지시서는 아래 순서로 구성되어 있습니다.

1. 제목
2. 목적
3. 언제 쓰는지
4. 바로 복사할 본문
5. 바꿔야 할 부분
6. 후속 질문 예시
7. 수정 요청 예시
8. 검수 요청 예시

즉, 하나의 작업지시서만 봐도
`처음 요청 -> 발전 -> 수정 -> 최종 점검`
까지 이어질 수 있게 설계되어 있습니다.

## 6. 복사 전에 꼭 바꿔야 할 것
대부분의 작업지시서는 아래 요소만 바꾸면 바로 쓸 수 있습니다.

- 현재 작업 상황
- 원하는 결과물
- 대상 독자 또는 읽는 사람
- 원하는 스타일
- 분량 또는 형식

이 부분을 바꾸지 않고 그대로 넣으면 결과가 일반적으로 나올 가능성이 높습니다.

## 7. 결과가 별로일 때 어떻게 해야 하나
처음 답변이 마음에 안 드는 것은 자연스러운 일입니다.  
중요한 것은 질문을 한 번 던지고 끝내지 않는 것입니다.

추천 순서:
1. 후속 질문으로 구체화
2. 수정 요청으로 방향 조정
3. 검수 요청으로 빠진 부분 점검

즉, 첫 답변은 초안일 뿐이고, 완성은 그 다음 흐름에서 만들어집니다.

## 8. 이런 식으로 쓰면 좋다
### 예시 흐름
1. 블로그 글의 첫 구조를 잡고 싶을 때
2. 글 제목 후보를 여러 방향으로 뽑고 싶을 때
3. 글 초안을 대상 독자에 맞게 다시 다듬고 싶을 때
4. 완성된 글을 전체 검수하고 수정하고 싶을 때

이런 식으로 한 카테고리 안에서도 여러 작업지시서를 이어서 쓰면 결과 품질이 크게 올라갑니다.

## 9. 어떤 기대를 가지면 좋은가
이 상품은 AI가 완벽한 정답을 한 번에 주게 만드는 마법의 문장 모음이 아닙니다.  
대신 사용자가 AI를 더 잘 시키고, 결과물을 더 빨리 완성하게 만드는 실전용 작업지시서 세트입니다.

즉, 한 번 던지고 끝내는 자료가 아니라 반복해서 꺼내 쓰는 자료라고 생각하는 것이 맞습니다.

## 10. 다음 단계 상품과의 연결
스타터팩은 입문용 유료 상품입니다.  
이후 자주 쓰는 분야가 생기면 해당 분야만 더 깊게 다룬 `딥팩`으로 확장될 수 있습니다.

예:
- 블로그/콘텐츠 딥팩
- 업무/보고서 딥팩
- 앱/웹사이트 개발 딥팩
- 결과물 검수/수정 딥팩

## 11. 최종 기준
이 사용 가이드는 사용자가 "자료를 받았는데 어떻게 써야 할지 모르겠다"는 상태에 빠지지 않게 만들기 위한 문서입니다.  
스타터팩은 본문 자체의 품질도 중요하지만, 어떻게 써야 하는지까지 함께 안내할 때 비로소 완성도 있는 유료 상품이 됩니다.
